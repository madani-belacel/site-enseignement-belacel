Chapitre 02 — OSI Model and TCP/IP

Attribute Value

References [KR] § 1.5 ; [FO] Ch. 2 ; [TA] § 1.4

Chapter Objectives

After completing this chapter, the student will be able to:

  1. Maîtriser la correspondance OSI ↔ TCP/IP et le rôle de chaque couche en production.
  2. Analyser une communication réseau couche par couche (encapsulation/désencapsulation).
  3. Appliquer le modèle OSI comme outil de diagnostic (top-down et bottom-up).
  4. Identifier les goulots d'étranglement et overhead par couche.

2. Performance et overhead par couche

2.1 Overhead typique (Ethernet IPv4 TCP)

En-tête Taille (octets) % pour MTU 1500
Ethernet 14 (+4 FCS) ~1,2 %
IP 20 ~1,3 %
TCP 20 ~1,3 %
Total en-têtes ~54 ~3,6 %
Payload utile 1446 ~96,4 %

Avec 802.1Q : +4 octets. Avec IPv6 : en-tête IP 40 octets (Ch. 06).

2.2 MTU et fragmentation

Concept Value Ethernet Impact
MTU standard 1500 octets Taille max payload IP
MSS TCP MTU − 40 (IP+TCP) ~1460 octets
Fragmentation IP Si paquet > MTU lien Pénalisant — éviter (Path MTU Discovery)

2.3 Latence par couche (ordre de grandeur)

Couche Traitement typique
L1 Négligeable (ns–μs)
L2 1–10 μs (switch ASIC)
L3 10–100 μs (routage logiciel) ; <10 μs (ASIC)
L4 10–50 μs (stack OS)
L7 ms (application, TLS)

3. Diagnostic réseau par couche

3.1 Approche bottom-up (Physique → Application)

Étape Couche Vérification Outils
1 L1 Link up, câble, duplex LED, ethtool
2 L2 MAC, VLAN, ARP arp -a, show vlan, Wireshark
3 L3 IP, masque, route ipconfig, show ip route, ping GW
4 L4 Port ouvert, TCP telnet, Test-NetConnection, Wireshark
5 L7 DNS, HTTP, certificat nslookup, curl, navigateur F12

3.2 Approche top-down (Application → Physique)

Recommandée quand le symptôme est applicatif (« le site ne s'ouvre pas ») :

  1. URL correcte ? Code HTTP ? (L7)
  2. DNS résout ? (L7/L4)
  3. TCP connect ? (L4)
  4. Ping IP serveur ? (L3)
  5. ARP / VLAN ? (L2)
  6. Link ? (L1)

3.3 Matrice symptôme → couche

Symptôme Couche probable Action
LED port éteinte L1 Vérifier câble, port, SFP
« Destination host unreachable » L3 Route, masque, GW
« Request timed out » (GW OK) L3/L4 Firewall, ACL, routage
« Connection refused » L4 Service arrêté, mauvais port
« Name or service not known » L7 DNS
Certificat SSL invalide L6/L7 TLS, date système

4. Scénario intégré : accès HTTPS complet

Context : PC SI (192.168.50.10) → https://www.univ-mosta.dz

Étape Couche Événement
1 L7 Résolution DNS www.univ-mosta.dz
2 L4 TCP SYN → port 443
3 L6 TLS ClientHello / ServerHello
4 L7 HTTP GET (dans tunnel TLS)
5 L4–L1 Encapsulation descendante
6 L3 Routage via GW 192.168.50.1
7 L2 Trame vers MAC passerelle (ARP)
8 Retour HTML chiffré, désencapsulation

Exercice 2 — Diagnostic

ping 8.8.8.8 OK, ping google.com échec. Couche en cause ? Actions ?

Solution **L7 — DNS**. Vérifier serveur DNS configuré (`ipconfig /all`), `nslookup google.com`, tester autre DNS (8.8.8.8).
