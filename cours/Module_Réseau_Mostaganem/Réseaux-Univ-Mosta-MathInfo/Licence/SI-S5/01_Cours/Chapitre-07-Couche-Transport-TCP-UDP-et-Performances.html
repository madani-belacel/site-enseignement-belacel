Objectifs du chapitre

À l'issue de ce chapitre, l'étudiant sera capable de :

  1. Analyser les mécanismes avancés de TCP (fenêtre, RTT, retransmission).
  2. Expliquer le contrôle de congestion (slow start, AIMD).
  3. Mesurer les performances transport avec Wireshark et netstat.
  4. Choisir TCP ou UDP pour des applications SI (API, streaming, IoT).

2. Contrôle de flux (Flow Control)

2.1 Fenêtre glissante (Sliding Window)

  • Le récepteur annonce rwnd (receive window) dans chaque segment TCP.
  • L'émetteur ne peut pas avoir plus de rwnd octets non acquittés en transit.
Émetteur:  [==== envoyé et ACK ====][== en vol ==][  en attente  ]
                                              ← rwnd →

2.2 Zero Window

  • Si récepteur saturé → rwnd = 0 → émetteur pause.
  • Persist timer : sondes périodiques pour réouverture.

3. RTT, RTO et retransmission

3.1 Estimation RTT (Jacobson/Karels)

$$\text{SRTT} = (1-\alpha) \times \text{SRTT} + \alpha \times \text{RTT}_{\text{échantillon}}$$

$$\text{RTTVAR} = (1-\beta) \times \text{RTTVAR} + \beta \times |\text{SRTT} - \text{RTT}_{\text{échantillon}}|$$

$$\text{RTO} = \text{SRTT} + 4 \times \text{RTTVAR}$$

3.2 Retransmission

  • Si ACK non reçu avant RTO → retransmission du segment.
  • Wireshark marque [TCP Retransmission] et [TCP Dup ACK].

3.3 Fast Retransmit / Fast Recovery

  • 3 ACK dupliqués → perte probable → retransmission sans attendre RTO.
  • Améliore performance sur liens à latence variable.

4. Contrôle de congestion

Objectif : éviter la saturation du réseau (contrairement du flow control = récepteur).

Phase Algorithme Comportement
Slow Start cwnd double chaque RTT Croissance exponentielle
Congestion Avoidance cwnd += 1 MSS par RTT Croissance linéaire
Détection perte Timeout ou 3 dup ACK cwnd réduit (AIMD)

AIMD : Additive Increase, Multiplicative Decrease

cwnd
  │     ╱╲    slow start
  │    ╱  ╲___ congestion avoidance
  │   ╱       ╲ (perte)
  └────────────────── temps
Variable Signification
cwnd Congestion window (contrôle émetteur)
rwnd Receive window (contrôle récepteur)
Effective window min(cwnd, rwnd)

5. Performance TCP

5.1 Débit théorique maximum

$$\text{Débit max} \approx \frac{\text{MSS}}{\text{RTT}} \times \frac{1}{\sqrt{\text{perte}}}$$

(Rule of thumb — modèle simplifié)

5.2 Facteurs limitants

Facteur Impact
RTT élevé Satellite, intercontinental — débit TCP limité
Perte de paquets cwnd réduit drastiquement
Bufferbloat Latence artificielle dans buffers surdimensionnés
Taille fenêtre Windows scaling (option TCP) pour liens haut débit

5.3 TCP vs UDP — choix SI

Application SI Protocole Justification
API REST / Web TCP Fiabilité, HTTP/HTTPS
Streaming vidéo live UDP (+ QUIC HTTP/3) Latence, perte tolérable
Monitoring SNMP UDP Requêtes légères
DNS UDP (TCP si gros) Rapidité
Backup fichiers TCP Intégrité
Jeu multijoueur UDP Temps réel

7. Exercices

Exercice 1 : RTT = 100 ms, MSS = 1460 octets, cwnd = 4 MSS en slow start. Débit approximatif ?

Solution 4 × 1460 = 5840 octets par RTT → 5840 / 0,1 ≈ **58 400 o/s ≈ 467 kbps** (phase initiale)
