TP 05 — Wireshark Analysis

Attribute Value
Level Bachelor SI — S5
Estimated duration 3 h
Outil Wireshark
Chapters associés Ch. 07–08

Objectives

  • Capturer trafic TCP (3-way handshake, fenêtre)
  • Analyser requêtes DNS et HTTP/HTTPS
  • Appliquer filtres display et suivi de flux

Partie 1 — Préparation

Scénario Action génératrice
TCP curl -v http://example.com ou navigateur
DNS nslookup www.univ-mosta.dz
HTTP GET page non-HTTPS (lab)

Interface capture : Wi-Fi ou Ethernet active.

Partie 2 — Consignes

Étape 1 — Capture TCP (60 min)

  1. Démarrer capture.
  2. Ouvrir site HTTPS.
  3. Stop ; filtre tcp.port==443.
  4. Follow → TCP Stream ; identifier SYN, SYN-ACK, ACK.
  5. Noter RTT (Statistics → TCP Stream Graphs).

Étape 2 — DNS (45 min)

  1. vider cache DNS (ipconfig /flushdns).
  2. Capture + nslookup domaine.
  3. Identifier requête/réponse ; type A ou AAAA.
  4. Noter TTL.

Étape 3 — HTTP (45 min)

  1. Site HTTP lab (ou http://example.com).
  2. Filtre http ; méthode GET, code 200.
  3. Headers : Host, User-Agent.

Étape 4 — Rapport (30 min)

Tableau : n° paquet, protocole, info, couche OSI.

Partie 3 — Vérifications

Élément Présent dans capture
3-way handshake Oui
DNS query/response Oui
HTTP GET Oui
Filtre appliqué tcp/dns/http

Partie 4 — Questions de bilan

  1. Pourquoi HTTPS masque-t-il le contenu HTTP dans Wireshark ?
  2. Différence capture filter vs display filter ?
  3. Comment détecter retransmission TCP ?

Annexe — Corrigé

Filtres : dns.qry.name contains "usto", tcp.analysis.retransmission, tls.handshake.type==1.

Retransmission : [Expert Info], dup ACK, RTO.

Livrables

  • Fichier .pcapng + rapport 2 pages (captures annotées)
