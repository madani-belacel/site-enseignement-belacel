TP 02 — Subnetting et VLSM

Attribut Valeur
Niveau Licence SI — S5
Durée estimée 3 h
Outil Packet Tracer
Chapitres associés Ch. 05

Objectifs

  • Appliquer VLSM sur topologie multi-sites
  • Configurer interfaces routeur/switch selon plan d'adressage
  • Vérifier connectivité et tables de routage

Partie 1 — Topologie

Bloc 172.16.100.0/24 — besoins :

Site Hôtes Réseau assigné
Siège 50 172.16.100.0/26
Agence 25 172.16.100.64/27
Invités 10 172.16.100.96/28
Lien R1↔R2 2 172.16.100.112/30

Partie 2 — Consignes

Étape 1 — Plan VLSM (30 min)

  1. Vérifier le tableau ci-dessus (calcul manuscrit).
  2. Assigner IP aux PC : Siège .10, Agence .10, Invités .10.

Étape 2 — Configuration (90 min)

  1. Topologie : R1 (Siège + lien), R2 (Agence + Invités + lien).
  2. Configurer toutes interfaces + GW PC.
  3. Routes statiques ou connect si directement connectés.

Étape 3 — NAT/PAT (option 45 min)

Sur R1, PAT overload vers interface WAN simulée :

access-list 1 permit 172.16.100.0 0.0.0.255
ip nat inside source list 1 interface G0/2 overload

Étape 4 — Vérifications (15 min)

ping inter-sites
show ip route
show ip nat translations

Partie 4 — Questions de bilan

  1. Pourquoi VLSM réduit le gaspillage vs 4× /26 ?
  2. Quelle route résume les 4 sous-réseaux ?
  3. Impact NAT sur adresse source vue par Internet simulé ?

Annexe — Corrigé

Routes connect sur sous-réseaux locaux ; statiques pour distants. NAT : inside sur LAN, outside sur G0/2.
