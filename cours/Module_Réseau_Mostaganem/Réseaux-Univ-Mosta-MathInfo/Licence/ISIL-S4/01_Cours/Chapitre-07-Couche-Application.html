Objectifs du chapitre

À l'issue de ce chapitre, l'étudiant sera capable de :

  1. Décrire le modèle client-serveur et le modèle P2P.
  2. Expliquer le fonctionnement du DNS (résolution de noms).
  3. Décrire le protocole HTTP/HTTPS et le cycle requête/réponse.
  4. Identifier les protocoles FTP, SMTP, DHCP (aperçu).
  5. Comprendre le rôle de TLS/SSL dans HTTPS.

1. Rôle de la couche Application

La couche Application (Layer 7) est la couche la plus proche de l'utilisateur. Elle fournit des services réseau aux applications :

Fonction Description
Interface utilisateur Accès aux services réseau (navigateur, client email)
Protocoles applicatifs HTTP, DNS, FTP, SMTP, SSH…
Format des messages Structure des requêtes et réponses

C'est la couche visible pour l'utilisateur final.

2. Modèles architecturaux

   1 client                      1 serveur

Caractéristique Détail
Serveur Toujours actif, IP fixe, haute capacité

3. DNS — Domain Name System

3.1 Problème résolu

Les humains préfèrent les noms (www.univ-mosta.dz), les machines utilisent les adresses IP (41.107.x.x). Le DNS traduit un nom de domaine en adresse IP.

3.2 Hiérarchie DNS

                    ┌─────────────┐
                    │ Root Servers│  (. )
                    └──────┬──────┘
              ┌────────────┼────────────┐
         ┌────┴────┐  ┌────┴────┐  ┌──┴──────┐
         │  .dz    │  │  .com   │  │  .org   │  TLD
         └────┬────┘  └────┬────┘  └─────────┘
         ┌────┴────┐  ┌────┴────┐
         │ univ-mosta.dz │  │google.com│             Domaine
         └────┬────┘  └─────────┘
    ┌─────────┼─────────┐
 www.usto  mail.usto  ftp.usto                  Sous-domaines
Niveau Exemple Rôle
Root (.) 13 serveurs racine Point de départ
TLD (Top-Level Domain) .dz, .com, .org, .edu Par pays/organisation
Domaine univ-mosta.dz, google.com Organisation
Sous-domaine www.univ-mosta.dz, mail.google.com Services

3.3 Types d'enregistrements DNS

Type Nom Contenu Usage
A Address IPv4 www.univ-mosta.dz → 41.107.x.x
AAAA Address IPv6 www.univ-mosta.dz → 2001:db8::1
CNAME Canonical Name Alias → autre nom ftp.univ-mosta.dz → www.univ-mosta.dz
MX Mail Exchange Serveur mail + priorité Email entrant
NS Name Server Serveur DNS autoritaire Délégation
TXT Text Texte libre SPF, vérification

3.4 Processus de résolution (récursive)

Exemple : L'utilisateur tape www.univ-mosta.dz dans son navigateur.

sequenceDiagram
    participant PC as PC Client
    participant LR as Resolver local
    participant RS as Root DNS
    participant TD as TLD .dz
    participant AD as DNS univ-mosta.dz

    PC->>LR: www.univ-mosta.dz ?
    LR->>RS: Où est .dz ?
    RS->>LR: Demandez au TLD .dz
    LR->>TD: Où est univ-mosta.dz ?
    TD->>LR: Demandez au NS univ-mosta.dz
    LR->>AD: Où est www.univ-mosta.dz ?
    AD->>LR: 41.107.x.x
    LR->>PC: 41.107.x.x
Étape Action
1 Le PC consulte son résolveur local (configuré via DHCP ou manuellement : 8.8.8.8, DNS FAI)
2 Le résolveur interroge un serveur racine → renvoie vers le TLD .dz
3 Interroge le TLD .dz → renvoie vers le NS de univ-mosta.dz
4 Interroge le serveur autoritaire univ-mosta.dz → obtient l'enregistrement A
5 Réponse mise en cache (TTL)

3.5 Commandes utiles

nslookup www.univ-mosta.dz       # Windows/Linux — requête DNS
dig www.univ-mosta.dz            # Linux — requête détaillée
ipconfig /displaydns       # Windows — cache DNS local

4. HTTP et HTTPS

4.1 HTTP — HyperText Transfer Protocol

HTTP (RFC 7230) : protocole de transfert de documents hypertexte (pages web).

Propriété Valeur
Port 80 (TCP)
Mode Client-Serveur, requête/réponse
Format ASCII (texte lisible)
État Stateless (sans état — chaque requête est indépendante)

4.2 Format d'une requête HTTP

GET /index.html HTTP/1.1
Host: www.univ-mosta.dz
User-Agent: Mozilla/5.0
Accept: text/html
Connection: keep-alive

(ligne vide = fin de l'en-tête)
Méthode Action Exemple
GET Lire une ressource Charger une page
POST Envoyer des données Formulaire de connexion
PUT Créer/modifier une ressource Upload API
DELETE Supprimer une ressource Supprimer un fichier
HEAD GET sans le corps Vérifier l'existence

4.3 Format d'une réponse HTTP

HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1234
Date: Mon, 06 Jun 2025 10:00:00 GMT

<!DOCTYPE html>
<html>...
Code Signification Description
200 OK Succès
301 Moved Permanently Redirection permanente
302 Found Redirection temporaire
400 Bad Request Requête mal formée
401 Unauthorized Authentification requise
403 Forbidden Accès interdit
404 Not Found Ressource introuvable
500 Internal Server Error Erreur serveur
503 Service Unavailable Serveur surchargé

4.4 HTTPS — HTTP Secure

HTTPS = HTTP + TLS/SSL (chiffrement)

Propriété Valeur
Port 443 (TCP)
Sécurité Chiffrement, authentification du serveur (certificat)
Certificat Émis par une Autorité de Certification (CA) 
Client ──→ [TLS Handshake] ──→ Serveur
         ←── Certificat ────
         ──→ Session chiffrée ──→
         ←── HTTP chiffré ──────

4.5 HTTP/1.1 vs HTTP/2 (aperçu)

Critère HTTP/1.1 HTTP/2
Connexions 1 requête/connexion (ou keep-alive) Multiplexage sur 1 connexion
Format Texte ASCII Binaire
Compression en-têtes Non HPACK
Performance Bonne Meilleure

5. Autres protocoles applicatifs

5.1 FTP — File Transfer Protocol

Propriété Valeur
Ports 21 (contrôle, TCP), 20 (données, TCP)
Mode Client-Serveur
Usage Transfert de fichiers (legacy, remplacé par SFTP/SCP)

5.2 SMTP — Simple Mail Transfer Protocol

Propriété Valeur
Port 25 (TCP), 587 (soumission, TLS)
Usage Envoi d'emails entre serveurs
Complément POP3 (110) / IMAP (143) pour la réception 
Expéditeur ──SMTP──→ Serveur mail ──SMTP──→ Serveur destinataire
                                              │
Destinataire ←─POP3/IMAP──────────────────────┘

5.3 DHCP — Dynamic Host Configuration Protocol

Propriété Valeur
Port 67 (serveur, UDP), 68 (client, UDP)
Usage Attribution automatique d'adresse IP, masque, passerelle, DNS
Processus DORA : Discover → Offer → Request → Acknowledge 
PC (0.0.0.0) ──Discover (broadcast)──→ Serveur DHCP
PC ──Request──→ Serveur DHCP
PC ←──Ack (IP: 192.168.1.50, GW: 192.168.1.1, DNS: 8.8.8.8)── Serveur

5.4 SSH — Secure Shell

Propriété Valeur
Port 22 (TCP)
Usage Accès sécurisé à distance (terminal chiffré)
Remplace Telnet (23) — non chiffré, obsolète

5.5 Tableau récapitulatif

Protocole Port Transport Fonction
DNS 53 UDP/TCP Résolution de noms
HTTP 80 TCP Web
HTTPS 443 TCP Web sécurisé
FTP 20/21 TCP Transfert fichiers
SMTP 25 TCP Envoi email
POP3 110 TCP Réception email
DHCP 67/68 UDP Configuration IP
SSH 22 TCP Terminal sécurisé
Telnet 23 TCP Terminal (obsolète)

7. Exercices et QCM

Exercice 1

Classer par ordre chronologique les messages lors d'un accès HTTP :

  • [ ] TCP SYN
  • [ ] DNS Query
  • [ ] HTTP GET
  • [ ] TCP SYN-ACK
  • [ ] DNS Response
  • [ ] HTTP 200 OK
  • [ ] TCP ACK
Solution 1. DNS Query → 2. DNS Response → 3. TCP SYN → 4. TCP SYN-ACK → 5. TCP ACK → 6. HTTP GET → 7. HTTP 200 OK

QCM
