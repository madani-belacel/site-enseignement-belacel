After completing this chapter, the student will be able to:

1. Pourquoi un modèle en couches ?

1.1 Problématique

Construire un réseau global impliquant des technologies hétérogènes (cuivre, fibre, Wi-Fi, différents fabricants) nécessite une architecture structurée pour :

  • Modulariser les fonctions (chaque couche a un rôle précis)
  • Faciliter l'interopérabilité (standardisation)
  • Permettre l'évolution indépendante de chaque couche
  • Simplifier l'enseignement et le dépannage

1.2 Principe fondamental

Chaque couche utilise les services de la couche inférieure et offre des services à la couche supérieure.

┌─────────────────────────────────────────────┐
│           Couche N+1 (Application)          │
├─────────────────────────────────────────────┤
│           Couche N   (Transport)            │
├─────────────────────────────────────────────┤
│           Couche N-1 (Réseau)               │
├─────────────────────────────────────────────┤
│           Couche N-2 (Liaison)              │
├─────────────────────────────────────────────┤
│           Couche N-3 (Physique)             │
└─────────────────────────────────────────────┘
         ▲                           │
    Services offerts          Services utilisés

2. Le modèle OSI (ISO 7498)

Le modèle OSI (Open Systems Interconnection), standardisé par l'ISO en 1984, définit 7 couches :

Couche Nom Fonction principale PDU Exemples de protocoles
7 Application Interface avec l'utilisateur et les applications Data HTTP, DNS, FTP, SMTP
6 Présentation Format des données, chiffrement, compression Data SSL/TLS, JPEG, ASCII
5 Session Établissement, gestion, fermeture de sessions Data NetBIOS, RPC
4 Transport Communication bout-à-bout fiable ou non Segment (TCP) / Datagramme (UDP) TCP, UDP
3 Réseau Adressage logique, routage inter-réseaux Paquet IP, ICMP, OSPF
2 Liaison de données Accès au média, adressage physique, détection d'erreurs Trame Ethernet, Wi-Fi (802.11), PPP
1 Physique Transmission des bits sur le média Bits Câbles, connecteurs, signaux

2.1 Mnémotechnique

« All People Seem To Need Data Processing » Application — Présentation — Session — Transport — Network — Data Link — Physical

Version francophone :

« Astrologues Persévérants Servent Théoriquement Neuf Dieux Parfaits »

2.2 Détail par couche

Couche 1 — Physique

  • Transmet les bits (0 et 1) sur le support physique.
  • Définit : tensions, fréquences, connecteurs (RJ-45), topologie physique.

Couche 2 — Liaison de données

  • Organise les bits en trames, détecte/corrige les erreurs.
  • Adressage MAC (48 bits, ex : AA:BB:CC:DD:EE:FF).
  • Commutation locale (switch).

Couche 3 — Réseau

  • Adressage logique (IPv4/IPv6), routage entre réseaux.
  • Le routeur est l'équipement clé de cette couche.

Couche 4 — Transport

  • Communication de bout en bout entre processus (applications).
  • Ports (16 bits, 0–65535) pour multiplexer les applications.
  • TCP : fiable, ordonné. UDP : rapide, sans connexion.

Couches 5, 6, 7 — Session, Présentation, Application

  • En pratique, souvent regroupées en « couche Application » dans TCP/IP.
  • Gestion des sessions, format des données, protocoles applicatifs.

3. La pile TCP/IP

La pile TCP/IP (Transmission Control Protocol / Internet Protocol), développée pour ARPANET puis Internet, est le modèle réellement implémenté. Elle comporte 4 couches :

Couche TCP/IP Fonction Protocoles
Application Services réseau aux applications HTTP, DNS, FTP, SMTP, SSH, Telnet
Transport Communication bout-à-bout TCP, UDP
Internet Adressage et routage IP (v4/v6), ICMP, ARP
Accès réseau Transmission sur le média physique Ethernet, Wi-Fi, PPP

4. Correspondance OSI ↔ TCP/IP

Couche OSI Couche TCP/IP Équipement associé
7 — Application
6 — Présentation Application Passerelle, proxy
5 — Session
4 — Transport Transport Firewall L4
3 — Réseau Internet Routeur
2 — Liaison Accès réseau Switch, carte réseau
1 — Physique Accès réseau Hub, câbles, répéteur

4.1 Tableau comparatif OSI vs TCP/IP

Critère Modèle OSI Pile TCP/IP
Origine ISO (1984) DARPA / ARPANET (1970s)
Couches 7 4
Nature Modèle de référence théorique Modèle implémenté (Internet)
Développement Protocoles définis après le modèle Protocoles définis avant le modèle
Usage actuel Pédagogique, diagnostic Production (Internet)
Couches 5-6 OSI Distinctes Fusionnées dans Application

En pratique : On utilise le modèle OSI pour comprendre et diagnostiquer, et la pile TCP/IP pour implémenter.

5. Encapsulation et désencapsulation

5.1 Principe de l'encapsulation

Lorsqu'une application envoie des données, chaque couche ajoute son en-tête (header) — parfois un pied de page (trailer) — avant de transmettre à la couche inférieure. Ce processus s'appelle l'encapsulation.

Application  │  Data (Données)
             ▼
Transport    │ [En-tête TCP/UDP │ Data]                    = Segment
             ▼
Réseau       │ [En-tête IP │ En-tête TCP/UDP │ Data]       = Paquet
             ▼
Liaison      │ [En-tête Eth │ En-tête IP │ ... │ Data │ FCS] = Trame
             ▼
Physique     │  0 1 0 1 1 0 0 1 ...                          = Bits

5.2 PDU par couche

Couche Nom de la PDU Contenu
Application Data (Données) Message applicatif (ex : requête HTTP)
Transport Segment (TCP) ou Datagramme (UDP) En-tête TCP/UDP + Data
Réseau Paquet (Packet) En-tête IP + Segment
Liaison Trame (Frame) En-tête Ethernet + Paquet + FCS
Physique Bits Signal électrique/optique

5.3 Désencapsulation (réception)

À la réception, chaque couche retire son en-tête et transmet le contenu à la couche supérieure :

Bits → Trame → Paquet → Segment → Data → Application
  L1     L2      L3       L4        L7

5.4 Exemple : en-têtes d'une trame Ethernet/IP/TCP

En-tête Taille Champs principaux
Ethernet II 14 octets MAC dest (6), MAC src (6), Type (2)
IP (v4) 20 octets min. IP src, IP dest, TTL, Protocole
TCP 20 octets min. Port src, Port dest, Seq, Ack, Flags
HTTP Variable GET /index.html HTTP/1.1 …

6. Example concret : parcours d'une requête HTTP

Scénario : Un étudiant Université de Mostaganem ouvre un navigateur et accède à http://www.univ-mosta.dz

Étape Couche Action
1 Application Le navigateur forme la requête GET / HTTP/1.1
2 Transport TCP établit une connexion (3-way handshake) vers port 80
3 Réseau IP encapsule avec adresse source (192.168.1.10) et dest (IP du serveur)
4 Liaison Ethernet ajoute les adresses MAC source et destination
5 Physique Les bits sont transmis sur le câble / Wi-Fi
6 Routeur Lit l'en-tête IP (couche 3), route vers le réseau suivant
7 Serveur Désencapsulation couche par couche, traitement HTTP
8 Retour La page HTML remonte les couches en sens inverse

    SW->>PC: Trame livrée

7. Adressage à chaque couche

Couche Type d'adresse Exemple Portée
Liaison (L2) Adresse MAC 4C:EB:42:A1:B2:C3 Segment local (LAN)
Réseau (L3) Adresse IP 192.168.1.10 Inter-réseaux (global avec routage)
Transport (L4) Port 443 (HTTPS) Processus sur un hôte
Application (L7) URL / nom de domaine www.univ-mosta.dz Service utilisateur

Règle clé : Les adresses MAC ne traversent pas les routeurs ; les adresses IP sont conservées de bout en bout.
