TP 01 — Configuration basique Packet Tracer

Attribute Value
Level Bachelor ISIL — S4
Estimated duration 3 h
Outil Cisco Packet Tracer
Prérequis Ch. 01–02

Objectifs

  • Découvrir l'interface Packet Tracer
  • Créer une topologie étoile simple
  • Configurer les adresses IP et tester la connectivité
  • Utiliser le mode Simulation

Partie 1 — Topologie cible

Équipement Interface Adresse IP Masque
PC-Admin NIC 192.168.1.10 255.255.255.0
PC-Etudiant NIC 192.168.1.20 255.255.255.0
PC-Serveur NIC 192.168.1.5 255.255.255.0
Switch0 — — —

Partie 2 — Consignes

Étape 1 — Créer la topologie (30 min)

  1. Ouvrir Packet Tracer.
  2. Placer : 1 Switch (2960), 3 PC (Generic ou PC-PT).
  3. Câbler en Copper Straight-Through (câble droit) : chaque PC → un port du switch.
  4. Vérifier que les liens passent au vert (Link Up).
  5. Nommer les équipements (clic → Config → Display Name).

Capture attendue :

Étape 2 — Configuration IP (30 min)

Pour chaque PC : 1. Cliquer sur le PC → Desktop → IP Configuration. 2. Saisir l'adresse IP et le masque selon le tableau. 3. Laisser Gateway et DNS vides pour l'instant.

PC IP Masque
PC-Admin 192.168.1.10 255.255.255.0
PC-Etudiant 192.168.1.20 255.255.255.0
PC-Serveur 192.168.1.5 255.255.255.0

Étape 3 — Tests de connectivité (30 min)

  1. Ouvrir Command Prompt sur PC-Admin.
  2. Exécuter :
ping 192.168.1.20
ping 192.168.1.5
ping 192.168.1.99
  1. Noter les résultats (succès/échec) et expliquer.

Capture attendue :

Étape 4 — Mode Simulation (45 min)

  1. Passer en mode Simulation (coin inférieur droit).
  2. Cliquer Edit Filters → cocher uniquement ICMP et ARP.
  3. Depuis PC-Admin, lancer ping 192.168.1.20.
  4. Cliquer Capture/Forward (▶) pour observer :
  5. La requête ARP (broadcast)
  6. La réponse ARP (unicast)
  7. Les paquets ICMP Echo Request/Reply
  8. Faire une capture d'écran du panneau OSI Model (montrer les couches).

Étape 5 — Changement d'adresse (15 min)

  1. Changer l'IP de PC-Etudiant en 192.168.2.20 / masque 255.255.255.0.
  2. Re-tester ping 192.168.1.10 depuis PC-Etudiant.
  3. Expliquer le résultat.

Partie 3 — Vérifications

Test Commande Résultat attendu
Connectivité même réseau ping 192.168.1.20 Succès (4/4)
Connectivité serveur ping 192.168.1.5 Succès
Hôte inexistant ping 192.168.1.99 Échec (timeout)
Réseau différent ping après changement IP Échec

Partie 4 — Questions de bilan

  1. Quelle topologie avez-vous réalisée ? Pourquoi est-elle la plus courante ?
  2. Pourquoi une requête ARP est-elle envoyée avant le premier ping ?
  3. Que se passe-t-il quand les PC sont sur des réseaux différents (192.168.1.x vs 192.168.2.x) sans routeur ?
  4. Quelles couches OSI interviennent lors d'un ping ? (utiliser le mode Simulation)
  5. Quelle est la différence entre un câble droit et un câble croisé ?

Annexe — Corrigé

Réponses attendues

  1. Topologie étoile — switch central, fiabilité, performances.
  2. ARP résout l'IP en MAC avant d'envoyer la trame Ethernet.
  3. Pas de communication — pas de routeur pour relayer entre réseaux.
  4. L1 (bits), L2 (Ethernet/ARP), L3 (ICMP/IP).
  5. Droit : PC↔Switch, Switch↔Routeur. Croisé : PC↔PC, Switch↔Switch (legacy).

Configuration de référence

PC-Admin:     192.168.1.10 / 255.255.255.0
PC-Etudiant:  192.168.1.20 / 255.255.255.0
PC-Serveur:   192.168.1.5  / 255.255.255.0
Switch:       Aucune config IP (L2)
