TD 03 — QoS et Traffic Shaping pour Applications Multimedia

Attribute Value
Level Master RSID
Semester M2
Estimated duration 2 h
Module Projet-Recherche
Enseignant BELACEL Madani
Chapters associés Ch. 03

Objectives

  • Configurer des classes DiffServ pour trafic multimédia
  • Mettre en œuvre du traffic shaping (policing, shaping)
  • Analyser l'impact des paramètres QoS sur la perception utilisateur

Consignes générales

  • Justifier toutes les réponses (calculs, schémas, tableaux).
  • Les schémas doivent être lisibles et légendés.
  • Durée indicative : 2 h en autonomie encadrée.

Exercice 1 — Classification DiffServ (6 pts)

On considère un réseau IP supportant trois types de trafic :

Trafic DSCP Bande passante requise Sensibilité latence
VoIP EF (46) 128 Kbps par flux < 150 ms
Vidéo 4K AF41 (34) 25 Mbps par flux < 200 ms
Web / Mail BE (0) Best-effort Aucune
  1. Proposer une politique de classification sur le router d'accès.
  2. Justifier l'ordre de priorité des files d'attente.

Exercice 2 — Traffic Shaping (6 pts)

Un fournisseur d'accès propose un abonnement 100 Mbps avec un CIR (Committed Information Rate) de 50 Mbps et un CBS (Committed Burst Size) de 10 Mo.

  1. Expliquer le rôle du token bucket dans ce contexte.
  2. Calculer le temps nécessaire pour écouler un burst de 50 Mo.
  3. Proposer une configuration d'interface router Cisco (policy-map, class, shape/police).

Exercice 3 — QoS E2E (4 pts)

Décrire la chaîne de traitement QoS de bout en bout pour un appel VoIP entre deux sites distants (Site A → FAI → CDN → Site B). Préciser les points de dégradation possibles.

Exercice 4 — Analyse MOS (4 pts)

À partir des métriques de QoS collectées (latence = 180 ms, jitter = 40 ms, perte = 2 %), estimer la note MOS (Mean Opinion Score) de la communication VoIP. La formule simplifiée est :

MOS = 4.5 - 0.03 * L - 0.01 * J - 0.2 * P

où L = latence (ms), J = jitter (ms), P = perte (%).

Annexe — Corrigé TD 03

  1. Classification : class-map match-all VOIP → match dscp EF ; class-map match-all VIDEO → match dscp AF41 ; class-map match-all WEB → match dscp default
  2. Token bucket : le seau se remplit à 50 Mbps (CIR), taille max 10 Mo (CBS) ; un burst de 50 Mo nécessite (50-10)/50 + 10/50 = 0.8 + 0.2 = 1.0 s si le seau était plein
  3. Chafne E2E : terminal → switch accès → router aggregation → FAI → internet → CDN → site B ; dégradations : congestion accès, bufferbloat, perte paquets, jitter accumulateur
  4. MOS = 4.5 - 0.03180 - 0.0140 - 0.2*2 = 4.5 - 5.4 - 0.4 - 0.4 = -1.7 → qualité inacceptable. Seuils à respecter : latence < 150 ms, jitter < 30 ms, perte < 1 %.
