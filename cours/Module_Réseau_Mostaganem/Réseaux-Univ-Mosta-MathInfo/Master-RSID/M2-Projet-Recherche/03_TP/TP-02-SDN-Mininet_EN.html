TP 02 — SDN/OpenFlow avec Mininet

Objectives

  • Déployer une topologie SDN avec Mininet
  • Configurer les flux OpenFlow via un contrôleur POX/Ryu
  • Observer et analyser le trafic SDN avec Wireshark

Matériel et logiciels

Élément Version / Remarque
Mininet 2.3+ (VM ou Linux natif)

Wireshark Dernière version stable

Partie 1 — Context et topologie

Context

On souhaite simuler un réseau SDN simple avec un contrôleur centralisé. La topologie comprend 3 switches OpenFlow et 4 hôtes, avec un contrôleur POX ou Ryu.

Topology cible

          ┌──────────┐
          │Controlleur│
          │ (POX/Ryu) │
          └─────┬────┘
                │
    ┌───────────┼───────────┐

┌───┴───┐  ┌───┴───┐  ┌───┴───┐

Partie 2 — Étapes pratiques

Étape 1 — Lancer Mininet (topologie personnalisée)

Créer un script Python topo-sdn.py :

from mininet.topo import Topo

class MyTopo(Topo):
    def build(self):
        s1 = self.addSwitch('s1')
        s2 = self.addSwitch('s2')
        s3 = self.addSwitch('s3')
        h1 = self.addHost('h1')
        h2 = self.addHost('h2')
        h3 = self.addHost('h3')
        h4 = self.addHost('h4')
        self.addLink(s1, s2)
        self.addLink(s2, s3)
        self.addLink(h1, s1)
        self.addLink(h2, s1)
        self.addLink(h3, s2)
        self.addLink(h4, s3)

topos = { 'mytopo': (lambda: MyTopo()) }

Lancer : sudo mn --custom topo-sdn.py --topo mytopo --controller=remote,ip=127.0.0.1,port=6633

Étape 2 — Contrôleur POX (hub)

Dans un terminal séparé : pox.py forwarding.hub

Tester la connectivité : mininet> pingall

Observer les trames inondées (hub behavior).

Étape 3 — Contrôleur POX (switch L2)

Remplacer par : pox.py forwarding.l2_learning

Vérifier que pingall fonctionne avec forwarding intelligent.

Étape 4 — Observer les flux OpenFlow

Wireshark sur l'interface loopback (lo) — filtre : openflow_v1 ou openflow_v4.

Identifier les messages : OFPT_PACKET_IN, OFPT_FLOW_MOD, OFPT_PACKET_OUT.

Étape 5 — Règles de QoS (optionnel, Ryu)

Utiliser Ryu avec l'application simple_switch.py et configurer une règle de priorité pour le trafic VoIP (DSCP EF).

Partie 3 — Vérifications

Test Résultat attendu
pingall en mode hub OK (mais trafic inondé)
pingall en mode l2_learning OK (switching appris)
OF messages dans Wireshark OFPT_HELLO, FEATURES_REPLY, PACKET_IN, FLOW_MOD
Table de flux (dpctl) dpctl dump-flows → règles actives
