Chapitre 09 — Équipements, dépannage et best practices

Attribut Valeur

Objectifs du chapitre

À l'issue de ce chapitre, l'étudiant sera capable de :

  1. Concevoir une architecture réseau campus (3 tiers, segmentation VLAN).
  2. Appliquer une méthodologie de dépannage structurée et documentée.
  3. Utiliser les outils CLI et Wireshark pour isoler une panne.
  4. Appliquer les bonnes pratiques de sécurité et d'exploitation réseau.

2. Équipements — choix SI

Besoin Équipement Critère
Interconnexion postes Switch L2 manageable Ports PoE si AP
Routage inter-VLAN Switch L3 ou routeur Débit, ACL
Accès Internet Routeur + pare-feu NAT, VPN (aperçu)
Wi-Fi Contrôleur + AP Couverture, WPA3
Supervision Serveur NMS / SNMP Alertes (aperçu)

Comparaison routeur vs switch L3 vs pare-feu

Fonction Routeur Switch L3 Pare-feu
Routage IP ✅ ✅ ✅ (policy-based)
Commutation L2 ❌ ✅ Parfois
NAT ✅ ✅ ✅
Filtrage sécurité Basique (ACL) ACL L3/L4 Avancé (L7 NGFW)
Débit switching — Très élevé Variable

3. Méthodologie de dépannage

3.1 Processus en 8 étapes

Étape Action
1 Définir le problème (qui, quoi, quand, où)
2 Collecter informations (changements récents, logs)
3 Reproduire ou confirmer le symptôme
4 Isoler la couche (OSI bottom-up ou top-down)
5 Hypothèse — cause probable
6 Tester la correction
7 Vérifier solution complète
8 Documenter (ticket, runbook)

3.2 Arbre de décision

Pas d'accès réseau ?
├─ ping 127.0.0.1 FAIL → Stack TCP/IP / driver NIC
├─ ping GW FAIL → L1/L2/L3 local (câble, IP, masque, VLAN, switch)
├─ ping 8.8.8.8 FAIL → Routage, NAT, pare-feu sortie, FAI
├─ ping nom FAIL → DNS
└─ ping OK, app FAIL → L7 (proxy, certificat, service down)

3.3 Documentation incident (modèle)

Champ Exemple
ID INC-2025-0142
Symptôme « Pas Internet salle TP2 »
Couche identifiée L3 — route par défaut absente
Cause racine Mise à jour efface config routeur
Correction ip route 0.0.0.0 0.0.0.0 Gi0/0
Prévention Backup config, change management

4. Outils essentiels

4.1 Windows / Linux

# Connectivité
ping -n 4 8.8.8.8
tracert www.univ-mosta.dz
pathping 8.8.8.8          # Windows — combinaison ping/traceroute

# Configuration
ipconfig /all             # Windows
ip addr show              # Linux
ip route show             # Linux

# DNS
nslookup www.univ-mosta.dz
Resolve-DnsName www.univ-mosta.dz   # PowerShell

# Ports / connexions
netstat -an
Test-NetConnection -ComputerName 8.8.8.8 -Port 443   # PowerShell
ss -tulnp                 # Linux

# Couche 2
arp -a
getmac                    # Windows

5. Scénarios types (TP 06)

# Symptôme Cause Couche
1 Un seul PC isolé Mauvais VLAN port access L2
2 Tout un VLAN down Trunk down / native VLAN mismatch L2
3 Inter-VLAN échoue Pas de routage L3 / ACL L3

6. Best practices

6.1 Sécurité

Pratique Détail
Segmentation VLAN Invités ≠ serveurs ≠ admin
Désactiver ports inutilisés shutdown sur interfaces
SSH, pas Telnet Chiffrement management
Mots de passe forts Enable secret, console
Sauvegarde configs copy run start, versioning
VLAN 1 non utilisé Native VLAN dédié (99)

6.2 Exploitation

Pratique Détail
Nommage cohérent SW-TP1-Oran, R-GW-Core
Documentation Schéma à jour, plan IP
Monitoring Logs, SNMP traps (aperçu)
Change management Tester avant production
Redondance Double uplink distribution-core

6.3 Checklist mise en service

  • [ ] Plan IP validé (VLSM)
  • [ ] VLANs créés et documentés
  • [ ] Routage inter-VLAN testé
  • [ ] NAT/DHCP fonctionnels
  • [ ] Sauvegarde config initiale
  • [ ] Tests ping/traceroute depuis chaque VLAN
  • [ ] Accès management sécurisé
