Cours 08 : Sécurité et détection d'attaques dans RPL-AER

Cours 08 — Sécurité et détection d'attaques
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h30
  • Objectifs : Comprendre les types d'attaques, leur détection par attack_detector.c, et la gestion des faux positifs

1. Vulnérabilités du protocole RPL

RPL standard présente plusieurs vulnérabilités de sécurité :

  • Absence d'authentification des messages de contrôle (DIO, DAO, DIS)
  • Topologie prévisible facilitant les attaques ciblées
  • Mécanismes de routage exploitables par des nœuds malveillants

RPL-AER adresse ces vulnérabilités via le module attack_detector.c qui surveille en continu le comportement des nœuds.

2. Attaque Sinkhole

L'attaque sinkhole (ou trou noir) consiste pour un nœud malveillant à annoncer un chemin de très haute qualité (MCS très élevé) pour attirer tout le trafic vers lui, puis à dropper les paquets.

Mécanisme de détection dans RPL-AER :

// attack_detector.c — Détection sinkhole
int detect_sinkhole(uint16_t node_id, float mcs, float nre) {
    if (mcs > SINKHOLE_MCS_THRESHOLD && nre < SINKHOLE_NRE_THRESHOLD) {
        // MCS anormalement élevé pour un nœud avec peu d'énergie
        LOG_WARN("Sinkhole suspect sur nœud %u\n", node_id);
        return 1;
    }
    return 0;
}

Le seuil SINKHOLE_MCS_THRESHOLD est défini à 0.95 et SINKHOLE_NRE_THRESHOLD à 0.3. Un nœud annonçant MCS > 0.95 avec NRE < 0.3 est très suspect.

3. Attaque Selective Forwarding

Le selective forwarding consiste à transmettre certains paquets et en supprimer d'autres, de manière à perturber le réseau sans être détecté comme complètement défaillant.

Détection par analyse du taux de livraison :

int detect_selective_forwarding(uint16_t node_id) {
    float delivery_ratio = get_delivery_ratio(node_id, 300);  // 5 min
    if (delivery_ratio < SF_LOW_THRESHOLD) {
        LOG_WARN("Selective forwarding: nœud %u ratio=%f\n",
                 node_id, delivery_ratio);
        return 1;
    }
    return 0;
}

4. Implémentation de attack_detector.c

Le module attack_detector fonctionne en arrière-plan :

  • Analyse périodique (toutes les 60 secondes) des logs de chaque voisin
  • Maintient une matrice de confiance pour chaque paire de nœuds
  • Déclenche des alertes lorsque des anomalies sont détectées
  • Communique avec trust_module.c pour ajuster les scores de confiance
void attack_detector_init(void) {
    ctimer_set(&detect_timer, DETECT_INTERVAL,
               attack_detector_check, NULL);
}

void attack_detector_check(void *ptr) {
    for each neighbor in neighbor_table {
        if (detect_sinkhole(neighbor.id, neighbor.mcs, neighbor.nre))
            trust_module_adjust_score(neighbor.id, -0.3);
        if (detect_selective_forwarding(neighbor.id))
            trust_module_adjust_score(neighbor.id, -0.2);
    }
}

5. Gestion des faux positifs

Un faux positif se produit quand un nœud honnête est identifié comme malveillant. RPL-AER utilise plusieurs mécanismes pour minimiser ce risque :

  • Seuils progressifs : Une seule anomalie ne suffit pas à exclure un nœud. Plusieurs détections consécutives sont nécessaires.
  • Période d'observation : Avant de déclarer un nœud comme malveillant, attack_detector observe son comportement pendant 5 minutes.
  • Réhabilitation : Un nœud exclu peut être réhabilité si son comportement redevient normal.

6. Logs de détection

[ATTACK] Sinkhole suspect: Node 22 MCS=0.98 NRE=0.15
[ATTACK] Selective forwarding: Node 22 delivery_ratio=0.35
[TRUST] Node 22 Trust=0.12 FLAGGED MALICIOUS
[NET] Node 5: removing Node 22 from parent set (Trust too low)

7. Métriques de sécurité

Les performances du module de sécurité sont évaluées avec :

  • Taux de détection (DR) : Pourcentage d'attaques effectivement détectées
  • Taux de faux positifs (FPR) : Pourcentage de nœuds honnêtes classés comme malveillants
  • Temps de détection : Temps moyen entre le début de l'attaque et sa détection
