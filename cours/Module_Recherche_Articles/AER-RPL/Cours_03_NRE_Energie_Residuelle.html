Cours 03 : NRE — Normalized Residual Energy

Cours 03 — NRE — Normalized Residual Energy
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h
  • Objectifs : Comprendre le modèle énergétique, le calcul du NRE et son rôle dans la métrique MCS

1. Modèle énergétique dans Contiki-NG

Contiki-NG intègre un modèle de consommation énergétique appelé Energest. Ce module trace le temps passé par le microcontrôleur dans chaque état (CPU, LPM, TX, RX) et estime la consommation totale :

Energie = temps_CPU × courant_CPU + temps_LPM × courant_LPM
         + temps_TX × courant_TX + temps_RX × courant_RX

Les valeurs de courant sont paramétrées dans project-conf.h selon le matériel utilisé (ex: Zolertia Z1, Tmote Sky, CC2650).

2. Capacité de la batterie

Chaque nœud possède une capacité de batterie configurable :

#define BATTERY_CAPACITY_MAH 2000  // 2000 mAh
#define INITIAL_ENERGY_MWH   (BATTERY_CAPACITY_MAH * 3.0)  // 6000 mWh pour 3V

L'énergie initiale est convertie en mWh. Au fur et à mesure de la simulation, l'énergie consommée est soustraite de l'énergie initiale pour obtenir l'énergie résiduelle.

3. Calcul de l'énergie résiduelle

L'énergie résiduelle est calculée périodiquement (toutes les 30 secondes par défaut) :

// Dans le module énergétique de RPL-AER
float get_residual_energy(void) {
    float consumed = energest_get_total_energy();
    float initial  = get_initial_energy();
    float residual = initial - consumed;
    if (residual < 0) residual = 0;
    return residual;
}

4. Normalisation du NRE

Le NRE normalise l'énergie résiduelle pour obtenir une valeur entre 0 et 1 :

NRE = get_residual_energy() / get_initial_energy()

Cette normalisation permet de comparer équitablement des nœuds avec des capacités de batterie différentes. Un nœud avec une batterie de 2000 mAh à moitié vide (NRE=0.5) est comparable à un nœud avec une batterie de 4000 mAh à moitié vide (NRE=0.5).

5. Rôle du NRE dans la décision de routage

Le NRE influence directement la sélection du parent dans RPL-AER via le MCS :

  • NRE élevé (>0.7) : Le nœud a suffisamment d'énergie pour servir de parent. Il peut acheminer le trafic des nœuds enfants sans risque d'épuisement.
  • NRE moyen (0.3-0.7) : Le nœud est encore capable de router, mais le MCS sera modéré. Le nœud peut être choisi si ses autres scores (PEC, ECS) sont élevés.
  • NRE faible (<0.3) : Le nœud est en risque d'épuisement. Il sera évité comme parent, même si ses autres scores sont bons.

6. Seuils et alertes

RPL-AER définit des seuils d'alerte énergétique :

#define ENERGY_THRESHOLD_LOW    0.2   // Alerte basse
#define ENERGY_THRESHOLD_CRIT   0.1   // Alerte critique

Lorsque le NRE passe sous le seuil critique, le nœud envoie une notification à ses enfants pour qu'ilschangent de parent, évitant ainsi la perte de paquets suite à l'épuisement complet.

7. Exemple de logs NRE

Pendant la simulation, RPL-AER génère des logs de la forme :

[MCS] Node 15: NRE=0.823, PEC=0.651, ECS=0.432, MCS=0.724
[MCS] Node 15: NRE=0.791, PEC=0.634, ECS=0.445, MCS=0.698
[MCS] Node 15: NRE=0.754, PEC=0.612, ECS=0.458, MCS=0.668

On observe la diminution progressive du NRE à mesure que le nœud consomme son énergie, entraînant une baisse du MCS.
