TP 10 — Collecte des métriques de performance
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h00
  • Objectifs : Collecter et agréger les métriques de performance pour comparer les scénarios

1. Collecte des métriques de performance

Ce TP vise à collecter systématiquement les métriques de performance pour évaluer RPL-AER.

Objectifs pédagogiques
  • Collecter les métriques clés : PDR, latence, throughput, énergie
  • Automatiser la collecte sur plusieurs simulations
  • Calculer des statistiques agrégées
  • Préparer les données pour l'analyse scientifique

2. Script de collecte automatisée

1 #!/usr/bin/env python3 2 import subprocess 3 import re 4 import json 5 import os 6 7 def extract_metrics(log_file): 8 with open(log_file) as f: 9 logs = f.read() 10 metrics = {} 11 pdr = re.findall(r"PDR = ([0-9.]+)", logs) 12 metrics["pdr"] = { 13 "mean": sum(float(p) for p in pdr) / len(pdr), 14 } if pdr else None 15 latency = re.findall(r"Avg Latency = ([0-9.]+) ms", logs) 16 metrics["latency"] = { 17 "mean": sum(float(l) for l in latency) / len(latency) 18 } if latency else None 19 energy = re.findall(r"Energy=([0-9]+) mWh", logs) 20 metrics["energy"] = { 21 "initial": int(energy[0]), "final": int(energy[-1]) 22 } if energy else None 23 return metrics 24 25 scenarios = ["scenario_20_static.csc", "scenario_40_mixed.csc"] 26 all_metrics = {} 27 for s in scenarios: 28 log = f"cooja_results/{s.replace('.csc', '.log')}" 29 if os.path.exists(log): 30 all_metrics[s] = extract_metrics(log) 31 32 with open("cooja_results/all_metrics.json", "w") as f: 33 json.dump(all_metrics, f, indent=2)

3. Tableau récapitulatif

1 import json 2 3 with open("cooja_results/all_metrics.json") as f: 4 data = json.load(f) 5 6 print(f"{'Scénario':<30} {'PDR(%)':<10} {'Latence(ms)':<12} {'Énergie':<12} {'Attaques':<10}") 7 print("-" * 74) 8 for scenario, metrics in data.items(): 9 pdr = f"{metrics['pdr']['mean']:.1f}" if metrics["pdr"] else "N/A" 10 lat = f"{metrics['latency']['mean']:.1f}" if metrics["latency"] else "N/A" 11 eng = f"{metrics['energy']['final']}" if metrics["energy"] else "N/A" 12 print(f"{scenario:<30} {pdr:<10} {lat:<12} {eng:<12}")
Vérification

Vérifiez que le fichier all_metrics.json contient les données pour chaque scénario. Les valeurs de PDR doivent être comprises entre 0 et 100%.

Dépannage

Aucune métrique extraite : vérifiez le format des logs. Les logs doivent contenir les motifs 'PDR =', 'Avg Latency =', 'Energy='.

Questions de réflexion
  1. Quel scénario donne le meilleur PDR ? Pourquoi ?
  2. Quel est l'impact du nombre de nœuds sur la latence moyenne ?
  3. Comment l'énergie finale varie-t-elle entre les scénarios ?
  4. Quelle métrique est la plus impactée par la mobilité ?
  5. Proposer une méthodologie pour comparer RPL-AER avec RPL standard.
Livrables

Scripts collect_metrics.py, fichier all_metrics.json, tableau dans metrics_summary.txt.
