TP 01 : Cloner et explorer le dépôt RPL-AER

TP 01 — Cloner et explorer le dépôt RPL-AER
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 45 minutes
  • Objectifs : Cloner le dépôt, explorer la structure, comprendre chaque fichier

1. Cloner le dépôt GitHub

# Les codes sont déjà présents localement
# Si nécessaire, cloner depuis GitHub:
# git clone https://github.com/madani-belacel/RPL-AER.git
cd /home/madani/contiki-ng/examples/projet_madani/RPL-AER-main
Objectifs pédagogiques
  • Cloner le dépôt RPL-AER depuis GitHub
  • Explorer la structure du projet et ses fichiers
  • Comprendre le rôle de chaque module
  • Se familiariser avec les outils de développement

2. Explorer la structure

ls -la
ls -R | head -40

3. Examiner les fichiers principaux

3.1. rpl-aer.c et rpl-aer.h

grep -n "rpl_aer_calculate_mcs\|rpl_aer_init\|rpl_aer_log_mcs" examples/rpl-aer/rpl-aer.c

Résultat attendu :

77: float rpl_aer_calculate_mcs(void)
297: void rpl_aer_log_mcs(void)
321: void rpl_aer_init(void)

3.2. mcs_calculator.h

cat examples/rpl-aer/mcs_calculator.h

3.3. lstm_predictor.h

cat examples/rpl-aer/lstm_predictor.h

4. Examiner les fichiers de configuration

cat examples/rpl-aer/project-conf.h
cat examples/rpl-aer/Makefile

5. Examiner les scripts

cat tools/build_and_test.sh
Vérification

Vérifiez que tous les fichiers listés ci-dessus existent et sont lisibles. Utilisez `ls -la` pour confirmer la présence des 15+ fichiers sources.

Dépannage

Si le dépôt n'est pas trouvé, vérifiez le chemin : `ls /home/madani/contiki-ng/examples/projet_madani/`. Si le dossier RPL-AER-main n'existe pas, lancez : `git clone https://github.com/madani-belacel/RPL-AER.git`

Questions de réflexion
  1. Combien de fichiers sources C contient le projet ?
  2. Quels paramètres prend la fonction mcs_calculator_compute() ?
  3. Quelle est la taille de la fenêtre LSTM (LSTM_WINDOW_SIZE) ?
  4. Quels types d'attaques sont définis dans attack_detector.h ?
  5. Comment le harvest_module simule-t-il le cycle jour/nuit ?
Livrables

Fichier exploration.txt contenant : la liste complète des fichiers avec leur rôle, les réponses aux questions ci-dessus, et un diagramme textuel de l'architecture (modules et leurs interactions).
