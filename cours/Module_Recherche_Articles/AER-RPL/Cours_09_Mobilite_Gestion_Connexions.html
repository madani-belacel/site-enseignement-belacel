Cours 09 : Mobilité et gestion des connexions

Cours 09 — Mobilité et gestion des connexions
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h
  • Objectifs : Comprendre la gestion de la mobilité dans RPL-AER, le modèle Random Waypoint et son impact sur les performances

1. Mobilité dans les réseaux IoT agricoles

Dans les scénarios agricoles, la mobilité peut provenir de plusieurs sources :

  • Drones de surveillance : survolent les champs pour collecter des données
  • Robots agricoles : se déplacent pour l'irrigation, la fertilisation ou la récolte
  • Capteurs mobiles : montés sur du bétail ou des véhicules

Ces nœuds mobiles doivent rester connectés au réseau tout en se déplaçant, ce qui pose des défis pour le routage RPL.

2. Modèle Random Waypoint

RPL-AER utilise le modèle de mobilité Random Waypoint (RWP) implémenté dans Cooja. Dans ce modèle :

  • Chaque nœud choisit une destination aléatoire dans la zone de simulation
  • Il se déplace vers cette destination à une vitesse aléatoire (typiquement 0.5-2 m/s)
  • Arrivé à destination, il marque une pause (10-30 secondes)
  • Le cycle recommence avec une nouvelle destination

3. Impact sur le routage RPL

La mobilité affecte le routage RPL de plusieurs manières :

  • Reconstruction du DODAG : Un nœud mobile change fréquemment de parent, provoquant des mises à jour du DODAG
  • Fluctuation du MCS : Le NRE du nœud mobile est moins affecté (panneau solaire), mais le PEC et l'ECS varient avec la position
  • Pertes de paquets : Les changements de parent peuvent entraîner des pertes temporaires

4. Gestion de la mobilité dans RPL-AER

RPL-AER implémente plusieurs mécanismes pour gérer la mobilité :

// Configuration de la mobilité
#define MOBILITY_SPEED_MIN  0.5   // m/s
#define MOBILITY_SPEED_MAX  2.0   // m/s
#define MOBILITY_PAUSE_MIN  10    // secondes
#define MOBILITY_PAUSE_MAX  30    // secondes
#define MOBILITY_NODES_PCT  28    // % de nœuds mobiles

4.1 Détection de la mobilité

Un nœud détecte qu'il est en mouvement via les variations du RSSI de ses voisins fixes :

int is_node_mobile(void) {
    float rssi_variance = get_rssi_variance(NEIGHBOR_WINDOW);
    return (rssi_variance > MOBILITY_RSSI_THRESHOLD);
}

4.2 Ajustement du MCS pour la mobilité

Quand un nœud est détecté comme mobile, son MCS est ajusté pour éviter les changements fréquents de parent :

float adjust_mcs_for_mobility(float mcs, int is_mobile) {
    if (is_mobile) {
        return mcs * MOBILITY_PENALTY;  // Pénalité de 0.85
    }
    return mcs;
}

5. Métriques de performance avec mobilité

Les performances du réseau avec mobilité sont évaluées via :

  • PDR (Packet Delivery Ratio) : Ratio de paquets reçus avec/sans mobilité
  • Temps de convergence : Temps nécessaire au DODAG pour se stabiliser après un changement
  • Nombre de changements de parent : Reflète la stabilité du routage
