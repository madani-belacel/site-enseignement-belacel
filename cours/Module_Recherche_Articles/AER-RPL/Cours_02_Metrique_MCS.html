Cours 02 : La métrique Multi-Criteria Score (MCS)

Cours 02 — La métrique Multi-Criteria Score (MCS)
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h30
  • Objectifs : Comprendre la formule MCS, les poids α/β/γ et leur implémentation

1. Définition du MCS

Le Multi-Criteria Score (MCS) est une métrique composite qui fusionne trois critères pondérés pour évaluer la qualité d'un parent potentiel dans le DODAG RPL :

MCS = α × NRE + β × PEC + γ × ECS

Où :

  • α (MCS_ALPHA) — Poids de l'énergie résiduelle (NRE), typiquement 0.5
  • β (MCS_BETA) — Poids de la prédiction de consommation (PEC), typiquement 0.3
  • γ (MCS_GAMMA) — Poids du score contextuel (ECS), typiquement 0.2
Objectifs pédagogiques
  • Comprendre la formule du MCS et le rôle de chaque composant
  • Analyser l'impact des poids α, β, γ sur la sélection du parent
  • Étudier l'implémentation du calcul du MCS dans le code source
  • Interpréter les logs MCS générés par la simulation

2. Implémentation dans rpl-aer.c

La fonction rpl_aer_calculate_mcs() dans rpl-aer.c:77 implémente le calcul :

1 float rpl_aer_calculate_mcs(void) { 2 float nre = rpl_aer_calculate_nre(); 3 float pec = rpl_aer_calculate_pec(); 4 float ecs = rpl_aer_calculate_ecs(); 5 6 rpl_aer_ctx.mcs.mcs = (NRE_WEIGHT * nre) + 7 (PEC_WEIGHT * pec) + 8 (ECS_WEIGHT * ecs); 9 10 return rpl_aer_ctx.mcs.mcs; 11 }

Les constantes NRE_WEIGHT, PEC_WEIGHT et ECS_WEIGHT sont définies dans project-conf.h ou rpl-aer.h.

3. La fonction mcs_calculator_compute

Le fichier mcs_calculator.h:14 déclare la fonction de calcul alternative :

1 float mcs_calculator_compute( 2 float nre, float etx_norm, float trustscore, 3 float alpha, float beta, float gamma 4 );

Cette version inclut également l'ETX normalisé et le Trust Score en plus du NRE, avec une flexibilité de paramétrage via α, β, γ passés en arguments.

4. Pondération et impact

Poids Valeur typique Impact
α (NRE)0.5Favorise les nœuds avec beaucoup d'énergie résiduelle
β (PEC)0.3Favorise les nœuds avec une faible consommation prédite
γ (ECS)0.2Favorise les nœuds dans un environnement favorable (solaire, stable)

La somme des poids est normalisée à 1.0 (α + β + γ = 1.0).

5. Logging du MCS

La fonction rpl_aer_log_mcs() à la ligne 297 de rpl-aer.c génère les logs :

1 void rpl_aer_log_mcs(void) { 2 LOG_INFO("RPL-AER: MCS=%.3f (NRE=%.3f, PEC=%.3f, ECS=%.3f)\n", 3 rpl_aer_ctx.mcs.mcs, rpl_aer_ctx.mcs.nre, 4 rpl_aer_ctx.mcs.pec, rpl_aer_ctx.mcs.ecs); 5 }

Exemple de sortie dans les logs :

RPL-AER: MCS=0.723 (NRE=0.850, PEC=0.600, ECS=0.800)
Questions de réflexion
  1. Si α=0.5, β=0.3, γ=0.2, quel est le MCS pour NRE=0.8, PEC=0.6, ECS=0.7 ? (Calculer)
  2. Que se passe-t-il si un nœud a NRE=0.1 mais ECS=0.9 ? Sera-t-il choisi comme parent ?
  3. Pourquoi la somme α+β+γ doit-elle être égale à 1.0 ?
  4. Proposer une autre combinaison de poids pour un scénario avec forte mobilité.
  5. Comment le trust module peut-il modifier le MCS final ?
