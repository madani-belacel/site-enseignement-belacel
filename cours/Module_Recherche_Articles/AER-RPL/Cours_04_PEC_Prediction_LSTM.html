Cours 04 : PEC — Prédiction LSTM de consommation

Cours 04 — PEC — Prédiction LSTM de consommation
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h30
  • Objectifs : Comprendre l'architecture LSTM, son rôle dans la prédiction de consommation et son intégration dans RPL-AER

1. Pourquoi un LSTM pour la prédiction énergétique ?

La consommation énergétique des nœuds IoT n'est pas constante. Elle varie selon le trafic réseau, les cycles d'émission/réception, et les événements capteurs. Un réseau de neurones LSTM (Long Short-Term Memory) est particulièrement adapté car il peut capturer les dépendances temporelles dans les séquences de consommation.

Contrairement à un réseau feedforward classique, le LSTM possède une mémoire interne (cell state) qui lui permet de retenir des informations sur le long terme.

2. Architecture du LSTM dans RPL-AER

Le prédicteur LSTM implémenté dans lstm_predictor.c est une version légère adaptée aux contraintes mémoire des nœuds IoT :

  • Couche d'entrée : Séquence de 5 pas de temps (window_size = 5) de consommation énergétique normalisée
  • Couche LSTM : 4 cellules LSTM (taille réduite pour l'embarqué)
  • Couche de sortie : Un neurone avec activation sigmoïde produisant la prédiction normalisée
// Architecture simplifiée du LSTM
#define LSTM_WINDOW_SIZE  5   // Séquence d'entrée
#define LSTM_HIDDEN_SIZE  4   // Nombre de cellules cachées
#define LSTM_OUTPUT_SIZE  1   // Sortie : consommation prédite

3. Fonctionnement du prédicteur

Le module lstm_predictor.c fonctionne en trois étapes :

  1. Collecte : À chaque intervalle (30s), la consommation est enregistrée dans un buffer circulaire
  2. Prédiction : Toutes les 5 minutes, le LSTM prédit la consommation pour les 5 prochains intervalles
  3. Mise à jour du PEC : La prédiction est convertie en score PEC entre 0 et 1

4. Conversion en score PEC

La prédiction brute du LSTM (consommation en mW) est convertie en PEC normalisé :

float predict_to_pec(float predicted_consumption) {
    // Plus la consommation prédite est faible, plus le PEC est élevé
    float pec = 1.0 - (predicted_consumption / MAX_CONSUMPTION);
    if (pec < 0) pec = 0;
    if (pec > 1) pec = 1;
    return pec;
}

Un PEC élevé signifie que le nœud prévoit une faible consommation future, ce qui le rend plus fiable comme parent.

5. Implémentation du stub LSTM dans Cooja

Dans la simulation Cooja, le LSTM est implémenté comme un stub qui émule le comportement du réseau de neurones sans nécessiter de framework ML lourd :

// lstm_predictor.c — stub de prédiction
float lstm_predict(float *window, int len) {
    // Modèle pré-entraîné : combinaison linéaire simplifiée
    float weights[] = {0.1, 0.15, 0.2, 0.25, 0.3};
    float prediction = 0;
    for (int i = 0; i < len; i++) {
        prediction += weights[i] * window[i];
    }
    return prediction;
}

Pour une utilisation réelle, les poids seraient obtenus par entraînement sur Keras/TensorFlow puis exportés vers le firmware.

6. Logs de prédiction

Les logs LSTM permettent d'évaluer la qualité de la prédiction :

[LSTM] Node 12: Pred=4.32mW Actual=4.18mW Error=0.14mW MAE=0.12
[LSTM] Node 12: Pred=4.45mW Actual=4.51mW Error=0.06mW MAE=0.11
[LSTM] Node 12: Pred=4.10mW Actual=5.02mW Error=0.92mW MAE=0.38

La Mean Absolute Error (MAE) est calculée en continu pour évaluer la dérive du modèle. Une MAE < 0.5 mW est considérée comme acceptable.

7. Impact sur le routage

La prédiction LSTM permet d'anticiper l'épuisement d'un nœud avant qu'il ne se produise. Par exemple, si le LSTM prédit une consommation élevée (PEC faible) pour un nœud dans les 5 prochaines minutes, RPL-AER peut progressivement rediriger le trafic vers d'autres parents avant que le nœud ne s'éteigne, assurant ainsi une continuité de service.
