Cours 06 : Module de confiance et sécurité

Cours 06 — Module de confiance et sécurité
  • Auteur : Dr. Madani BELACEL
  • Durée estimée : 1h30
  • Objectifs : Comprendre le module de confiance Trust, le calcul du score, et la détection d'attaques

1. Pourquoi un module de confiance ?

Les réseaux IoT agricoles sont vulnérables à diverses attaques. Un nœud compromis peut perturber le routage en attirant le trafic (sinkhole) ou en supprimant sélectivement des paquets (selective forwarding). Le module Trust de RPL-AER surveille en continu le comportement des voisins et calcule un score de confiance pour chaque nœud.

2. Calcul du Trust Score

Le Trust Score combine trois indicateurs :

Trust = w_rssi × S_rssi + w_ack × S_ack + w_mcs × S_mcs_coherence
  • S_rssi : Cohérence du RSSI — si le RSSI d'un voisin change de manière brutale et inattendue, c'est un signe d'anomalie
  • S_ack : Taux d'acquittement — un faible taux d'ACK (paquets non acquittés) peut indiquer un nœud malveillant qui droppe les paquets
  • S_mcs_coherence : Cohérence du MCS — si le MCS annoncé par un nœud est incohérent avec son état réel (ex: MCS élevé mais NRE bas)

3. Détection basée sur le RSSI

L'attaque sinkhole se caractérise par un nœud qui annonce un très bon chemin (faux) pour attirer tout le trafic. Le module Trust détecte cette anomalie en analysant le RSSI :

// trust_module.c — analyse du RSSI
float check_rssi_anomaly(uint16_t neighbor_id, int16_t rssi) {
    // Comparer avec la moyenne historique
    int16_t avg_rssi = get_historical_rssi(neighbor_id);
    int16_t delta = abs(rssi - avg_rssi);
    if (delta > RSSI_ANOMALY_THRESHOLD) {
        return 0.3;  // Faible score — anomalie détectée
    }
    return 0.9;  // Score normal
}

4. Détection des attaques Selective Forwarding

Le selective forwarding (ou gray hole) est une attaque où le nœud malveillant transmet certains paquets et en supprime d'autres. Le module Trust détecte cette attaque en surveillant le ratio paquets reçus / paquets attendus :

float check_forwarding_rate(uint16_t neighbor_id) {
    uint32_t expected = get_expected_packets(neighbor_id);
    uint32_t forwarded = get_forwarded_packets(neighbor_id);
    float rate = (expected > 0) ? (float)forwarded / expected : 1.0;
    if (rate < FORWARDING_THRESHOLD) {
        return 0.2;  // Attaque probable
    }
    return 0.8 + 0.2 * rate;  // Score normal
}

5. Gestion des faux positifs

Un défi majeur des systèmes de détection est le taux de faux positifs (un nœud honnête classé comme malveillant). RPL-AER utilise un mécanisme de seuil progressif :

  • Un Trust < 0.3 déclenche une alerte et l'exclusion temporaire du nœud
  • Un Trust entre 0.3 et 0.6 déclenche une surveillance renforcée
  • Un Trust > 0.6 est considéré comme normal

6. Logs du module Trust

[TRUST] Node 12: Neighbor 7 Trust=0.85 RSSI=0.9 ACK=0.8 MCS=0.85
[TRUST] Node 12: Neighbor 15 Trust=0.32 RSSI=0.3 ACK=0.4 MCS=0.25 ALERT
[TRUST] Node 15: Flagged as malicious by Node 12 (Trust=0.32)

Le nœud 15 est identifié comme suspect avec un Trust score bas. Le nœud 12 évitera de choisir le nœud 15 comme parent.

7. Intégration avec le MCS

Le Trust Score peut également influencer le MCS pour pénaliser les nœuds suspects :

MCS_final = MCS × Trust

Cette pondération garantit qu'un nœud avec un faible score de confiance (même avec un bon MCS) ne sera pas choisi comme parent, renforçant ainsi la sécurité globale du réseau.
