Variants et études d'ablation

Cours 09 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Fichiers : variants/imacros-*.h

1. Principe de l'étude d'ablation

L'étude d'ablation consiste à désactiver un composant à la fois pour mesurer sa contribution aux performances globales du système. RPL-ClusterIDS définit 7 variantes (plus la baseline B1) qui permettent d'isoler l'impact de chaque mécanisme : clustering, IDS, politiques contextuelles, fitness énergétique, et score LAS.

2. Variante B1 — RPL Standard (baseline)

Configuration : RPL pur, sans aucun module IDS. Aucun clustering, aucune détection.

Rôle : Baseline minimale pour mesurer l'overhead des autres variantes en termes d'énergie et de trafic.

Fichier : imacros-B1.h — toutes les macros IDS désactivées.

3. Variante B2 — RPL + IDS basique

Configuration : RPL + IDS déployé sur tous les nœuds, mais sans clustering. Chaque nœud détecte localement et envoie ses alertes directement à la racine.

Rôle : Mesure l'impact du clustering en comparant avec CLUSTERIDS (MAIN).

Fichier : imacros-B2.h — IDS activé mais clustering désactivé.

4. Variante B3 — RPL + clustering (sans IDS)

Configuration : RPL + mécanisme de clustering (formation des clusters, élection CH), mais sans les modules de détection IDS (R1-R4, LAS, agrégation).

Rôle : Mesure l'overhead du clustering seul (messages de signalling, rotation CH).

Fichier : imacros-B3.h — clustering activé, IDS désactivé.

5. Variante CLUSTERIDS (MAIN) — Système complet

Configuration : RPL-ClusterIDS complet : clustering adaptatif, élection CH avec fitness, détection R1-R4, LAS, agrégation CH, politiques contextuelles.

Rôle : Proposition complète, point de comparaison pour toutes les ablations.

Fichier : imacros-MAIN.h — toutes les fonctionnalités activées.

6. Variante NOCLUS — Ablation du clustering

Configuration : Identique à MAIN mais sans formation de clusters. Tous les nœuds sont membres directs de la racine.

Rôle : Isoler l'impact du clustering adaptatif sur la détection et l'énergie.

Fichier : imacros-NOCLUS.h — IDS_CONF_CLUSTERING=0.

7. Variante NOCTX — Ablation des politiques contextuelles

Configuration : MAIN sans le module ctx_policy. Le monitoring est toujours en mode Full.

Rôle : Mesurer l'économie d'énergie apportée par les politiques adaptatives.

Fichier : imacros-NOCTX.h — IDS_CONF_CTX_POLICY=0.

8. Variante NOENR — Ablation de la fitness énergétique

Configuration : MAIN où l'élection CH n'utilise pas l'énergie résiduelle dans la fonction de fitness (Eq. 3 avec w₁=0).

Rôle : Isoler l'importance de l'énergie dans le choix du CH.

Fichier : imacros-NOENR.h — CH_FITNESS_W1=0.

9. Variante NOML — Ablation du LAS/ML

Configuration : MAIN sans le score LAS (Eq. 4). Les règles R1-R4 fonctionnent individuellement sans combinaison pondérée. Décision basée sur un vote majoritaire simple.

Rôle : Mesurer l'apport du LAS comme métrique composite de détection.

Fichier : imacros-NOML.h — IDS_CONF_LAS=0.
