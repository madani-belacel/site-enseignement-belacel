Élection des Cluster Heads — Fonction de Fitness

Cours 04 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Code source : ch_elect.c / ch_elect.h

1. Rôle du Cluster Head

Le Cluster Head (CH) est le nœud responsable de la coordination de la détection d'intrusion au sein d'un cluster. Ses tâches incluent la collecte des LAS, l'agrégation des scores, la confirmation des alertes et la communication avec la racine RPL. Le choix du CH est critique car il impacte directement l'efficacité énergétique et la qualité de la détection.

2. Fonction de fitness (Eq. 3)

La fitness d'un nœud i pour être CH est calculée par :

F(i) = w₁ · E_res(i) + w₂ · (1 - 1/deg(i)) + w₃ · LQI_avg(i)

Où :

  • E_res(i) — Énergie résiduelle du nœud i (normalisée [0,1])
  • deg(i) — Degré du nœud (nombre de voisins) — plus le degré est élevé, meilleur est le score
  • LQI_avg(i) — Qualité de lien moyenne (Link Quality Indicator) normalisée
  • w₁, w₂, w₃ — Poids configurables (w₁ + w₂ + w₃ = 1, par défaut w₁ = 0.5, w₂ = 0.3, w₃ = 0.2)

3. Processus d'élection

  1. Annonce : chaque nœud calcule sa fitness F(i) et broadcast un message CH_ELECT contenant sa valeur
  2. Comparaison : chaque nœud compare sa fitness avec celles reçues des voisins
  3. Décision : le nœud avec la plus haute fitness dans le voisinage se déclare CH et envoie CH_ANNOUNCE
  4. Affiliation : les autres nœuds rejoignent le CH avec la plus haute affinité (Eq. 1)
  5. Confirmation : si deux CH sont trop proches, un arbitrage basé sur la fitness départage

4. Mécanisme de rotation

Pour éviter l'épuisement des nœuds CH, une rotation périodique est effectuée tous les T_rotation (par défaut 600 secondes simulées). Le processus de rotation :

  • Le CH actuel initie une nouvelle élection en broadcastant CH_ROTATE
  • Tous les nœuds du cluster recalculent leur fitness
  • Le nœud avec la fitness maximale devient le nouveau CH
  • Le transfert de rôle inclut la table des membres et l'état de détection courant

5. Équité et équilibrage de charge

Pour garantir l'équité, les mécanismes suivants sont implémentés :

  • Anti-biais : un facteur de pénalité réduit la fitness des nœuds ayant déjà été CH récemment
  • Taille de cluster : les CH avec trop de membres voient leur fitness réduite pour encourager la scission
  • Seuil d'énergie : un nœud avec E_res < 10% ne peut pas être élu CH

6. Analyse de l'overhead

L'overhead de l'élection CH est mesuré en nombre de messages échangés : O(N) messages par cycle d'élection, où N est le nombre de nœuds. Avec une rotation typique toutes les 10 minutes, l'overhead est négligeable (quelques paquets par heure par nœud).

Implémentation : ch_elect.c — fonctions compute_fitness(), elect_ch(), rotate_ch(). Les poids sont définis dans project-conf.h via CH_FITNESS_W1, CH_FITNESS_W2, CH_FITNESS_W3.
