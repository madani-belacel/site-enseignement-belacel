Formation des clusters et fonction d'affinité

Cours 03 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Durée : 1 séance
  • Objectif : Comprendre clus_form.c : fonction d'affinité (Eq. 1) et re-clustering (Eq. 2)
Objectif pédagogique : Analyser clus_form.c : calcul du score d'affinité, logique de re-clustering, implications sur la topologie.

1. Fonction d'affinité (Eq. 1)

affinity_score = (topo * 3 + energy_term * 2 + traffic_class) % 100

topo        = (node_id + traffic_class) % 8
energy_term = (100 - nre_x100) / 4
traffic_class = 0..3 (C0-C3)
  • Topologie ×3 : poids dominant
  • Énergie ×2 : terme inversé (plus d'énergie = meilleur score)
  • Trafic ×1 : profil C0-C3
  • Score 0-99, seuil de stabilité > 70

2. Re-clustering (Eq. 2)

void clus_form_tick(uint8_t nre_x100, uint8_t traffic_class) {
    uint8_t topo = (uint8_t)((node_id + traffic_class) % 8u);
    uint8_t energy_term = (uint8_t)((100u - nre_x100) / 4u);
    affinity_score = (uint8_t)((topo * 3u + energy_term * 2u + traffic_class) % 100u);
    if(affinity_score > 70) { stable_ticks++; }
    else { stable_ticks = 0; }
}

uint8_t clus_form_should_recluster(void) {
    return stable_ticks > 120 ? 1 : 0;  // ~10 min à 5s/tick
}

3. Paramètres clés

  • Seuil de stabilité : score > 70
  • Période de re-cluster : 120 ticks (~10 min)
  • Poids : topo ×3, énergie ×2, trafic ×1
Vérification : Vérifiez que clus_form_should_recluster() retourne 1 après 120 ticks consécutifs avec affinity_score > 70. Simulez avec node_id=1, traffic_class=2, nre_x100=80.

4. Limitations

  • Implémentation purement locale (pas de communication inter-nœuds)
  • Intégration LQI réservée pour travaux futurs
  • Poids calibrés sur simulation
