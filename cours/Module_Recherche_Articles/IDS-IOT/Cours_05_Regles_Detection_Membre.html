Règles de détection au niveau membre (R1-R4)

Cours 05 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Code source : ids_member.c / ids_member.h

1. Détection locale distribuée

Chaque nœud membre exécute quatre règles de détection locales (R1 à R4) qui surveillent différents aspects du trafic réseau et du comportement des voisins. Ces règles sont légères en calcul et conçues pour fonctionner sur des nœuds contraints en ressources.

2. Règle R1 — Packet Drop Ratio Anomaly

Objectif : Détecter le forwarding sélectif (selective forwarding attack). Un nœud malveillant reçoit des paquets mais ne les transmet pas (ou les transmet partiellement).

Mécanisme : Le membre surveille le ratio de paquets reçus vs. transmis par chaque voisin. Si le Packet Drop Ratio (PDR) d'un voisin dépasse un seuil θ_pdr (typiquement 0.4), une anomalie est signalée.

R1_score = max(0, (PDR_observed - θ_pdr) / (1 - θ_pdr))

3. Règle R2 — Control Message Frequency Anomaly

Objectif : Détecter les attaques par inondation de messages de contrôle RPL (DAO flood, DIO flood).

Mécanisme : Le membre compte le nombre de messages DIO/DAO reçus par intervalle de temps. Si la fréquence dépasse un seuil θ_freq (par défaut 10 messages par période de monitoring), une anomalie est enregistrée.

R2_score = min(1, max(0, (freq_observed - θ_freq) / θ_freq))

4. Règle R3 — Data Rate Anomaly

Objectif : Détecter les anomalies de débit de données, typiques d'une attaque par tunnellisation (wormhole) ou d'un nœud compromis qui génère un trafic anormal.

Mécanisme : Le membre compare le débit observé de chaque voisin avec la moyenne du cluster. Un écart de plus de θ_rate (par défaut 2 écarts-types) déclenche une anomalie.

R3_score = min(1, max(0, |rate_observed - rate_mean| / (θ_rate · rate_stddev)))

5. Règle R4 — DAO Inconsistency

Objectif : Détecter les manipulations de topologie via des messages DAO incohérents (rank attack).

Mécanisme : Le membre vérifie la cohérence des informations de routage annoncées par les voisins. Une incohérence est détectée si le rang annoncé est incompatible avec la topologie locale (ex. : un nœud annonce un rang trop bas par rapport à sa position dans le DODAG).

R4_score = min(1, max(0, |rank_announced - rank_expected| / rank_max))

6. Calcul du LAS (Local Anomaly Score) — Eq. 4

Le Local Anomaly Score combine les scores des quatre règles en une métrique composite :

LAS = w_R1 · R1_score + w_R2 · R2_score + w_R3 · R3_score + w_R4 · R4_score

Avec w_R1 + w_R2 + w_R3 + w_R4 = 1. Par défaut, les poids sont uniformes (0.25 chacun). Le LAS est normalisé entre 0 (comportement normal) et 1 (comportement malveillant certain).

7. Transmission du LAS

Chaque membre transmet son LAS au Cluster Head selon la politique contextuelle :

  • Full : transmission à chaque intervalle de monitoring (toutes les 30s simulées)
  • Balanced : transmission seulement si LAS > seuil_min (0.3)
  • Eco : transmission seulement si LAS > seuil_haut (0.6)
Implémentation : ids_member.c — fonctions apply_rule_R1(), apply_rule_R2(), apply_rule_R3(), apply_rule_R4(), compute_las(). Les seuils sont configurables dans project-conf.h.
