TP 12 — Projet de synthèse — Évaluation complète

TP 12 — Module IDS-IOT / RPL-ClusterIDS
  • Durée : 3 séances
  • Prérequis : Tous les TP précédents
Objectif pédagogique : Synthétiser l'ensemble des connaissances : compiler, simuler, analyser, critiquer et proposer des améliorations.

1. Objectifs du projet

Ce projet de synthèse vous demande de :

  1. Reproduire une campagne complète (ou sous-ensemble significatif)
  2. Produire un rapport d'analyse incluant : tables, figures, interprétation
  3. Identifier les forces et faiblesses de RPL-ClusterIDS
  4. Proposer au moins 3 améliorations concrètes

2. Livrables attendus

2.1 Rapport d'analyse (PDF, 8-12 pages)

  • Introduction et contexte
  • Méthodologie : variants, scénarios, métriques
  • Résultats : Tables II-IX, Figures 1-11
  • Analyse : DR, FAR, F1, énergie, latence, clustering
  • Discussion : forces, faiblesses, limites
  • Améliorations proposées (≥3)
  • Conclusion

2.2 Code produit

  • Script de reproduction (reproduce_campaign.sh)
  • Script d'analyse personnalisé (optionnel)

3. Grille d'évaluation

CritèrePoints
Campagne exécutée (minimum 3 variants × 2 scénarios × 3 seeds)20%
Tables générées et correctes15%
Figures générées et interprétées15%
Analyse critique (forces/faiblesses)25%
Propositions d'amélioration (≥3, argumentées)25%

4. Pistes d'amélioration

  • ML embarqué : remplacer R1-R4 par une forêt aléatoire ou SVM léger
  • LQI dans l'affinité : améliorer la formation des clusters
  • Détection multi-échelle : ajouter une fenêtre temporelle variable
  • Rotation CH adaptative : basée sur l'énergie prédite plutôt que fixe
  • Nouvelles attaques : implémenter sybil, hello flood, version attack
  • Validation matérielle : déployer sur Zolertia RE-Mote
  • Interface utilisateur : dashboard temps réel des alertes

5. Exemple de structure de rapport

1. Introduction (1 page)
   - Contexte IoT et sécurité RPL
   - Présentation de RPL-ClusterIDS

2. Méthodologie (2 pages)
   - Architecture du système (schéma)
   - 8 variantes et protocole d'ablation
   - Campagne : 480 simulations, 50 nœuds
   - Métriques : DR, FAR, F1, énergie

3. Résultats (3 pages)
   - Tables II-IX commentées
   - Figures 1-11 interprétées
   - Comparaison MAIN vs ablations

4. Discussion (2 pages)
   - Forces : détection distribuée, clustering adaptatif
   - Faiblesses : pas de ML, signaux calibrés
   - Limites : simulation seulement

5. Améliorations (2 pages)
   - Proposition 1: forêt aléatoire embarquée
   - Proposition 2: intégration LQI
   - Proposition 3: validation matérielle

6. Conclusion (1 page)

6. Remarques importantes

  • Le rapport doit être rédigé en français ou en anglais
  • Citez les équations (Eq. 1-4) et les tables/figures
  • Soyez critique : identifiez les limitations réelles
  • Les améliorations doivent être réalisables (pas de "solution miracle")

7. Vérification

Vérification : Avant de rendre votre projet, vérifiez :
  1. Le rapport compile sans erreur LaTeX
  2. Toutes les tables et figures sont référencées dans le texte
  3. Les métriques DR, FAR, F1 sont correctement calculées
  4. Au moins 3 améliorations sont proposées et argumentées
  5. Le script de reproduction est exécutable (chmod +x)
Dépannage : Si vous manquez de temps pour la campagne complète (480 sims) : - Réduisez à 3 variants (MAIN, B1, B2) × 2 scénarios (none, mixed) × 3 seeds = 18 sims - Utilisez les données precomputées dans data/ si disponibles
Question réflexive : Si vous deviez ne retenir qu'un seul résultat de ce module, quel serait-il et pourquoi ? Quelle est la contribution la plus importante de RPL-ClusterIDS ?
