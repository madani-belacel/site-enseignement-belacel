TP 06 — Analyse des logs de campagne

TP 06 — Module IDS-IOT / RPL-ClusterIDS
  • Durée : 1 séance
  • Script : parse_cooja_ids_metrics.py

Objectif

Utiliser le script de parsing parse_cooja_ids_metrics.py pour extraire les métriques IDS des fichiers COOJA.testlog générés par la campagne pilote. Comprendre le format METRIC et produire un fichier CSV agrégé.

1. Localiser les scripts

ls scripts/
# Vous devriez voir :
# python/generate_figures.py
# statistics/compute_statistics.py

Le script parse_cooja_ids_metrics.py se trouve dans scripts/python/ ou SIMULATION_CAMPAIGN_READY/.

2. Format METRIC (ids_campaign_log.h)

Chaque ligne de log structuré suit le format :

METRIC,<sim_time_ms>,<node_id>,<event_type>,<value>,<details>

Types d'événements :

  • CH_ELECTED — Nœu élu CH avec sa fitness
  • CLUSTER_FORMED — Cluster formé avec sa taille
  • LAS_COMPUTED — Score LAS calculé par un membre
  • LAS_REPORTED — LAS transmis au CH
  • ALERT_GENERATED — Alerte générée par le CH
  • RULE_TRIGGERED — Règle R1-R4 déclenchée
  • ENERGY_UPDATE — Mise à jour du niveau d'énergie

3. Parser les logs

cd $IDS_ROOT
python3 scripts/python/parse_cooja_ids_metrics.py \
  --input data/real/raw/ \
  --output data/real/parsed/

4. Examiner les fichiers parsés

ls data/real/parsed/
# Vous devriez voir des fichiers CSV comme :
# MAIN_rank_seed1_metrics.csv
# MAIN_rank_seed2_metrics.csv
head -20 data/real/parsed/MAIN_rank_seed1_metrics.csv

5. Comprendre le CSV généré

Le CSV agrège les événements par catégorie :

ColonneDescription
sim_time_msTemps de simulation en ms
node_idID du nœud source
event_typeType d'événement METRIC
valueValeur associée (score, compteur)
detailsDétails supplémentaires (chaîne JSON-like)
variantVariant utilisé (MAIN, B1, etc.)
attack_typeType d'attaque
seedSeed aléatoire

6. Statistiques de base

Utilisez Python ou des outils shell pour analyser :

# Nombre total d'alertes
grep -c "ALERT_GENERATED" data/real/parsed/MAIN_rank_*.csv

# Distribution des types d'événements
cut -d',' -f3 data/real/parsed/MAIN_rank_seed1_metrics.csv | sort | uniq -c | sort -rn

# Score LAS moyen
awk -F',' '$3=="LAS_COMPUTED" {sum+=$4; cnt++} END {print sum/cnt}' \
  data/real/parsed/MAIN_rank_seed1_metrics.csv

7. Détection des attaques

Comparez les alertes générées avec la vérité terrain (ground truth) définie dans la simulation :

# Vrai positif : alerte pour un nœud malveillant
# Faux positif : alerte pour un nœud légitime
# Faux négatif : nœud malveillant sans alerte

Rendu attendu

Produisez un fichier analyse_logs.txt contenant :

  1. Le nombre de lignes parsées par fichier
  2. La distribution des types d'événements
  3. Le nombre d'alertes par seed et par type d'attaque
  4. Le score LAS moyen par seed
  5. Une analyse préliminaire de la détection (vrais/faux positifs)
