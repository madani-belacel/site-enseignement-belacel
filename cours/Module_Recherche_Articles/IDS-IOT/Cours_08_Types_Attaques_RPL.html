Types d'attaques RPL simulées

Cours 08 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Code source : ids_attack.c / ids_attack.h

1. Générateur d'attaques ids_attack.c

Le module ids_attack.c implémente 5 types d'attaques RPL configurables. Les attaques sont activées via des paramètres de compilation ou des messages Cooja. Chaque attaque peut être paramétrée en intensité, durée et moment de déclenchement.

2. Rank Attack (manipulation de rang)

Principe : Un nœud malveillant annonce un rang anormalement bas (généralement 1 ou 2) pour attirer le trafic de ses voisins. En attirant les paquets, il peut les analyser, les modifier ou les dropper.

Paramètres : RANK_ATTACK_VALUE (rang usurpé, défaut=256), RANK_ATTACK_START (temps de début en secondes simulées)

Fonction C : rank_attack_start() — modifie le champ dag_rank dans les messages DIO broadcastés.

Détection par règle : R4 (DAO Inconsistency) — comparaison entre rang annoncé et rang attendu basé sur la topologie locale.

3. Selective Forwarding Attack

Principe : Le nœud malveillant reçoit des paquets mais n'en transmet qu'une fraction. Cette attaque perturbe la communication et peut isoler des parties du réseau.

Paramètres : SEL_FWD_DROP_RATIO (ratio de paquets drop, défaut=0.6), SEL_FWD_MODE (0: aléatoire, 1: ciblé sur certains types de paquets)

Fonction C : selective_forwarding_drop() — intercepte la fonction de transmission et droppe aléatoirement.

Détection par règle : R1 (Packet Drop Ratio Anomaly) — surveillance du ratio paquets reçus vs. transmis.

4. Wormhole Attack (tunnel)

Principe : Deux nœuds malveillants collusoires créent un tunnel hors-bande (via un canal supposé à haute vitesse) pour donner l'illusion qu'ils sont voisins directs. Cela perturbe la topologie RPL et peut attirer le trafic vers les nœuds malveillants.

Paramètres : WORMHOLE_PAIR (IDs des deux nœuds), WORMHOLE_LATENCY (latence simulée du tunnel, défaut=1ms)

Fonction C : wormhole_forward() — redirige les paquets via le tunnel en contournant le routage normal.

Détection par règle : R3 (Data Rate Anomaly) — débit anormal entre les deux extrémités du tunnel ; R2 si le tunnel génère des messages de contrôle.

5. DAO Flood Attack

Principe : Le nœud malveillant inonde le réseau de messages DAO (Destination Advertisement Object) pour épuiser les ressources des nœuds parents et de la racine RPL (mémoire des tables de routage, CPU, énergie).

Paramètres : DAO_FLOOD_INTERVAL (intervalle entre DAO, défaut=0.1s au lieu de 60s normalement), DAO_FLOOD_COUNT (nombre maximum de DAO à envoyer)

Fonction C : dao_flood_start() — programme un timer qui envoie des DAO à haute fréquence.

Détection par règle : R2 (Control Message Frequency Anomaly) — détection de la fréquence anormale de messages DAO/DIO.

6. Mixed Attacks

Principe : Combinaison de plusieurs types d'attaques simultanément ou séquentiellement pour tester la robustesse de l'IDS face à des scénarios complexes.

Combinaisons typiques : rank + selective forwarding, wormhole + DAO flood, rank + wormhole + forwarding sélectif.

Fonction C : mixed_attack_start() — active plusieurs modules d'attaque selon un script défini dans mixed_attack_config.

7. Configuration des attaques

Les attaques sont configurées via des macros de compilation dans project-conf.h ou via des paramètres passés par Cooja.

// Activer les attaques
#define IDS_CONF_ATTACK_ENABLED 1
#define IDS_CONF_ATTACK_TYPE    ATTACK_RANK
#define IDS_CONF_ATTACK_START   60   // début à 60s
#define IDS_CONF_ATTACK_DURATION 300 // durée 300s simulées
Important : Dans une campagne de simulation, chaque seed utilise un positionnement différent des nœuds malveillants (défini dans le template CSC) pour assurer la validité statistique des résultats.
