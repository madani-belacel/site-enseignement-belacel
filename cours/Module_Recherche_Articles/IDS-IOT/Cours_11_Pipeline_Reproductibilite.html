Pipeline de reproductibilité scientifique

Cours 11 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Objectif : Comprendre le pipeline complet de la simulation à la publication

1. Principes de la reproductibilité

La reproductibilité scientifique est un enjeu majeur pour la recherche en réseaux. RPL-ClusterIDS a été conçu selon les principes FAIR (Findable, Accessible, Interoperable, Reusable) avec un pipeline entièrement automatisé qui permet de reproduire l'intégralité des résultats, de la simulation à la génération du manuscrit.

2. Pipeline complet

  1. Génération de scénarios (generate_campaign_csc.py) — Produit les fichiers .csc pour chaque combinaison variant × attaque × seed
  2. Compilation du firmware (build_variant.sh) — Compile les 8 variantes pour la plateforme Cooja
  3. Simulation Cooja (run_ids_campaign.sh) — Exécute les simulations en mode headless
  4. Parsing des logs (parse_cooja_ids_metrics.py) — Extrait les métriques structurées des fichiers COOJA.testlog
  5. Calcul des statistiques (compute_statistics.py) — Produit les Tables II-IX au format LaTeX
  6. Génération des figures (generate_figures.py) — Produit les 11 figures TikZ/PGFPlots
  7. Compilation du manuscrit (pdflatex + bibtex) — Assemble le document final

3. Structure des données

Les données suivent une hiérarchie claire :

data/
├── estimated/        # Données estimées (placeholders)
├── real/
│   ├── raw/          # Logs bruts COOJA.testlog
│   └── parsed/       # CSV parsés et agrégés

4. Support Docker

Un environnement Docker est fourni pour garantir la reproductibilité :

cd docker/
docker build -t ids-iot .
docker run -v $(pwd)/../:/workspace ids-iot /workspace/run_pipeline.sh

Le Dockerfile installe toutes les dépendances nécessaires : Contiki-NG, Cooja, Python 3, pandas, matplotlib, LaTeX (texlive), TikZ/PGFPlots.

5. Script de pipeline unifié

Un script run_pipeline.sh orchestre l'ensemble des étapes :

#!/bin/bash
# Pipeline RPL-ClusterIDS
echo "1. Generating scenarios..."
python3 scripts/generate_campaign_csc.py --campaign --output sim/scenarios/

echo "2. Building firmware..."
cd code_source_RPL_ClusterIDS && ./build_variant.sh all

echo "3. Running simulations..."
./run_ids_campaign.sh all

echo "4. Parsing logs..."
python3 scripts/parse_cooja_ids_metrics.py --input data/real/raw/ --output data/real/parsed/

echo "5. Computing statistics..."
python3 scripts/compute_statistics.py --input data/real/parsed/ --output tables/ --format latex

echo "6. Generating figures..."
python3 scripts/generate_figures.py --csv data/real/parsed/agg --out Figures/

echo "7. Compiling manuscript..."
pdflatex main.tex && bibtex main && pdflatex main.tex && pdflatex main.tex
echo "Pipeline complete."

6. Gestion des seeds aléatoires

Pour garantir la reproductibilité :

  • Chaque seed est explicitement définie dans le fichier CSC
  • Les seeds sont enregistrées dans un fichier seeds.txt
  • Le script de campagne peut reprendre à partir d'un seed spécifique

7. Validation des résultats

Le pipeline inclut des vérifications automatiques :

  • Vérification que tous les fichiers CSC existent avant la simulation
  • Vérification que les logs contiennent des lignes METRIC
  • Comparaison avec les données estimées pour détecter les anomalies
  • Rapport de validation généré après chaque étape

8. Bonnes pratiques pour la recherche reproductible

  • Versionner le code source et les scripts (Git)
  • Documenter toutes les dépendances et versions
  • Utiliser des seeds fixes et documentées
  • Automatiser le pipeline (pas de manipulation manuelle)
  • Fournir un environnement conteneurisé (Docker)
  • Publier les données brutes et les résultats intermédiaires
Référence : Le dépôt IDS-IOT suit les recommandations du ACM Artifact Review and Badging et vise le badge "Artifacts Available" et "Results Reproduced".
