Politiques contextuelles (Full/Balanced/Eco)

Cours 07 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Code source : ctx_policy.c / ctx_policy.h

1. Principe des politiques contextuelles

Les politiques contextuelles permettent d'ajuster dynamiquement l'intensité du monitoring IDS en fonction de l'énergie résiduelle du nœud et du contexte opérationnel. L'objectif est d'optimiser le compromis entre sécurité (taux de détection) et consommation d'énergie (durée de vie du réseau).

2. Mode Full

Description : Monitoring intensif de tous les paquets entrants et sortants. Toutes les règles R1-R4 sont appliquées sur chaque paquet. Les LAS sont transmis au CH à chaque intervalle.

Consommation : Élevée (≈ 15-20% d'overhead énergétique par rapport à RPL standard)

Taux de détection : Maximum (DR > 95% pour la plupart des attaques)

Quand l'utiliser : Périodes de menace élevée, énergie suffisante, nœuds CH

3. Mode Balanced

Description : Monitoring par échantillonnage. Les règles sont appliquées sur 1 paquet sur N (par défaut N=5 pour 20% d'échantillonnage). Les LAS sont transmis seulement s'ils dépassent un seuil bas (0.3).

Consommation : Modérée (≈ 8-10% d'overhead)

Taux de détection : Bon (DR > 85%)

Quand l'utiliser : Fonctionnement normal, équilibre sécurité/énergie

4. Mode Eco

Description : Monitoring déclenché par événement. Les règles sont appliquées seulement si un événement inhabituel est détecté (changement soudain de topologie, message RPL anormal, etc.). Entre les événements, seul un monitoring passif minimal est maintenu.

Consommation : Faible (≈ 3-5% d'overhead)

Taux de détection : Réduit (DR ≈ 70-75%)

Quand l'utiliser : Énergie critique, longue période sans menace détectée

5. Implémentation dans ctx_policy.c

Le module ctx_policy.c expose les fonctions suivantes :

  • set_context_policy(enum ctx_mode mode) — Change la politique courante
  • ctx_should_monitor() — Détermine si le paquet courant doit être inspecté
  • ctx_should_report(float las) — Détermine si le LAS doit être transmis au CH
  • ctx_get_sampling_rate() — Retourne le taux d'échantillonnage courant
  • ctx_energy_overhead() — Estime l'overhead énergétique de la politique courante

6. Transition entre modes

Le système peut basculer automatiquement entre les modes selon l'énergie résiduelle :

Énergie résiduelleMode par défaut
> 60%Full
30% — 60%Balanced
< 30%Eco

La transition peut aussi être déclenchée manuellement via un message de la racine RPL.

7. Compromis sécurité vs énergie

L'analyse préliminaire montre que le mode Balanced offre le meilleur compromis : il préserve 87% du taux de détection du mode Full tout en réduisant l'overhead énergétique de 45%. Le choix de la politique est donc contextuel et peut être adapté dynamiquement.

Note : Les seuils de transition et les taux d'échantillonnage sont configurables dans project-conf.h via les macros CTX_THRESHOLD_FULL, CTX_THRESHOLD_BALANCED, CTX_SAMPLING_RATE.
