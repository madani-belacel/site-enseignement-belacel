Politiques contextuelles (Full/Balanced/Eco)

Cours 07 — Module IDS-IOT / RPL-ClusterIDS
  • Auteur : Dr. Madani BELACEL
  • Durée : 1 séance
  • Objectif : Comprendre l'adaptation contextuelle du niveau de détection
Objectif pédagogique : Analyser ctx_policy.c : trois modes, seuils de transition, impact sur le masque de règles.

1. Les trois modes

ModeMasqueRèglesConsommation
Full (0)0x0FR1+R2+R3+R4Élevée
Balanced (1)0x07R1+R2+R3Moyenne
Eco (2)0x03R1+R2Faible

2. Logique de transition

void ctx_policy_tick(uint8_t nre_x100, uint8_t control_load_x10) {
    if(nre_x100 < 25 || control_load_x10 > 80) {
        mode = IDS_MODE_ECO;            // Faible énergie ou saturation
    } else if(nre_x100 > 70 && control_load_x10 < 40) {
        mode = IDS_MODE_FULL;           // Haute énergie + faible charge
    } else {
        mode = IDS_MODE_BALANCED;       // Compromis
    }
}

uint8_t ctx_policy_rule_mask(void) {
    switch(mode) {
    case IDS_MODE_FULL:     return 0x0F;
    case IDS_MODE_ECO:      return 0x03;
    default:                return 0x07;  // Balanced
    }
}

3. Ablation NOCTX

Le variant NOCTX (FIXED_MODE) désactive ctx_policy_tick(). Le mode reste Balanced toute la simulation.

Vérification : Test : nre_x100=20 (<25) → mode Eco. ctx_policy_rule_mask() doit retourner 0x03.
Question réflexive : Quel est l'impact d'une politique Eco prolongée sur la détection des attaques wormhole (R4) ? Acceptable selon le contexte ?
