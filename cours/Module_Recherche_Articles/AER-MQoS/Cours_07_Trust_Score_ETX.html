Cours 07 — Trust Score basé sur ETX

Type : Cours théorique — Durée : 1h00
Objectif : Comprendre le calcul du Trust Score à partir de l'ETX, son rôle dans la sécurité du routage et son intégration dans la métrique MCS
Prérequis : Cours 03 (MCS), notions d'ETX
Telecharger PDF Telecharger PPTX

1. Définition de l'ETX

L'ETX (Expected Transmission Count) est une métrique qui estime le nombre de transmissions nécessaires pour qu'un paquet soit reçu avec succès. Il est calculé comme :

ETX = 1 / (PDR_forward * PDR_backward)

Où :

  • PDR_forward — probabilité de livraison dans le sens direct (mesurée via les paquets de données ou de contrôle)
  • PDR_backward — probabilité de livraison dans le sens retour (mesurée via les acquittements)

Un ETX de 1.0 indique un lien parfait, un ETX de 3.0 signifie qu'en moyenne 3 transmissions sont nécessaires.

2. De l'ETX au Trust Score

Le Trust Score transforme l'ETX en une mesure de confiance dans [0, 1] via une fonction de mappage :

TrustScore = max(0, 1 - (ETX - 1) / (ETX_max - 1))

Où ETX_max est une valeur seuil au-delà de laquelle le lien est considéré comme non fiable (typiquement 5.0).

Ainsi :

  • ETX = 1.0 → TrustScore = 1.0 (confiance parfaite)
  • ETX = 2.0 → TrustScore = 0.75
  • ETX = 3.0 → TrustScore = 0.50
  • ETX ≥ 5.0 → TrustScore = 0.0 (lien jugé non fiable)

3. Prise en compte des anomalies

Le Trust Score intègre également la détection d'anomalies de routage. Si un nœud détecte :

  • Un rank anomaly : un parent annonce un rank anormalement bas (attaque de type sinkhole)
  • Un selective forwarding : un nœud ne transmet pas les paquets qu'il devrait transmettre
  • Des incohérences de version DODAG

Le Trust Score du nœud suspect est réduit d'un facteur de pénalité (par exemple, divisé par 2). Cette pénalité est appliquée progressivement pour éviter les faux positifs.

4. Implémentation dans aer_rpl_trust.c

Le module aer_rpl_trust.c gère le calcul et la mise à jour du Trust Score :

/* Structure de confiance pour un voisin */
struct trust_entry {
    rpl_nbr_t *neighbor;
    double etx;           // ETX actuel
    double trust_score;   // Score de confiance dans [0,1]
    uint8_t anomaly_count; // Nombre d'anomalies détectées
    clock_time_t last_update;
};

/* Mise à jour du Trust Score à partir de l'ETX */
void aer_rpl_trust_update(rpl_nbr_t *nbr, double etx) {
    struct trust_entry *entry = find_entry(nbr);
    entry->etx = etx;
    // Mise à jour exponentielle lissée
    entry->trust_score = (1 - ALPHA) * entry->trust_score
                         + ALPHA * calculate_base_trust(etx);
    // Appliquer pénalités si anomalies
    if (entry->anomaly_count > 0) {
        entry->trust_score /= (1 + entry->anomaly_count * PENALTY_FACTOR);
    }
}

5. Élagage des voisins non fiables

Un seuil de confiance minimum (AER_TRUST_THRESHOLD, typiquement 0.3) permet d'élaguer les candidats parents dont le Trust Score est trop bas. Ces nœuds ne sont pas considérés lors de la sélection du parent, ce qui protège le DODAG contre les nœuds compromiseés ou défaillants.

6. Rôle du Trust Score dans la métrique MCS

Dans la métrique MCS, le Trust Score est multiplié par le poids gamma. Lorsque gamma est élevé (contexte d'attaque suspectée), les nœuds avec un Trust Score faible sont fortement pénalisés dans le score MCS, ce qui les exclut du routage.

L'agent Q-learning peut également augmenter gamma en réponse à une dégradation des performances, renforçant ainsi l'importance de la confiance dans la décision de routage.

7. Exemple de fonctionnement sous attaque

Considérons un nœud attaquant qui annonce un rank très bas pour attirer le trafic (sinkhole). Les voisins détectent l'anomalie (rank trop bas par rapport à l'ETX) et réduisent son Trust Score à 0.1. Avec gamma = 0.7, la contribution du Trust Score au MCS est de 0.7 × 0.1 = 0.07, même avec un NRE parfait (0.9) et un ETX normalisé bas (0.2), le MCS total serait :

MCS = 0.15 * 0.9 + 0.15 * (1 - 0.2) + 0.7 * 0.1 = 0.135 + 0.12 + 0.07 = 0.325

Un nœud honnête voisin avec NRE=0.7, ETX_norm=0.15, TrustScore=0.95 obtiendrait :

MCS = 0.15 * 0.7 + 0.15 * 0.85 + 0.7 * 0.95 = 0.105 + 0.1275 + 0.665 = 0.8975

Le nœud honnête est nettement préféré, démontrant l'efficacité de la défense.

8. Résumé

Le Trust Score transforme l'ETX et la détection d'anomalies en une mesure de confiance exploitable par la métrique MCS. Il constitue la première ligne de défense d'AER-MQoS contre les attaques de routage, en pénalisant les nœuds suspects et en protégeant l'intégrité du DODAG.
