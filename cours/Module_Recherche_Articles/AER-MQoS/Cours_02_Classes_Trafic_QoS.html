Cours 02 — Classes de trafic et QoS (C0–C3)

Type : Cours théorique — Durée : 1h00
Objectif : Comprendre les quatre classes de trafic QoS et leur rôle dans la différenciation de service
Prérequis : Cours 01, notions de QoS réseau
Télécharger PDF Télécharger PPTX

1. Pourquoi différencier les trafics dans l'IoT ?

Dans un réseau IoT typique, les nœuds capteurs produisent des flux de données hétérogènes : des alarmes critiques nécessitant un acheminement immédiat, des relevés périodiques de température, des diagnostics de maintenance, ou des mises à jour logicielles. Traiter tous ces flux avec la même priorité conduit à une dégradation des performances pour les applications temps réel.

La différenciation QoS (Quality of Service) permet d'attribuer des traitements distincts aux paquets selon leur classe, garantissant aux flux prioritaires une latence réduite, un taux de livraison élevé et une bande passante réservée.

2. Les quatre classes AER-MQoS

AER-MQoS définit quatre classes de trafic, numérotées de C0 (priorité maximale) à C3 (priorité minimale) :

ClasseNomPrioritéExemples d'applicationPoids WRR
C0Haute prioritéCritiqueAlarmes, détection d'intrusion, urgence médicale6
C1Moyenne prioritéImportanteDonnées capteurs temps réel, vidéo surveillance3
C2Basse prioritéNormaleRelevés périodiques, rapports de diagnostic2
C3Meilleur effortFaibleMaintenance, mise à jour firmware, logs1

3. Marquage des paquets

Le marquage de classe est effectué au niveau de l'application émettrice via un champ dédié dans la structure de données du paquet. Dans l'implémentation Contiki-NG, chaque application UDP associe une classe à ses paquets :

/* Exemple de marquage dans l'application émettrice */
#include "aer_qos_queue.h"

void send_alarm(void) {
    packetbuf_clear();
    packetbuf_set_datalen(sizeof(alarm_data));
    memcpy(packetbuf_dataptr(), &alarm, sizeof(alarm_data));
    /* Classe C0 pour l'alarme */
    aer_qos_mark_packet(packetbuf_dataptr(), AER_QOS_CLASS_C0);
    udp_send(&client_conn, sizeof(alarm_data));
}

4. Gestion des files d'attente

Le module aer_qos_queue.c implémente quatre files d'attente FIFO distinctes, une par classe. Chaque file maintient :

  • Un compteur de paquets en attente (queue_length)
  • Un pointeur de tête et de queue pour l'accès FIFO
  • Un mécanisme de drop en cas de saturation (priorité inverse : on drop C3 d'abord)

5. Interaction avec la métrique MCS

La classe de trafic influence également le choix du parent dans le DODAG. AER-MQoS utilise la métrique MCS qui intègre la confiance et l'énergie, et le routage peut favoriser des parents fiables et énergétiquement stables pour les classes prioritaires. Cependant, la décision de routage reste unifiée (un seul DODAG), c'est l'ordonnancement local qui différencie le service.

Principe : Un seul DODAG est construit pour tout le trafic. La différenciation QoS s'opère au niveau de l'ordonnancement local (WRR) et non au niveau de la construction du graphe de routage.

6. Avantages de la classification

  • Garantie de service : les paquets C0 sont toujours transmis avant C1, C2, C3.
  • Équité pondérée : les classes inférieures ne sont pas affamées grâce au ratio WRR 6:3:2:1.
  • Adaptabilité : le ratio peut être ajusté selon les besoins de l'application.
  • Simplicité : le modèle à 4 classes est suffisamment expressif sans complexité excessive.

7. Résumé

Les quatre classes de trafic C0–C3 sont le fondement de la QoS dans AER-MQoS. Elles permettent une différenciation fine des flux IoT, garantissant que les applications critiques reçoivent le service qu'elles exigent. Le prochain cours détaille la métrique MCS qui, combinée à ces classes, offre un routage contextuel adapté aux besoins hétérogènes des LLN.
