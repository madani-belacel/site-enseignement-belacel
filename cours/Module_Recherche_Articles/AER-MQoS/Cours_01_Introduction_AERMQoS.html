Cours 01 — Introduction à AER-MQoS

Type : Cours théorique — Durée : 1h30
Objectif : Comprendre le contexte, la problématique et les contributions du protocole AER-MQoS
Prérequis : Connaissances de base en RPL (RFC 6550), IoT, réseaux de capteurs sans fil
Télécharger PDF Télécharger PPTX

1. Contexte : l'IoT et les réseaux de capteurs sans fil

L'Internet des Objets (IoT) connecte des milliards d'objets physiques — capteurs, actionneurs, dispositifs intelligents — capables de collecter, traiter et échanger des données via Internet. Dans ce contexte, les réseaux de capteurs sans fil (WSN) forment l'infrastructure de base : des nœuds contraints en énergie, mémoire et puissance de calcul communiquent sans fil pour acheminer des données vers un point de collecte (puits).

Le protocole RPL (Routing Protocol for Low-Power and Lossy Networks, RFC 6550) est le standard IETF pour le routage dans les LLN. Il construit un DODAG (Destination-Oriented Directed Acyclic Graph) orienté vers un puits en utilisant des fonctions objectives (OF) qui définissent la métrique de routage.

2. Problématique : les limites de RPL standard

RPL standard utilise des métriques simples comme ETX (Expected Transmission Count) via MRHOF (Multi-Hop Routing Objective Function). Cette approche présente plusieurs limitations :

  • Absence de différenciation QoS : tous les paquets sont traités de la même façon, qu'ils soient une alarme critique ou un relevé périodique.
  • Métrique unique : ETX ne capture que la fiabilité du lien, ignorant l'énergie résiduelle ou la confiance.
  • Pas d'adaptation contextuelle : les poids de métriques sont statiques, incapables de s'adapter aux changements du réseau.
  • Vulnérabilité aux attaques : l'absence de mécanisme de confiance rend RPL sensible aux attaques de routage.

3. AER-MQoS : une extension multi-objectifs contextuelle

AER-MQoS (v1.1) est une extension de RPL qui introduit :

  • Une métrique composite contextuelle (MCS) combinant l'énergie résiduelle normalisée (NRE), la fiabilité des liens (ETX normalisé) et un score de confiance (Trust Score).
  • Quatre classes de trafic QoS (C0–C3) avec des priorités distinctes, ordonnancées par WRR (Weighted Round Robin) selon les proportions 6:3:2:1.
  • Un mécanisme d'adaptation par Q-learning qui ajuste dynamiquement le poids gamma de la confiance dans la métrique MCS en fonction des conditions du réseau.
  • Un modèle d'énergie NRE étendu du protocole RPL-AER, intégrant la capacité de batterie et la consommation résiduelle.
  • Un score de confiance basé sur l'ETX et les anomalies de routage, renforçant la résilience aux attaques.

4. Architecture logicielle

Le code source est organisé autour de modules spécialisés :

  • aer_rpl_plus.c/h : module central implémentant la métrique MCS et la pondération contextuelle (alpha, beta, gamma).
  • aer_qos_queue.c/h : gestion des quatre files d'attente QoS et de l'ordonnanceur WRR.
  • aer_rpl_energy.c/h : modèle de consommation énergétique NRE avec suivi de la capacité de batterie.
  • aer_rpl_qlearn.c/h : agent Q-learning pour l'ajustement du poids gamma.
  • aer_rpl_trust.c/h : calcul du score de confiance basé sur l'ETX.
  • rpl-of-aer-plus.c/h : fonction objective personnalisée utilisant la métrique MCS.
  • variants/imacros-*.h : quatre fichiers de macros définissant les variantes du protocole (RPL-MRHOF, RPL-MQoS-style, RPL-AER-style, AER-MQoS).

5. Variantes du protocole

AER-MQoS supporte quatre variantes sélectionnables via des macros de préprocesseur :

VarianteMacroDescription
RPL-MRHOFRPL_MRHOFETX uniquement, sans QoS (baseline)
RPL-MQoS-styleRPL_MQOS_STYLEMétrique composite + QoS sans adaptation
RPL-AER-styleRPL_AER_STYLEMétrique NRE + énergie uniquement
AER-MQoSAER_MQOSVersion complète avec MCS, WRR, Q-learning

6. Publication scientifique

AER-MQoS fait l'objet d'un article scientifique détaillant l'architecture, les algorithmes et les résultats expérimentaux. Le dépôt GitHub (v1.1) contient l'ensemble du code source, les scripts de campagne et les templates de simulation Cooja permettant de reproduire les résultats.

Point clé : AER-MQoS est un protocole de recherche complet, implémenté dans Contiki-NG, validé par simulation avec Cooja, et conçu pour démontrer l'apport du routage contextuel multi-objectifs dans les LLN.

7. Résumé

Dans ce cours introductif, nous avons planté le décor : l'IoT a besoin de différenciation QoS, RPL standard ne la fournit pas, et AER-MQoS répond à ce besoin par une approche multi-objectifs contextuelle. Les prochains cours détailleront chaque composant : classes de trafic, métrique MCS, ordonnancement WRR, Q-learning, modèle d'énergie, confiance et analyse des résultats.
