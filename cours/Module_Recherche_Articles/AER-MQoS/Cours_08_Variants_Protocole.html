Cours 08 — Variants du protocole

Type : Cours théorique — Durée : 1h00
Objectif : Comprendre les 4 variantes d'AER-MQoS, leurs différences architecturales et la méthodologie de comparaison
Prérequis : Cours 01 à 07
Telecharger PDF Telecharger PPTX

1. Principe de la comparaison

Pour évaluer l'apport d'AER-MQoS, le protocole est comparé à 3 variantes plus simples dans des conditions de simulation identiques. Chaque variante ajoute progressivement des fonctionnalités, permettant d'isoler l'impact de chaque innovation. Les 4 variantes partagent la même base de code ; seules les macros de compilation changent.

3. RPL-MRHOF (baseline)

Cette variante implémente le comportement standard de RPL avec la fonction objective MRHOF basée sur ETX. Tous les paquets sont traités de manière identique. Elle sert de référence minimale pour évaluer l'amélioration apportée par les fonctionnalités QoS et multi-objectifs.

Macro associée :

/* imacros-rpl-mrhof.h */
#define RPL_MRHOF
#undef AER_MQOS
#undef RPL_MQOS_STYLE
#undef RPL_AER_STYLE

4. RPL-MQoS-style

Cette variante est inspirée du protocole RPLMQoS. Elle introduit une métrique composite à poids fixes (sans adaptation contextuelle ni Q-learning) et active l'ordonnanceur WRR pour la QoS. Elle permet d'isoler l'apport de la QoS par rapport à la baseline.

Caractéristiques :

  • Métrique composite : NRE + ETX + Trust (poids fixes alpha=0.3, beta=0.35, gamma=0.35)
  • WRR actif avec poids 6:3:2:1
  • Pas d'adaptation contextuelle ni de Q-learning
  • Trust Score basique (sans pénalité d'anomalie)

5. RPL-AER-style

Cette variante correspond au protocole RPL-AER antérieur. Elle utilise le modèle d'énergie NRE comme métrique principale, sans QoS ni trust. Elle permet d'évaluer l'apport du routage énergétique seul.

Caractéristiques :

  • Métrique : NRE uniquement (ou NRE + ETX avec poids forts sur NRE)
  • Pas de WRR (file unique)
  • Pas de Trust Score
  • Optimisé pour l'équilibrage de charge énergétique

6. AER-MQoS (full)

La variante complète active l'ensemble des fonctionnalités : MCS contextuelle avec Q-learning, WRR 6:3:2:1, Trust Score avec détection d'anomalies. C'est la version la plus sophistiquée, censée offrir les meilleures performances globales.

/* imacros-aer-mqos.h */
#define AER_MQOS
#define AER_CONTEXTUAL_WEIGHTS
#define AER_QLEARNING
#define AER_TRUST_ANOMALY_PENALTY

7. Méthodologie de comparaison

La campagne comparative suit ces principes :

  • Mêmes scénarios : tous les variants sont exécutés sur exactement les mêmes fichiers de simulation Cooja (topologie, trafic, durée)
  • Mêmes seeds : les seeds aléatoires sont identiques pour garantir la comparabilité
  • Métriques mesurées : PDR (Packet Delivery Ratio), latence moyenne, consommation énergétique, équité de charge
  • Répétitions : 4 seeds (20260601–20260604) pour la significativité statistique

8. Fichiers de macros variants

Chaque fichier dans variants/ définit les macros appropriées :

Le script build_variant.sh utilise ces fichiers pour compiler chaque variante.

9. Résumé et attentes

L'analyse comparative entre ces 4 variantes permet de quantifier l'apport de chaque fonctionnalité :

  • RPL-MRHOF vs RPL-MQoS-style → apport de la QoS (WRR)
  • RPL-MRHOF vs RPL-AER-style → apport du routage énergétique
  • RPL-MQoS-style vs AER-MQoS → apport de l'adaptation contextuelle et du Q-learning
  • RPL-MRHOF vs AER-MQoS → apport global de l'approche multi-objectifs
