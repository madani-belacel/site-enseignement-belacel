TP 08 — Lancement campagne complète automatisée

Type : Travail pratique — Durée : 2h00 (dont temps de calcul)
Objectif : Lancer la campagne complète multi-seed en utilisant les scripts fournis, automatiser les 16 simulations
Prérequis : Cours 09, TP 02 (firmware compilé), TP 04
Telecharger PDF Telecharger PPTX

1. Examiner les scripts de campagne

Commencez par examiner le répertoire des scripts :

ls -la scripts/
cat scripts/run_campaigns.sh

2. Lancer une campagne simple (1 variante)

Testez d'abord avec une seule variante :

# Usage: run_campaigns.sh  
./scripts/run_campaigns.sh aer_mqos 20260601

Observez la sortie pour vérifier le bon déroulement.

3. Lancer la campagne complète (4 variantes)

Une fois le test réussi, lancez la campagne complète :

./scripts/run_comprehensive_campaign.sh

Ce script lance séquentiellement les 4 variantes avec la seed 20260601.

4. Lancer la campagne multi-seed

Pour des résultats robustes, lancez la campagne multi-seed :

# En arrière-plan pour libérer le terminal
nohup ./scripts/run_multi_seed_campaign.sh > campagne_complete.log 2>&1 &
tail -f campagne_complete.log

Cette campagne lancera 16 simulations (4 variantes × 4 seeds).

5. Structure des résultats

Pendant l'exécution, les logs sont organisés ainsi :

logs/
  aer_mqos/
    20260601.log
    20260602.log
    20260603.log
    20260604.log
  rpl_mrhof/
    20260601.log
    ...
  rpl_mqos_style/
    ...
  rpl_aer_style/
    ...

6. Surveiller l'avancement

Vérifiez l'état des processus et les logs générés :

ps aux | grep cooja
ls -lh logs/*/

7. Vérifier les résultats [METRIC]

Même pendant l'exécution, vous pouvez inspecter les métriques déjà collectées :

grep "\[METRIC\]" logs/aer_mqos/20260601.log

8. En cas d'échec

Si une simulation échoue, consultez les logs d'erreur :

grep -i "error\|failed\|exception" logs/aer_mqos/20260601.log

Les causes fréquentes :

  • Firmware non compilé pour la variante
  • Chemin de simulation incorrect
  • Mémoire insuffisante
