TP 01 — Cloner et explorer AER-MQoS

Type : Travail pratique — Durée : 45 min
Objectif : Cloner le dépôt GitHub AER-MQoS, explorer la structure du code source et examiner les modules principaux
Prérequis : Git, environnement Linux avec les outils de base
Telecharger PDF Telecharger PPTX

1. Cloner le dépôt

Commencez par cloner le dépôt AER-MQoS depuis GitHub :

# Les codes sont déjà présents localement
# Si nécessaire, cloner depuis GitHub:
# git clone https://github.com/madani-belacel/AER-MQoS.git
cd /home/madani/contiki-ng/examples/AER-MQoS

📂 Codes sources disponibles localement : Ces codes sont déjà présents sur votre machine dans le dossier /home/madani/contiki-ng/examples/AER-MQoS. Vous pouvez également les cloner depuis GitHub si nécessaire.

2. Explorer la structure du dépôt

Listez le contenu racine pour comprendre l'organisation :

ls -la

Vous devriez voir :

  • code_source_AER_MQoS/ — répertoire du code source Contiki-NG
  • scripts/ — scripts de campagne et d'analyse
  • simulations/ — fichiers de simulation Cooja (.csc)
  • README.md — documentation du dépôt
  • LICENSE — licence du projet

3. Explorer le code source

Plongez dans la structure du code source Contiki-NG :

cd code_source_AER_MQoS
ls -la

Identifiez les dossiers clés : os/, examples/, arch/. Le code AER-MQoS se trouve principalement dans examples/aer-mqos/ ou un répertoire similaire.

Exercice : Trouvez et listez les fichiers suivants dans l'arborescence :

  • aer_rpl_plus.c et aer_rpl_plus.h
  • aer_qos_queue.c et aer_qos_queue.h
  • aer_rpl_energy.c et aer_rpl_energy.h
  • aer_rpl_qlearn.c et aer_rpl_qlearn.h
  • aer_rpl_trust.c et aer_rpl_trust.h
  • rpl-of-aer-plus.c et rpl-of-aer-plus.h

Utilisez la commande find :

find . -name "aer_*.c" -o -name "aer_*.h" -o -name "rpl-of-aer*"

4. Examiner le module principal aer_rpl_plus.c

Ouvrez le fichier aer_rpl_plus.c avec votre éditeur de texte :

nano chemin/vers/aer_rpl_plus.c

Identifiez :

  • La fonction mcs_calculate() — calcul de la métrique composite
  • La fonction aer_rpl_calculate_contextual_weights() — pondération contextuelle
  • Les constantes ALPHA_DEFAULT, BETA_DEFAULT, GAMMA_DEFAULT
  • Les inclusions d'en-tête et les dépendances

5. Examiner le module QoS

Ouvrez aer_qos_queue.c et examinez :

  • La structure struct aer_qos_queue
  • La fonction aer_qos_wrr_schedule() — algorithme WRR
  • Les poids par défaut (6, 3, 2, 1)
  • La politique de drop en cas de file pleine

6. Examiner le dossier variants/

Repérez les fichiers de macros de variantes :

find . -path "*/variants/*" -name "*.h"

Examinez chaque fichier imacros-*.h pour comprendre :

  • imacros-rpl-mrhof.h — variante RPL-MRHOF (baseline)
  • imacros-rpl-mqos-style.h — variante RPL-MQoS-style
  • imacros-rpl-aer-style.h — variante RPL-AER-style
  • imacros-aer-mqos.h — variante AER-MQoS complète

7. Vérification et rapport

Pour valider le TP, produisez un fichier exploration.txt contenant :

  1. La sortie de git log --oneline -5
  2. La liste des fichiers aer_*.c trouvés
  3. Le contenu du fichier imacros-aer-mqos.h
  4. Les 20 premières lignes de aer_rpl_plus.c

Ce rapport servira de point de départ pour les TP suivants.

8. Questions de réflexion

  1. Combien de fichiers .c le projet AER-MQoS contient-il ?
  2. Quels sont les trois poids contextuels par défaut ?
  3. Quelle est la différence entre les macros des 4 variantes ?
  4. Comment la métrique MCS est-elle structurée dans le code ?
