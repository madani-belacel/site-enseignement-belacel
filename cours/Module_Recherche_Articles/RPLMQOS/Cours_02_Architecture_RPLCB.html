Cours 02 — Architecture et mécanisme CB

Architecture et mécanisme Control Bit
  • Durée : 2h CM
  • Objectif : Comprendre en détail le fonctionnement du mécanisme CB et son intégration dans l'architecture RPL

1. Rappel de l'architecture RPL

RPL construit un DODAG (Destination-Oriented Directed Acyclic Graph) orienté vers un root (puits). Les messages de contrôle sont :

  • DIO (DODAG Information Object) : diffusé par le root et relayé par les nœuds pour annoncer le DODAG
  • DAO (Destination Advertisement Object) : envoyé par les nœuds vers le root pour annoncer leurs préfixes
  • DIS (DODAG Information Solicitation) : sollicitation d'informations DIO

La sélection de parent dans RPL standard utilise l'OF (Objective Function), typiquement MRHOF avec ETX.

2. Principe du Control Bit (CB)

Le Control Bit est un mécanisme qui étend le message DIO en y ajoutant un champ d'un bit. Ce bit code une information binaire qui influence la décision de sélection de parent. Dans RPLCB, le Control Bit est utilisé pour signaler :

  • CB = 0 : état normal — le nœud a une énergie suffisante et n'est pas congestionné
  • CB = 1 : état critique — le nœud a une énergie faible ou est congestionné, il ne doit pas être choisi comme parent

3. Placement du CB dans l'en-tête RPL

Le Control Bit est inséré dans le champ options du message DIO, dans un sous-champ de type RPLCB-option. La structure est la suivante :

Message DIO RPL standard :
  base-header (ICMPv6 type 155, code 1)
    RPLInstanceID
    Version
    Rank
    DODAGID
    Options... (variable)

Message DIO RPLCB :
  base-header (ICMPv6 type 155, code 1)
    RPLInstanceID
    Version
    Rank
    DODAGID
    Options...
      RPLCB-option (Type TBD, Length 1)
        Control Bit (1 bit) + padding (7 bits)

4. Algorithme de sélection de parent avec CB

L'algorithme de sélection de parent dans RPLCB fonctionne en deux phases :

  1. Phase de filtrage : tout nœud candidat avec CB=1 est exclu de la sélection, quel que soit son ETX
  2. Phase de classement : parmi les candidats restants (CB=0), le parent est choisi selon la métrique ETX classique

Cet algorithme simple permet d'éviter les nœuds à faible énergie tout en conservant les bonnes propriétés de RPL standard.

5. Implémentation du CB dans Contiki-NG

Dans Contiki-NG, l'implémentation de RPLCB modifie les fichiers suivants :

  • rpl-dio.c : ajout du champ CB dans l'option DIO
  • rpl-of0.c / rpl-mrhof.c : modification de la fonction de sélection de parent
  • rpl.h : définition de la structure rpl_cb_option

Le code C typique pour lire le CB est :

if (parent->cb_flag == 1) {
  /* Ne pas sélectionner ce parent */
  continue;
}
/* Sinon, procéder à la sélection normale basée sur ETX */

6. Gestion du CB dans les messages DIO et DAO

Le Control Bit est principalement transporté dans les messages DIO (descendants vers ascendants). Lorsqu'un nœud reçoit un DIO avec CB=1 d'un parent potentiel, il l'exclut de sa liste de parents. Le CB peut également être intégré dans les messages DAO pour signaler au root l'état des nœuds, permettant une vue globale de la santé du réseau.

7. Questions de révision

  3. Quels sont les avantages de placer le CB dans l'option DIO plutôt que dans un message séparé ?
  4. Comment le CB pourrait-il être étendu pour transporter plus d'un bit d'information ?
