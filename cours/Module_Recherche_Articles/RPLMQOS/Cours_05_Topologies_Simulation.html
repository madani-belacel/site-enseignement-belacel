Cours 05 — Topologies et scénarios de simulation

Topologies et scénarios de simulation
  • Durée : 2h CM
  • Objectif : Comprendre les configurations de simulation utilisées dans l'évaluation de RPLCB

1. Types de topologies

L'évaluation de RPLCB utilise deux types de topologies :

1.1 Topologie en grille (Grid)

Les nœuds sont disposés régulièrement sur une grille. Par exemple, pour 25 nœuds : grille 5x5. Avantages : contrôle précis de la densité, reproductibilité, analyse de la distance inter-nœuds facile. Inconvénient : moins réaliste.

1.2 Topologie aléatoire (Random)

Les positions des nœuds sont générées aléatoirement dans une zone de simulation. Avantages : plus réaliste, teste la robustesse du protocole. Inconvénient : moins reproductible (nécessite une graine aléatoire fixe).

2. Densité variable

Les simulations sont menées avec différentes densités de nœuds :

Nombre de nœudsTopologie grilleZone (m²)Densité (nœuds/km²)

3. Paramètres de simulation

Les simulations sont configurées avec les paramètres suivants dans Cooja :

ParamètreValeur
Radio mediumUDGM (Unit Disk Graph Model) avec distance
Portée radio100 m (transmission), 150 m (interférence)
Ratio de réceptionTX 100%, RX 80% (avec variations)
Durée de simulation300 s (pour collecte métriques) / jusqu'à épuisement (durée de vie)
Intervalle d'envoi10 s par nœud
Modèle de consommationCC2420 (Tmote Sky / Z1 mote)
Nombre de répétitions10 (pour significativité statistique)

4. Types de trafic

Le trafic généré dans les simulations RPLCB est de type UDP périodique :

  • Chaque nœud client envoie un paquet UDP au serveur (root) à intervalle régulier
  • La charge de trafic varie en fonction du nombre de nœuds
  • Le trafic est CBR (Constant Bit Rate) pour assurer la reproductibilité

5. Fichiers de simulation (CSC)

Les fichiers .csc (Cooja Simulation Configuration) définissent la topologie, les nœuds et les paramètres. Exemple de structure pour sim_25.csc :

<simconf>
  <project EXPORT="discard">
    <title>RPLCB 25 nodes</title>
    <randomseed>12345</randomseed>
    <motedelay_us>1000</motedelay_us>
    <radiomedium>
      org.contikios.cooja.radiomediums.UDGM
    </radiomedium>
    <simduration>300000</simduration> <!-- 300s en ms -->
  </project>
  ...
</simconf>

6. Graines aléatoires et reproductibilité

Pour assurer la reproductibilité des résultats, chaque simulation doit être exécutée avec une graine aléatoire (random seed) identique pour les deux protocoles (RPL et RPLCB). Cela garantit que les différences observées sont dues au protocole et non au hasard. Les 10 répétitions utilisent 10 graines différentes.
