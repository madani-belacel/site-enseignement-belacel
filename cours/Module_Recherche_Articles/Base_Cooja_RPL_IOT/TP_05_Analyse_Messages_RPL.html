TP 05 — Analyse des messages DIO, DAO, DIS

TP 05 — Durée estimée : 2h30 — Prérequis : TP 04

1. Objectifs

  • Observer et différencier les trois types de messages RPL (DIO, DAO, DIS)
  • Comprendre le fonctionnement du Trickle Timer
  • Analyser la création des routes descendantes (DAO)
  • Simuler l'arrivée d'un nouveau nœud (DIS)

2. Configuration de la simulation

  1. Créez une nouvelle simulation nommée Analyse_RPL_Messages
  2. Ajoutez 5 nœuds Sky : 1 racine (udp-server) + 4 clients (udp-client)
  3. Placez-les en topologie linéaire (chaîne) : chaque nœud ne voit que son voisin immédiat
NœudPositionVoisins
1 (racine)(20, 50)Nœud 2
2(40, 50)Nœuds 1, 3
3(60, 50)Nœuds 2, 4
4(80, 50)Nœuds 3, 5
5(100, 50)Nœud 4

3. Analyse des messages DIO

DIO (DAG Information Object) : diffusé par la racine pour annoncer le DODAG.

Dans le panneau Radio messages, activez le filtre ICMPv6 (type 155, code 1 pour DIO).

Observation du Trickle Timer :

  • Au début, les DIO sont très fréquents (toutes les ~100 ms)
  • Après stabilisation, l'intervalle augmente (toutes les ~4 s, puis ~32 s)
  • En cas de changement de topologie, l'intervalle est réinitialisé

Notez les horodatages des DIO reçus par chaque nœud :

Node 2 reçoit DIO de Node 1 à t=1.2s, t=2.4s, t=4.8s, t=9.6s
Node 3 reçoit DIO de Node 2 à t=2.5s, t=5.0s, t=10.0s

4. Analyse des messages DAO

DAO (Destination Advertisement Object) : envoyé par les nœuds pour annoncer leurs adresses et créer des routes descendantes.

  1. Filtrez les paquets ICMPv6 type 155, code 2 (DAO)
  2. Observez que chaque nœud envoie un DAO après avoir rejoint le DODAG
  3. Le DAO contient l'adresse IPv6 du nœud émetteur
  4. Le DAO est transmis de parent en parent jusqu'à la racine

Dans le panneau Radio messages, les DAO apparaissent comme :

[t=3.5s] DAO de Node 2 vers Node 1
[t=4.0s] DAO de Node 3 vers Node 2 (relayé vers Node 1)
[t=4.5s] DAO de Node 4 vers Node 3

5. Analyse des messages DIS

DIS (DAG Information Solicitation) : émis par un nœud qui souhaite rejoindre le réseau.

  1. Ajoutez un 6e nœud (client) à la position (120, 50) après 60 secondes de simulation
  2. Observez son comportement : il émet des DIS pour solliciter un DIO
  3. Le voisin (nœud 5) répond avec un DIO
  4. Le nouveau nœud rejoint le DODAG
[t=60.0s] Node 6: DIS émis
[t=60.1s] Node 5: DIO envoyé en réponse
[t=60.2s] Node 6: Joining DODAG via fe80::5 (rank=1280)

6. Analyse complète avec le Radio Logger

Le plugin Radio Logger de Cooja permet d'exporter les messages capturés dans un fichier.

Activation : Tools → Radio messages → Enable logging → Choisir un fichier de sortie

Exemple de sortie (CSV) :

Time,Source,Destination,Type,Size
1.234,1,2,DIO,78
1.567,2,3,DIO,78
3.456,2,1,DAO,54
60.001,6,5,DIS,28

7. Exercices

  1. Dessinez le DODAG final avec les relations parent-enfant
  2. Calculez le rank de chaque nœud (MinHopRankIncrease=256, supposer ETX=1 pour chaque lien)
  3. Que se passe-t-il si le nœud 3 est désactivé après 100s ? Observez la réorganisation du DODAG
  4. Mesurez l'intervalle moyen entre deux DIO consécutifs pour la racine après stabilisation

8. Livrables

  • Capture d'écran montrant les 5 nœuds et leurs relations parent-enfant
  • Fichier CSV exporté du Radio Logger avec les 3 types de messages
  • Analyse détaillée du Trickle Timer (intervalles observés)
  • Schéma du DODAG avec les ranks
