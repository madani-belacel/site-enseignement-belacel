Cours 05 — Collecte de Métriques dans Cooja

Cours 05 — Durée estimée : 2h — Outils d'analyse et plugins

1. Introduction

Pour évaluer les performances d'un protocole de routage, il est essentiel de collecter des métriques précises. Cooja offre plusieurs plugins et mécanismes pour mesurer la consommation d'énergie, le taux de livraison des paquets (PDR), la latence, et bien d'autres indicateurs.

2. PowerTracker — Analyse de la consommation d'énergie

PowerTracker est un outil intégré à Cooja qui estime la consommation énergétique de chaque nœud en fonction de ses états (CPU, radio TX, radio RX, veille).

Activation : Tools → PowerTracker

Métriques fournies :

MétriqueUnitéDescription
CPU powermWConsommation due au microcontrôleur
Radio TX powermWConsommation en transmission
Radio RX powermWConsommation en réception
LPM powermWConsommation en veille (Low Power Mode)
Total energymJÉnergie totale consommée

Estimation énergétique : Cooja utilise un modèle simple basé sur le temps passé dans chaque état multiplié par la consommation typique du composant. Par exemple, pour un Sky mote :

  • CPU actif : 1.8 mA × 3 V = 5.4 mW
  • Radio TX : 17.4 mA × 3 V = 52.2 mW
  • Radio RX : 18.8 mA × 3 V = 56.4 mW
  • Veille (LPM) : 0.005 mA × 3 V = 0.015 mW

3. Packet Delivery Ratio (PDR)

Le PDR est le rapport entre le nombre de paquets reçus avec succès et le nombre total de paquets envoyés. Il s'exprime en pourcentage.

PDR = (Paquets_reçus / Paquets_envoyés) × 100

Collecte manuelle :

  • Le serveur peut compter les paquets reçus et les identifier par numéro de séquence
  • Le client peut compter les accusés de réception (ACK) ou les réponses
  • Export via Serial.print() vers le panneau Log

4. Mesure de la latence

La latence (ou délai de bout en bout) est le temps écoulé entre l'envoi d'un paquet et sa réception à destination.

Méthode de calcul :

Latence = Temps_réception - Temps_envoi

Dans Contiki-NG, on utilise clock_time() pour horodater les événements :

// Côté client
unsigned long temps_envoi = clock_time();
udp_packet_send(conn, data, len);
printf("ENVOI %lu\n", temps_envoi);

// Côté serveur
unsigned long temps_reception = clock_time();
printf("RECEPTION %lu\n", temps_reception);

5. Collecte via Serial.print()

La fonction printf() dans Contiki-NG envoie les données sur le port série (simulé dans Cooja). Ces messages apparaissent dans le panneau Log.

Format de sortie recommandé :

// Format CSV pour faciliter l'analyse
printf("NODE;%d;TIME;%lu;SEQ;%d;TYPE;%s\n",
       node_id, clock_time(), seqno, "DATA");

Ce format permet d'exporter facilement les logs vers un fichier CSV pour traitement ultérieur.

8. Bonnes pratiques

  • Toujours inclure un timestamp et un identifiant de nœud dans les messages
  • Utiliser des formats structurés (CSV, JSON) pour faciliter l'analyse
  • Exécuter plusieurs simulations avec la même configuration pour des résultats statistiquement significatifs
  • Sauvegarder la configuration de simulation (fichier .csc) pour reproductibilité
  • Documenter les paramètres (durée, nombre de nœuds, topologie, OF)

9. Résumé

La collecte de métriques dans Cooja combine des plugins intégrés (PowerTracker, Radio messages) et des techniques de logging via Serial.print(). Les métriques clés sont la consommation d'énergie, le PDR, la latence et le nombre de messages de contrôle. Une bonne pratique de collecte est essentielle pour l'analyse comparative des protocoles.
