Cours 07 — Modèles de Mobilité et d'Énergie

Cours 07 — Durée estimée : 2h — Simulation avancée

1. Introduction

Dans les réseaux IoT réels, les nœuds peuvent être mobiles (capteurs sur des véhicules, des animaux, des personnes) et leur énergie est limitée. Ce cours présente les modèles disponibles dans Cooja et Contiki-NG pour simuler la mobilité et la gestion d'énergie.

2. Modèles de mobilité dans Cooja

Cooja propose plusieurs modèles de mobilité pour déplacer les nœuds pendant la simulation :

ModèleDescriptionUtilisation
Random WaypointLe nœud choisit une destination aléatoire, s'y déplace à vitesse constante, puis fait une pauseMobilité générale (piétons, véhicules)
Linear mobilityLe nœud se déplace en ligne droite entre deux pointsDéplacement simple
Random directionLe nœud change de direction aléatoirement à intervalles réguliersMouvement brownien
Gauss-MarkovModèle avec corrélation temporelle (mouvement plus réaliste)Mobilité avec inertie

2.1 Random Waypoint

C'est le modèle le plus utilisé. Paramètres configurables :

  • Vitesse : entre min_speed et max_speed (m/s)
  • Temps de pause : entre min_pause et max_pause (secondes)
  • Zone : limitée à la zone de simulation

Dans Cooja : sélectionnez un nœud → "Mote" → "Mobility" → choisissez "RandomWaypoint"

3. Impact de la mobilité sur RPL

La mobilité pose des défis importants pour RPL :

  • Reconstruction du DODAG : quand un nœud se déplace, il doit trouver un nouveau parent
  • Messages de contrôle : le Trickle Timer est réinitialisé, augmentant le trafic
  • Pertes de paquets : les liens se rompent lorsque les nœuds s'éloignent
  • Latence : les routes changent fréquemment, augmentant la latence

4. Modèles d'énergie dans Contiki-NG

Contiki-NG intègre un modèle d'estimation énergétique basé sur les états des composants :

ÉtatConsommation (Sky mote)Description
CPU actif5.4 mWMicrocontrôleur en fonctionnement
Radio TX52.2 mWTransmission radio
Radio RX56.4 mWÉcoute radio
LPM (veille)0.015 mWMode basse consommation

5. Duty-Cycling

Le duty-cycling est une technique qui alterne périodes d'éveil (actif) et de sommeil (veille) pour économiser l'énergie. Dans Contiki-NG, il est implémenté par le protocole MAC ContikiMAC.

Principe :

  • Le nœud écoute le canal radio pendant ~0.5% du temps (duty cycle = 0.5%)
  • Entre les écoutes, le nœud dort (LPM)
  • L'émetteur envoie des "strobes" jusqu'à ce que le récepteur se réveille

Impact :

  • Économie d'énergie significative (×10 à ×100)
  • Augmentation de la latence (attente du réveil du destinataire)
  • Réduction du débit effectif

Configuration du duty cycle :

#define NETSTACK_CONF_MAC      csma_driver
#define NETSTACK_CONF_MAC      nullmac_driver  # Pas de duty-cycling
#define NETSTACK_CONF_MAC      contikimac_driver  # Duty-cycling activé

6. Simulation de batterie

Contiki-NG permet de simuler une batterie avec capacité limitée :

// Dans project-conf.h
#define ENERGY_CONF_ON 1

// Dans le code
#include "sys/energest.h"

unsigned long cpu_time = energest_type_time(ENERGEST_TYPE_CPU);
unsigned long radio_tx = energest_type_time(ENERGEST_TYPE_TRANSMIT);
unsigned long radio_rx = energest_type_time(ENERGEST_TYPE_LISTEN);
unsigned long lpm_time = energest_type_time(ENERGEST_TYPE_LPM);

7. Récolte d'énergie solaire

La récolte d'énergie (energy harvesting) permet aux nœuds de recharger leur batterie à partir de sources externes (solaire, vibration, thermique). Dans Cooja, on peut simuler ce comportement.

Modèle solaire simplifié :

#define SOLAR_POWER_MW 10  // 10 mW reçus du panneau solaire
#define BATTERY_CAPACITY_mAh 2000
#define VOLTAGE 3.0

// Énergie récoltée par intervalle
energie_harvested = SOLAR_POWER_MW * intervalle;

La récolte d'énergie peut prolonger significativement la durée de vie des nœuds, voire permettre un fonctionnement perpétuel si l'énergie récoltée > énergie consommée.

8. Configuration de la mobilité dans Cooja

Pour configurer la mobilité dans Cooja :

  1. Sélectionnez un nœud dans la vue Network
  2. Onglet "Mote" → section "Mobility"
  3. Choisissez le type : "RandomWaypoint"
  4. Paramètres : min_speed=0.5, max_speed=2.0, min_pause=5, max_pause=30
  5. La position du nœud sera mise à jour automatiquement

9. Résumé

Les modèles de mobilité (Random Waypoint, linéaire) et d'énergie (duty-cycling, batterie, récolte solaire) sont essentiels pour simuler des scénarios IoT réalistes. La mobilité affecte les performances de RPL (reconstruction du DODAG, latence, PDR), tandis que l'énergie détermine la durée de vie du réseau.
