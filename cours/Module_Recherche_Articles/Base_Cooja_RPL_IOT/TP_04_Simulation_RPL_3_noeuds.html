TP 04 — Simulation RPL de base avec 3 nœuds

TP 04 — Durée estimée : 2h — Prérequis : Cours 03, TP 03

1. Objectifs

  • Utiliser l'exemple rpl-udp fourni avec Contiki-NG
  • Créer une topologie à 3 nœuds (1 racine DAG + 2 nœuds feuilles)
  • Observer la formation du DODAG et les échanges de messages DIO
  • Comprendre le processus de sélection du parent
  • Visualiser le routage RPL dans Cooja

2. Présentation de l'exemple rpl-udp

Contiki-NG fournit un exemple complet de communication UDP avec RPL dans le répertoire :

$CONTIKI/examples/rpl-udp/

Il contient :

  • udp-client.c : nœud client qui envoie des paquets UDP vers la racine
  • udp-server.c : nœud racine (sink) qui reçoit les paquets
  • Makefile : configuration de compilation
  • project-conf.h : configuration RPL avec MRHOF

3. Préparation de l'environnement

Copiez l'exemple dans votre espace de travail :

cp -r $CONTIKI/examples/rpl-udp ~/mon_rpl_udp
cd ~/mon_rpl_udp

Compilez les firmwares :

make TARGET=cooja

Les fichiers .cooja sont générés : udp-server.cooja et udp-client.cooja.

4. Création de la simulation

  1. Lancez Cooja : cd $CONTIKI/tools/cooja && make cooja
  2. Créez une nouvelle simulation : File → New simulation
  3. Nom : RPL_3_Noeuds, Durée : 300 secondes
  4. Ajoutez les nœuds dans cet ordre :
NœudFirmwareRôlePosition
1udp-server.coojaRacine DODAG (sink)(50, 50)
2udp-client.coojaNœud feuille 1(30, 30)
3udp-client.coojaNœud feuille 2(70, 30)

Assurez-vous que les nœuds sont à portée radio les uns des autres (distance < 100 m).

5. Observation de la formation du DODAG

  1. Ouvrez le panneau Log (View → Log)
  2. Ouvrez le panneau Radio messages (Tools → Radio messages)
  3. Démarrez la simulation

Dans le panneau Log, vous observerez :

[ID:1] Serveur RPL démarré, DODAG root
[ID:2] Client RPL démarré
[ID:3] Client RPL démarré
[ID:2] Joining DODAG via fe80::1 (rank=512)
[ID:3] Joining DODAG via fe80::1 (rank=512)
[ID:2] Envoi paquet à 2001:db8::1
[ID:1] Reçu paquet de fe80::2: data=Hello

6. Analyse des messages DIO

Dans le panneau Radio messages, filtrez pour afficher uniquement les paquets ICMPv6 (type 155 pour RPL). Observez :

  • Le nœud 1 (racine) émet des DIO périodiquement (trickle timer)
  • Après réception du premier DIO, les nœuds 2 et 3 rejoignent le DODAG
  • Les nœuds 2 et 3 émettent à leur tour des DIO (relais)
  • La fréquence des DIO diminue avec le temps (trickle timer)

7. Visualisation du DODAG

Cooja propose un outil de visualisation du DODAG :

  1. Tools → DODAG viewer (si disponible) ou utilisez la vue Network
  2. Dans la vue Network, les flèches indiquent les relations parent-enfant
  3. La racine (nœud 1) est généralement en vert

8. Comprendre la sélection du parent

Analysez le processus de sélection du parent :

  1. Le nœud 2 reçoit un DIO du nœud 1 (rank=256, ETX=1.0)
  2. Il calcule son rank : rank = 256 + (1.0 × 256) = 512
  3. Il sélectionne le nœud 1 comme parent préféré
  4. Le nœud 3 fait de même avec le nœud 1
  5. Si les nœuds 2 et 3 sont hors de portée l'un de l'autre, ils ne peuvent pas être parents

9. Exercices

  1. Modifiez la topologie : placez les nœuds 2 et 3 de sorte qu'ils communiquent via le nœud 1 uniquement (topologie en étoile)
  2. Ajoutez un 4e nœud qui ne peut communiquer qu'avec le nœud 2 (topologie en chaîne). Observez son rank
  3. Changez la fonction objectif dans project-conf.h de MRHOF vers OF0, recompilez, et comparez le comportement

10. Livrables

  • Capture d'écran de la simulation montrant les 3 nœuds et le panneau Log
  • Relevé des messages DIO avec leurs intervalles
  • Analyse du rank de chaque nœud
