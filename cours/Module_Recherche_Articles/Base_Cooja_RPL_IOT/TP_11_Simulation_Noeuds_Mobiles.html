TP 11 — Simulation avec Nœuds Mobiles

TP 11 — Durée estimée : 2h30 — Prérequis : Cours 07, TP 07

1. Objectifs

  • Ajouter la mobilité aux nœuds dans Cooja (Random Waypoint)
  • Observer la reconstruction du DODAG lorsqu'un nœud se déplace
  • Analyser l'impact de la mobilité sur le PDR et la latence
  • Comparer les performances avec un scénario statique

2. Configuration de la simulation

  1. Créez une simulation nommée Simulation_Mobile
  2. Ajoutez 1 racine fixe (udp-server) à la position (50, 50)
  3. Ajoutez 5 clients mobiles (udp-client avec horodatage)
  4. Zone de simulation : 200 m × 200 m
  5. Portée radio : 60 mètres
  6. Durée : 600 secondes

3. Configuration de la mobilité

Pour chaque nœud mobile :

  1. Sélectionnez le nœud → onglet "Mote"
  2. Dans "Mobility", choisissez "RandomWaypoint"
  3. Paramètres :
Vitesse min : 0.5 m/s
Vitesse max : 1.5 m/s
Pause min : 5 s
Pause max : 20 s
Zone X : [0, 200]
Zone Y : [0, 200]

4. Observation de la reconstruction du DODAG

Activez le panneau Log et le Radio Messages. Observez :

  • Au début, tous les nœuds rejoignent le DODAG via les parents les plus proches
  • Quand un nœud se déplace, il peut perdre la connexion avec son parent
  • Il émet alors des DIS pour trouver un nouveau parent
  • Le Trickle Timer est réinitialisé, augmentant les DIO
  • Le nœud se rattache à un nouveau parent

Log typique :

[t=120s] Node 3: Lien perdu avec parent fe80::1 (ETX=8.5)
[t=121s] Node 3: DIS émis
[t=121s] Node 2: DIO reçu par Node 3
[t=122s] Node 3: Nouveau parent: fe80::2 (rank=768)
[t=125s] Node 3: Envoi paquet via nouveau parent

6. Analyse des résultats

Utilisez les scripts du TP 08 pour analyser les logs des deux simulations :

python3 calcul_pdr.py logs_statique.csv
python3 calcul_pdr.py logs_mobile.csv
python3 analyse_latence.py logs_statique.csv
python3 analyse_latence.py logs_mobile.csv

Comparez les résultats et tirez des conclusions sur l'impact de la mobilité.

7. Visualisation des trajectoires

Dans Cooja, la vue Network montre les déplacements des nœuds en temps réel. Vous pouvez exporter les trajectoires :

  1. Tools → Radio messages → Enable logging (inclut les positions)
  2. Analysez les déplacements avec Python :
#!/usr/bin/env python3
import matplotlib.pyplot as plt

# Extraire les positions (format: POS;node;x;y;time)
positions = {1: [], 2: [], 3: []}
with open("logs_mobile.csv") as f:
    for line in f:
        if line.startswith("POS"):
            parts = line.strip().split(';')
            node, x, y = int(parts[1]), float(parts[2]), float(parts[3])
            positions[node].append((x, y))

for node, coords in positions.items():
    xs = [c[0] for c in coords]
    ys = [c[1] for c in coords]
    plt.plot(xs, ys, '-o', label=f'Node {node}')

plt.legend()
plt.savefig('trajectoires.png')

  4. Proposez une amélioration de RPL pour mieux gérer la mobilité
