TP 07 — Mesure du PDR, Latence et Consommation d'Énergie

TP 07 — Durée estimée : 3h — Prérequis : Cours 05, TP 06

1. Objectifs

  • Configurer le plugin PowerTracker pour mesurer l'énergie
  • Ajouter des horodatages dans le code pour le calcul de la latence
  • Collecter les statistiques de livraison des paquets (PDR)
  • Exécuter une simulation longue (600s) et exporter les données

2. Configuration de la simulation

  1. Créez une simulation nommée Mesures_Performances
  2. Topologie : grille 4×4 (16 nœuds), racine au centre
  3. Portée radio : 50 mètres, interference range : 100 mètres
  4. Durée : 600 secondes (10 minutes) — onglet "Simulation" → "Duration"
  5. Firmware : utilisez l'exemple rpl-udp modifié avec horodatage

3. Modification du firmware pour la latence

Ajoutez un numéro de séquence et un horodatage dans udp-client.c :

static int seqno = 0;

// Dans la boucle d'envoi :
seqno++;
clock_time_t t = clock_time();
printf("TX;%d;%d;%lu\n", node_id, seqno, (unsigned long)t);
snprintf(buf, sizeof(buf), "PING %d %lu", seqno, (unsigned long)t);
udp_packet_send(client_conn, buf, strlen(buf));

Dans udp-server.c, ajoutez la réception avec timestamp :

clock_time_t t_rx = clock_time();
printf("RX;%d;%s;%lu\n", node_id, (char*)uip_appdata, (unsigned long)t_rx);

4. Activation de PowerTracker

  1. Menu Tools → PowerTracker
  2. La fenêtre PowerTracker s'ouvre avec la liste des nœuds
  3. Cliquez sur "Start logging" pour commencer l'enregistrement
  4. Les métriques (CPU, Radio TX, Radio RX, LPM) s'affichent en temps réel
  5. À la fin de la simulation, cliquez sur "Export to CSV"

5. Collecte des logs

Pour enregistrer tous les messages dans un fichier :

  1. Tools → Mote output → "Enable logging"
  2. Choisissez un fichier de sortie : logs_simulation.csv
  3. Le format des logs inclut : timestamp Cooja, ID du nœud, message

6. Calcul du PDR

Après la simulation, extrayez les informations des logs :

# Nombre de paquets envoyés (TX)
grep "TX" logs_simulation.csv | wc -l

# Nombre de paquets reçus par la racine (RX)
grep "RX" logs_simulation.csv | wc -l

# PDR global
PDR = (Nombre_RX / Nombre_TX) × 100

Vous pouvez aussi calculer le PDR par nœud :

grep "TX;2;" logs_simulation.csv | wc -l   # Envois du nœud 2
grep "RX;2;" logs_simulation.csv | wc -l   # Réceptions du nœud 2

7. Calcul de la latence moyenne

Écrivez un script pour calculer la latence à partir des paires TX/RX :

# Pour chaque paire (seqno), la latence = t_rx - t_tx
# Exemple avec awk :
awk -F';' '
/TX/ { tx[$3] = $4 }
/RX/ {
  split($3, arr, " ");
  seq = arr[2];
  if (seq in tx) {
    lat = $4 - tx[seq];
    print seq, lat;
  }
}' logs_simulation.csv

8. Export des données d'énergie

Le fichier exporté par PowerTracker contient pour chaque nœud :

Time,Node,CPU(mJ),RadioTX(mJ),RadioRX(mJ),LPM(mJ),Total(mJ)
60,1,12.3,45.6,78.9,0.1,136.9
60,2,15.7,52.3,65.4,0.2,133.6
...

Calculez ensuite :

  • Énergie totale moyenne par nœud
  • Énergie de communication (RadioTX + RadioRX)
  • Pourcentage d'énergie dans chaque état

9. Exercices

  1. Comparez le PDR des nœuds proches de la racine vs les nœuds éloignés
  2. Calculez la latence moyenne et la latence maximale
  3. Quel est le ratio énergie de communication / énergie totale ?
  4. Refaites l'expérience avec OF0 et comparez les résultats avec MRHOF

10. Livrables

  • Fichier CSV des logs de simulation
  • Fichier CSV exporté de PowerTracker
  • Tableau récapitulatif : PDR, latence moyenne, latence max, énergie totale
  • Analyse comparative OF0 vs MRHOF
