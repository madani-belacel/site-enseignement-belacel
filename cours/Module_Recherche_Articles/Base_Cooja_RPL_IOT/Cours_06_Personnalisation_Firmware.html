Cours 06 — Personnalisation du Firmware Contiki-NG

Cours 06 — Durée estimée : 2h — Structure et configuration des projets

1. Structure d'un projet Contiki-NG

Un projet Contiki-NG typique contient les fichiers suivants :

mon_projet/
├── Makefile          # Configuration de la compilation
├── project-conf.h    # Configuration du projet (constantes, activation modules)
├── mon_app.c         # Code source principal
├── mon_app.h         # Header optionnel
└── README.md         # Documentation

2. Structure de l'arborescence Contiki-NG

Le répertoire racine de Contiki-NG est organisé ainsi :

$CONTIKI/
├── apps/           # Applications prêtes à l'emploi (CoAP, MQTT, Shell)
├── os/             # Système d'exploitation
│   ├── net/        # Pile réseau (MAC, IPv6, RPL, UDP, TCP)
│   ├── sys/        # Sytème (processus, timers, ETIMER)
│   ├── dev/        # Drivers (capteurs, radio, LED)
│   └── lib/        # Bibliothèques utilitaires
├── arch/           # Architecture spécifiques (Sky, Zoul, CC2538)
├── examples/       # Exemples de projets
├── tools/          # Outils (Cooja, tunslip, serialdump)
└── Makefile.include # Règles de compilation communes

3. Le Makefile

Le Makefile est essentiel pour la compilation. Voici sa structure typique :

CONTIKI = ../..   # Chemin vers la racine Contiki-NG

# Liste des fichiers source à compiler
all: mon_app.cooja

# Inclure les modules optionnels
MODULES += os/net/app-layer/coap
MODULES += os/services/shell

# Inclure les règles de compilation Contiki-NG
include $(CONTIKI)/Makefile.include

Variables Makefile importantes :

VariableDescription
CONTIKIChemin vers la racine Contiki-NG
TARGETCible de compilation (cooja, sky, zoul)
MODULESModules supplémentaires à inclure
APPSApplications à inclure
CFLAGSOptions du compilateur C
LDFLAGSOptions du linker

4. project-conf.h — Configuration du projet

Ce fichier permet de configurer les paramètres du système et du réseau sans modifier le code source de Contiki-NG :

#ifndef PROJECT_CONF_H_
#define PROJECT_CONF_H_

/* === Configuration réseau === */
#define NETSTACK_CONF_WITH_IPV6       1
#define UIP_CONF_IPV6                 1
#define UIP_CONF_IPV6_RPL             1

/* === Configuration RPL === */
#define RPL_CONF_OF                   rpl_mrhof
#define RPL_CONF_MINHOPRANKINC        256
#define RPL_CONF_MAX_ROUTING_ENTRIES  20

/* === Configuration radio === */
#define IEEE802154_CONF_PANID         0xABCD

/* === Communication série === */
#define LOG_CONF_LEVEL_RPL            LOG_LEVEL_WARN
#define LOG_CONF_LEVEL_TCPIP          LOG_LEVEL_INFO

#endif /* PROJECT_CONF_H_ */

5. Les processus Contiki-NG

Les applications Contiki-NG sont structurées autour des processus. Un processus est une unité d'exécution qui réagit aux événements :

PROCESS(mon_processus, "Mon processus");
AUTOSTART_PROCESSES(&mon_processus);

PROCESS_THREAD(mon_processus, ev, data)
{
  static struct etimer et;
  PROCESS_BEGIN();

  etimer_set(&et, CLOCK_SECOND * 5);

  while(1) {
    PROCESS_YIELD();
    if(ev == PROCESS_EVENT_TIMER) {
      printf("Timer expiré !\n");
      etimer_restart(&et);
    }
  }

  PROCESS_END();
}

6. Ajout de modules personnalisés

Pour ajouter un module personnalisé, créez un répertoire dans apps/ ou dans votre projet :

mon_projet/
├── Makefile
├── project-conf.h
├── mon_app.c
└── lib/
    ├── mon_module.c
    └── mon_module.h

Dans le Makefile :

MODULES += lib

7. Modification du processus de build

Pour personnaliser la compilation, vous pouvez :

  • Ajouter des flags compilateur : CFLAGS += -DMON_FLAG
  • Changer l'optimisation : CFLAGS += -Os (taille) ou -O2 (vitesse)
  • Exclure des modules : MODULES += os/services/shell
  • Utiliser des bibliothèques externes via LDFLAGS

8. Débogage et logs

Contiki-NG utilise un système de logs configurable :

#define LOG_CONF_LEVEL_APP LOG_LEVEL_INFO
LOG_INFO("Valeur: %d\n", valeur);

Niveaux de log : LOG_LEVEL_NONE, LOG_LEVEL_ERR, LOG_LEVEL_WARN, LOG_LEVEL_INFO, LOG_LEVEL_DBG.

9. Résumé

La personnalisation du firmware Contiki-NG passe par la maîtrise de la structure du projet (Makefile, project-conf.h), la compréhension des processus, et la capacité à ajouter des modules. Le système de logs facilite le débogage. Ces notions sont essentielles pour adapter les protocoles de recherche.
