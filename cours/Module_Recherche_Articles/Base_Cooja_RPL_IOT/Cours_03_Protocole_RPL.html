Cours 03 — Le Protocole RPL : Principes Fondamentaux

Cours 03 — Durée estimée : 2h30 — Référence : RFC 6550

1. Introduction à RPL

RPL (Routing Protocol for Low-Power and Lossy Networks) est un protocole de routage pour réseaux LLN (Low-Power and Lossy Networks), standardisé par l'IETF dans la RFC 6550. Il est conçu pour les réseaux IoT où les nœuds ont des ressources limitées et les liens sont souvent instables.

RPL construit un graphe acyclique orienté (DODAG) qui permet d'acheminer les paquets de manière efficace tout en minimisant la surcharge de contrôle.

2. Le DODAG (Destination Oriented Directed Acyclic Graph)

Un DODAG est un graphe orienté sans cycle qui part d'une racine (sink) et s'étend vers les nœuds feuilles. Chaque nœud a un ou plusieurs parents vers la racine.

Propriétés du DODAG :

  • Orientation : les arêtes pointent toujours vers la racine (routes montantes)
  • Acyclique : pas de boucles de routage
  • Destination-oriented : la racine est la destination principale
  • Instances : plusieurs DODAG peuvent coexister avec différentes métriques

3. Le Rank

Le rank est un nombre entier qui représente la distance logique d'un nœud par rapport à la racine du DODAG. La racine a un rank de 1 (ou 256 selon l'échelle). Les nœuds enfants ont un rank strictement supérieur à celui de leurs parents.

Règles :

  • Le rank doit augmenter en s'éloignant de la racine
  • Un nœud ne peut pas être parent d'un nœud de rank supérieur ou égal
  • Le rank est calculé selon la fonction objectif (OF)
  • Il peut être basé sur le nombre de sauts, l'ETX, ou d'autres métriques

4. Messages de contrôle RPL

RPL utilise trois types de messages ICMPv6 pour construire et maintenir le DODAG :

MessageSignificationRôleDirection
DIODAG Information ObjectAnnonce le DODAG, contient la configurationDe la racine vers les feuilles
DAODestination Advertisement ObjectEnregistre les routes descendantsDes feuilles vers la racine
DISDAG Information SolicitationDemande un DIO à un voisinD'un nouveau nœud vers le réseau

4.1 DIO (DAG Information Object)

Les DIO sont émis périodiquement par la racine et relayés par les nœuds. Ils contiennent :

  • RPLInstanceID — identifiant de l'instance RPL
  • DODAGID — identifiant du DODAG
  • Version — numéro de version (incrémenté lors des reconstructions)
  • Ground — indique si la racine est connectée à Internet
  • Rank du nœud émetteur
  • Objective Function (OF) utilisée

Le Trickle Timer contrôle la fréquence d'émission des DIO. Après une mise à jour, le timer est réinitialisé (période courte) puis augmente exponentiellement jusqu'à un maximum (période longue).

4.2 DAO (Destination Advertisement Object)

Les DAO sont envoyés des nœuds vers la racine pour annoncer :

  • Le préfixe du sous-réseau (si le nœud agit comme routeur)
  • L'adresse du nœud lui-même (routage descendant)

Le DAO peut être émis de manière piggyback (avec un DIO) ou autonome. Le mode de fonctionnement (stockage ou non-stockage) détermine où sont stockées les tables de routage.

4.3 DIS (DAG Information Solicitation)

Un nœud qui souhaite rejoindre le DODAG envoie un DIS pour solliciter un DIO de ses voisins. C'est la phase d'initialisation du nœud dans le réseau RPL.

5. Fonctions Objectifs (Objective Functions)

La fonction objectif (OF) définit comment :

  • Calculer le rank d'un nœud
  • Sélectionner le(s) parent(s) préféré(s)
  • Évaluer la qualité des routes

Les deux fonctions objectifs principales sont :

  • OF0 (RFC 6552) : minimise le nombre de sauts (rank = 256 × hops)
  • MRHOF (RFC 6719) : minimise l'ETX (Expected Transmission Count)

6. Instances RPL et DODAG ID

Un réseau RPL peut avoir plusieurs instances simultanées, chacune identifiée par un RPLInstanceID. Chaque instance peut avoir un ou plusieurs DODAG. Cela permet :

  • D'utiliser différentes métriques (ex: OF0 pour instance 1, MRHOF pour instance 2)
  • D'isoler le trafic de différents types (ex: données urgentes vs. données normales)
  • D'avoir plusieurs racines dans le même réseau

7. Routage montant et descendant

Routage montant (upward) : les paquets vont des nœuds vers la racine en suivant le DODAG (utilisation des parents). C'est le routage principal dans RPL.

Routage descendant (downward) : les paquets vont de la racine vers les nœuds. En mode stockage, chaque routeur stocke une table de routage pour ses enfants. En mode non-stockage, seule la racine stocke les routes (source routing).

8. Résumé

RPL est le protocole de routage standard pour l'IoT. Il construit un DODAG orienté vers la racine, utilise le rank pour éviter les boucles, et emploie trois types de messages (DIO, DAO, DIS) contrôlés par Trickle Timer. Les fonctions objectifs (OF0, MRHOF) définissent les métriques de routage. Ce cours prépare les TP de simulation RPL sous Cooja.
