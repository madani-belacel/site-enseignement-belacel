Objectifs pédagogiques

À l'issue de cette séance de TD, l'étudiant est capable de : - Expliquer le rôle du système d'exploitation et de ses composants (noyau, pilotes) - Décrire les états d'un processus et leur cycle de vie - Naviguer dans une arborescence de fichiers et construire des chemins absolus - Exécuter des commandes PowerShell pour manipuler fichiers et dossiers - Distinguer les privilèges noyau/mode utilisateur via les appels système

Contexte pédagogique — Scénario enseignant

Vous êtes enseignant et devez initier vos étudiants au rôle central du système d'exploitation. Ce TD explore les couches internes d'un OS (noyau, pilotes, syscalls), le cycle de vie des processus, l'arborescence des fichiers et la ligne de commande PowerShell. Utilisez l'analogie du chef d'orchestre (OS) qui dirige les musiciens (processus) et distribue les partitions (ressources).

Exercice 1 — Rôle de l'OS (15 min)

Scénario enseignant : L'objectif est de faire comprendre que l'OS est un intermédiaire obligatoire entre les applications et le matériel. Sans OS, chaque application devrait gérer elle-même les pilotes, l'ordonnancement, etc.

✓ Question de base (6 min)

Énoncé : Associer chaque fonction à sa description.

Fonction Description
Gestion des processus A. Organiser les fichiers en arborescence
Gestion de la mémoire B. Traduire les appels système vers le matériel
Gestion des fichiers C. Allouer la RAM aux applications
Noyau D. Ordonnancer l'exécution des programmes
Pilote (driver) E. Interface entre l'OS et un périphérique

Corrigé :

Fonction Description
Gestion des processus D — Ordonnancer l'exécution des programmes
Gestion de la mémoire C — Allouer la RAM aux applications
Gestion des fichiers A — Organiser les fichiers en arborescence
Noyau B (partiellement) — Cœur du système, gère tout
Pilote (driver) E — Interface entre l'OS et un périphérique

★ Question intermédiaire (5 min)

Énoncé : Classer les actions suivantes selon qu'elles relèvent du noyau (mode noyau) ou d'une application (mode utilisateur) :

  1. Un calcul dans un tableur Excel
  2. L'écriture d'un fichier sur le disque dur
  3. L'affichage d'une image à l'écran (via le pilote graphique)
  4. La lecture d'une touche du clavier
  5. L'ordonnancement du prochain processus à exécuter
  6. La navigation dans un navigateur web

Corrigé :

Action Mode
Calcul dans Excel Utilisateur (purement applicatif)
Écriture sur disque Noyau (via syscall write)
Affichage via pilote graphique Noyau (le pilote est dans l'OS)
Lecture clavier Noyau (interruption matérielle gérée par l'OS)
Ordonnancement Noyau (c'est le scheduler)
Navigation web Utilisateur (le navigateur fait des syscalls mais reste en mode utilisateur)

★★ Question avancée (4 min)

Énoncé : Lister 3 différences entre un noyau monolithique (Linux) et un noyau hybride (Windows). Donner un avantage et un inconvénient pour chaque approche.

Corrigé :

Caractéristique Monolithique (Linux) Hybride (Windows)
Architecture Tout le noyau dans un seul espace d'adressage Noyau minimal + services en mode utilisateur
Performance Meilleure (moins de changements de contexte) Légèrement moins bonne (IPC entre modules)
Stabilité / Sécurité Moins stable (un pilote crash tout le noyau) Plus stable (un pilote crash peut être isolé)
Modularité Chargeable via modules (.ko) Services séparés

Avantage monolithique : performances élevées. Inconvénient : risque de planter tout le système.

Avantage hybride : meilleure isolation (un pilote qui plante ne bloque pas tout). Inconvénient : surcoût de communication entre les couches.

Exercice 2 — Processus et états (15 min)

Scénario enseignant : Le diagramme d'états d'un processus est central en OS. Faites-le reproduire de mémoire par les étudiants (d'abord avec les 3 états, puis les transitions). Utilisez un jeu de rôle : 3 chaises = Prêt, Élu, Bloqué ; des étudiants mimant les transitions.

✓ Question de base (5 min)

Énoncé : Un processus passe par 3 états : Prêt, Élu, Bloqué. Associer chaque situation à l'état correspondant.

  1. Un processus attend que l'utilisateur clique sur un bouton.
  2. Le CPU exécute les instructions du processus.
  3. Le processus est dans la file d'attente, prêt à être exécuté.
  4. Un processus lit un fichier sur le disque dur.
  5. Le système d'exploitation vient de charger le processus en mémoire.

Corrigé : 1. Bloqué — attente d'une interaction utilisateur (E/S) 2. Élu — le CPU exécute activement le processus 3. Prêt — en attente dans la file d'ordonnancement 4. Bloqué — attente de la fin de l'opération disque (E/S bloquante) 5. Prêt — le processus est chargé mais pas encore élu

★ Question intermédiaire (5 min)

Énoncé : On observe un système avec 3 processus (P1, P2, P3). L'ordonnanceur utilise le Round Robin avec un quantum de 2 unités de temps. Compléter le diagramme de Gantt sachant que les processus arrivent tous à t = 0 et qu'aucun ne fait d'E/S :

Temps 0-2 2-4 4-6 6-8 8-10 10-12 12-14 14-16
CPU ? ? ? ? ? ? ? ?

Corrigé :

Round Robin : P1 → P2 → P3 → P1 → P2 → P3 → P1 → ...

Temps 0-2 2-4 4-6 6-8 8-10 10-12 12-14 14-16
CPU P1 P2 P3 P1 P2 P3 P1 P2

Explication : Chaque processus reçoit 2 unités de temps. Le cycle P1→P2→P3 se répète. L'ordre d'arrivée détermine l'ordre initial.

★★ Question avancée (5 min)

Énoncé : On reprend le même système mais P2 fait une E/S bloquante au temps t=3 (durée : 3 unités). Décrire l'état de chaque processus aux instants t=0, t=2, t=4, t=6, t=8.

Corrigé :

Temps P1 P2 P3 Exécuté par CPU
t=0 Prêt Prêt Prêt —
t=2 Élu (0-2) Prêt Prêt P1
t=3 Prêt Élu (2-3) puis Bloqué Prêt P2 (puis E/S)
t=4 Prêt Bloqué Élu (3-4, fin de quantum) P3
t=6 Élu (4-6) Bloqué Prêt P1
t=8 Prêt Prêt (E/S terminée à t=6, repasse en file) Élu (6-8) P3

Observation : Quand P2 est bloqué, l'ordre Round Robin continue entre P1 et P3 jusqu'au retour de P2.

★★ Question avancée (5 min)

Énoncé : Écrire un script PowerShell qui parcourt récursivement un dossier donné en argument et affiche pour chaque fichier :

  • Son nom
  • Sa taille en Ko
  • Sa date de dernière modification
  • L'extension

Trier les résultats par taille décroissante et n'afficher que les 10 plus gros fichiers.

Corrigé :

param($Dossier = ".")
Get-ChildItem -Path $Dossier -Recurse -File | 
    Select-Object Name, @{N="TailleKo";E={[math]::Round($_.Length/1KB, 2)}}, 
                  LastWriteTime, Extension |
    Sort-Object -Property TailleKo -Descending |
    Select-Object -First 10

Explication : - param($Dossier = ".") : paramètre avec valeur par défaut (dossier courant) - -Recurse -File : parcourt récursivement, ne garde que les fichiers - Select-Object avec @{...} : crée une propriété calculée TailleKo - [math]::Round(...) : arrondit à 2 décimales - Sort-Object -Descending : tri décroissant - -First 10 : top 10

Exercice 5 — Syscalls et permissions (15 min)

Scénario enseignant : La distinction mode utilisateur / mode noyau est fondamentale pour la sécurité et la stabilité du système. Un programme applicatif ne peut rien faire sans passer par l'OS.

✓ Question de base (5 min)

Énoncé : Vrai ou Faux ? Justifier.

  1. Un logiciel applicatif peut accéder directement au disque dur sans passer par l'OS.
  2. Le noyau Linux et le noyau Windows sont identiques.
  3. Un appel système (syscall) permet à une application de demander un service au noyau.
  4. La mémoire virtuelle permet à un processus d'utiliser plus de mémoire que la RAM disponible.
  5. Un processus bloqué consomme du temps CPU.

Corrigé :

  1. Faux — toute opération matérielle passe obligatoirement par l'OS (sécurité, abstraction, isolation). L'accès direct serait un trou de sécurité critique.
  2. Faux — architectures différentes (Linux : monolithique avec modules chargeables ; Windows : hybride avec micro-noyau + services). Les API (syscalls) sont également différentes.
  3. Vrai — c'est le mécanisme standard. L'application exécute une instruction spéciale (ex: int 0x80 ou syscall) qui passe en mode noyau.
  4. Vrai — via le swap (espace d'échange sur disque) et la pagination. Les pages rarement utilisées sont déplacées sur le disque pour libérer de la RAM.
  5. Faux — un processus bloqué est en attente d'une ressource (E/S, clavier, etc.). Il n'est pas dans la file des prêts et ne reçoit pas de temps CPU.

★ Question intermédiaire (5 min)

Énoncé : Tableau de permissions. Soit le fichier script.sh avec les permissions -rwxr-xr-- :

  1. Que peut faire le propriétaire ?
  2. Que peut faire un membre du groupe ?
  3. Que peut faire un autre utilisateur ?
  4. Quelle est la valeur numérique (en octal) de ces permissions ?

Corrigé :

- rwx r-x r--
  ↑  ↑   ↑   ↑
  |  |   |   └── Others (autres) : r-- = 4 (lecture seule)
  |  |   └────── Group (groupe) : r-x = 5 (lecture + exécution)
  |  └────────── User (propriétaire) : rwx = 7 (tous les droits)
  └───────────── Type : fichier normal (-), dossier (d)
  1. Propriétaire : peut lire, écrire et exécuter le script.
  2. Groupe : peut lire et exécuter (mais pas modifier).
  3. Autres : peut seulement lire (pas exécuter, pas modifier).
  4. Valeur octale : 754 (rwx=7, r-x=5, r--=4).

★★ Question avancée (5 min)

Énoncé : Scénario pratique. Un étudiant A crée un script evaluation.py dans son dossier personnel avec les permissions -rw-------. Un étudiant B veut l'exécuter.

  1. Pourquoi B ne peut-il pas exécuter le script ?
  2. Que doit faire A pour que B puisse l'exécuter (sans pouvoir le modifier) ?
  3. Et pour que tout le monde puisse le lire ET l'exécuter ?
  4. Quelle commande PowerShell (sous Windows) permet de gérer les permissions ? Quelle commande Linux fait la même chose ?

Corrigé :

  1. Permissions : -rw------- = 600. Le propriétaire (A) a lecture+écriture. Personne d'autre n'a aucun droit. B ne peut ni lire, ni exécuter.
  2. Donner l'exécution au groupe : chmod 710 evaluation.py (ou chmod g+rx evaluation.py). → -rwx--x--- (propriétaire : tout, groupe : exécution uniquement). B peut exécuter mais pas lire le code source.
  3. Lecture + exécution pour tous : chmod 755 evaluation.py → -rwxr-xr-x. Tout le monde peut lire et exécuter. La valeur 755 est le standard pour les scripts publics.
  4. Windows (PowerShell) : Get-Acl / Set-Acl pour lire/modifier les permissions (ACL).
    Linux : chmod, chown, chgrp pour gérer les permissions.

Note pédagogique ENS

Transposition didactique

La notion de système d'exploitation peut être introduite en SNT Seconde avec l'analogie du chef d'orchestre (OS) qui dirige les musiciens (applications) et distribue les partitions (ressources). L'arborescence des fichiers est un concept très concret : les étudiants peuvent explorer l'explorateur Windows pour retrouver les dossiers vus en TD. Pour les commandes PowerShell, organiser un défi « course aux commandes » où chaque groupe doit accomplir une série de tâches le plus rapidement possible.

Conseil pour l'enseignant formateur

L'exercice 3 (arborescence) est un bon support pour vérifier que les étudiants maîtrisent la différence entre chemin absolu et relatif. Proposer des exercices supplémentaires où les étudiants doivent écrire le chemin relatif entre deux points de l'arborescence. Pour les états du processus, le diagramme en machine à états est à faire reproduire par les étudiants de mémoire. L'ordonnancement Round Robin (★★) peut faire l'objet d'une activité physique où les étudiants se passent un ballon (le CPU) à tour de rôle.

Prolongement

Demander aux étudiants d'installer une machine virtuelle Linux (Ubuntu) sous VirtualBox et de reproduire les mêmes commandes en terminal bash : ls, mkdir, cd, touch, cat, rm, pwd. Comparer les syntaxes PowerShell/Linux et discuter des différences philosophiques entre les deux OS.

Pour aller plus loin

  • États de processus : Faire un jeu de rôle avec 3 chaises (Prêt, Élu, Bloqué) et des étudiants qui jouent les processus.
  • Permissions : Sur une machine Linux, faire ls -l dans /usr/bin et interpréter les permissions de 3 fichiers.
  • Arborescence : Dessiner l'arborescence de son propre C:\Users (sans entrer dans les sous-dossiers systèmes).
  • PowerShell : Demander aux étudiants d'écrire un script qui crée automatiquement leur arborescence de fichiers personnelle.
  • Syscalls : Sur Linux, utiliser strace ls pour voir les appels système émis par une commande simple.
