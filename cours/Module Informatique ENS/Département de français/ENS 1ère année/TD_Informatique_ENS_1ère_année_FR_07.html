Objectifs pédagogiques

À l'issue de cette séance de TD, l'étudiant est capable de : - Distinguer les différents types de réseaux (LAN, WAN, Internet) et leur portée - Comprendre le rôle des adresses IP (IPv4/IPv6), du masque et du DNS - Décrire les étapes d'une communication client-serveur et le rôle de chaque protocole - Associer les protocoles réseau à leurs ports par défaut - Comparer les méthodes de partage de fichiers et recommander la plus adaptée

Exercice 1 — Vocabulaire réseau (15 min)

Énoncé : Associer chaque terme à sa définition.

Terme Définition
1. LAN A. Réseau mondial interconnectant des millions de réseaux
2. WAN B. Adresse unique d'un appareil sur le réseau
3. Internet C. Réseau local (bâtiment, salle)
4. Adresse IP D. Traduit les noms de domaine en adresses IP
5. DNS E. Réseau étendu (ville, pays)
6. URL F. Adresse d'une ressource sur le Web

Corrigé : 1→C, 2→E, 3→A, 4→B, 5→D, 6→F

Exercice 2 — Adresses IP (20 min)

Énoncé : 1. Quelle est la différence entre IPv4 et IPv6 ? 2. À quelle classe appartient l'adresse 192.168.1.1 ? 3. Combien d'adresses IPv4 différentes peut-on coder au maximum ? 4. Combien d'adresses IPv6 ? 5. Que permet la commande ping 8.8.8.8 ?

Corrigé : 1. IPv4 : 32 bits (4 octets), ~4,3 milliards d'adresses. IPv6 : 128 bits, nombre astronomique d'adresses. 2. 192.168.x.x est une adresse privée de classe C (réseaux locaux). 3. 2³² = 4 294 967 296 (environ 4,3 milliards). 4. 2¹²⁸ = 340 282 366 920 938 463 463 374 607 431 768 211 456 (340 undécillions). 5. ping 8.8.8.8 teste la connectivité vers le serveur DNS de Google — si ça répond, la connexion Internet fonctionne.

Exercice 3 — Client-serveur (15 min)

Énoncé : Décrire les étapes de communication quand un utilisateur visite https://www.ens-mostaganem.dz.

Pour chaque étape, indiquer si c'est le client (navigateur) ou le serveur qui agit.

  1. Saisie de l'URL dans la barre d'adresse
  2. Requête DNS pour trouver l'adresse IP
  3. Établissement de la connexion TCP
  4. Négociation TLS (chiffrement)
  5. Envoi de la requête HTTP GET
  6. Traitement de la requête par le serveur
  7. Envoi de la réponse (page HTML)
  8. Affichage de la page dans le navigateur

Corrigé : 1. Client (utilisateur) 2. Client (le navigateur interroge le DNS) 3. Client et serveur (TCP handshake) 4. Client et serveur (TLS handshake) 5. Client 6. Serveur 7. Serveur 8. Client

Exercice 4 — Protocoles et ports (20 min)

Énoncé : Associer chaque protocole à son port par défaut et à son utilisation.

Protocole Port Utilisation
HTTP 22 Transfert de fichiers sécurisé
HTTPS 80 Accès distant sécurisé
FTP 21 Navigation web non chiffrée
SSH 443 Navigation web chiffrée
SMTP 25 Réception d'emails
IMAP 143 Envoi d'emails

Corrigé : | Protocole | Port | Utilisation | |-----------|------|-------------| | HTTP | 80 | Navigation web non chiffrée | | HTTPS | 443 | Navigation web chiffrée | | FTP | 21 | Transfert de fichiers | | SSH | 22 | Accès distant sécurisé | | SMTP | 25 | Envoi d'emails | | IMAP | 143 | Réception d'emails (synchro multi-appareils) |

Exercice 5 — Cloud et stockage (15 min)

Énoncé : Vous devez partager un dossier de 50 Mo (cours, TD, images) avec votre groupe de TD.

  1. Quels sont les avantages et inconvénients de chaque méthode : a) Clé USB b) Email (pièce jointe) c) Google Drive / OneDrive d) Moodle
  2. Quelle méthode recommandez-vous et pourquoi ?

Corrigé :

Méthode Avantages Inconvénients
Clé USB Pas besoin d'Internet, rapide Risque perte/virus, uniquement en présentiel
Email Simple, traçable Limite pièce jointe (souvent 25 Mo)
Drive/OneDrive Partage par lien, accessible partout, versioning Nécessite Internet et compte
Moodle Intégré à l'université, sécurisé Moins flexible, interface parfois lourde

Recommandation : Drive ou Moodle pour 50 Mo (l'email est limité à 25 Mo). La clé USB en complément pour le présentiel.

Note pédagogique ENS

Transposition didactique

Les concepts réseau peuvent être introduits en SNT Seconde avec des analogies simples : le réseau local est comme les salles d'une école reliées par des couloirs, Internet est comme le réseau routier mondial. L'adresse IP est comme une adresse postale, le DNS est comme l'annuaire téléphonique. Pour les protocoles, on peut comparer HTTP à une carte postale (texte clair) et HTTPS à une lettre cachetée.

Conseil pour l'enseignant formateur

L'exercice 3 (client-serveur) est central : demander aux étudiants de rejouer la scène en binômes, l'un jouant le client et l'autre le serveur. Chaque étape est verbalisée. Pour l'exercice 4 (ports), faire créer une fiche mémoire plastifiée avec les protocoles/ports à réviser régulièrement. L'exercice 5 (Cloud) est très concret : faire témoigner les étudiants de leurs propres pratiques de partage de fichiers.

Prolongement

Configurer un petit serveur web local avec Python (python -m http.server 8000) et y accéder depuis un navigateur. Observer les requêtes avec les outils développeur (F12 → onglet Réseau). Identifier les codes HTTP (200, 404, 500) et comprendre ce qu'ils signifient.
