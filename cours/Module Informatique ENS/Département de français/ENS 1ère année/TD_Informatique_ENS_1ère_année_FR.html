Exercice 1 — Architecture et codage (15 min)

Scénario enseignant : Vous devez vérifier que vos étudiants comprennent le rôle des composants élémentaires d'un ordinateur. Cet exercice permet de sonder leurs connaissances sur l'architecture von Neumann.

✓ Question de base (5 min)

Énoncé : Expliquer le rôle de l'ALU, de l'unité de contrôle et de la mémoire centrale. Convertir 13 en binaire.

Corrigé détaillé :

  • ALU (Arithmetic Logic Unit) : effectue les opérations arithmétiques (addition, soustraction) et logiques (ET, OU, NON).
  • UC (Unité de Contrôle) : orchestre le cycle fetch-decode-execute, séquence le déroulement des instructions.
  • Mémoire centrale (RAM) : stocke temporairement les instructions et les données en cours d'utilisation. Volatile.
  • 13₁₀ = 1101→ — méthode : divisions successives par 2 :
13 ÷ 2 = 6 reste 1  ↑
 6 ÷ 2 = 3 reste 0  |
 3 ÷ 2 = 1 reste 1  |
 1 ÷ 2 = 0 reste 1  |
 Lecture des restes de bas en haut → 1101

★ Question intermédiaire (5 min)

Énoncé : Associer chaque composant à sa catégorie (entrée, sortie, traitement, contrôle, mémoire) :

Composant Rôle Catégorie
Clavier Saisie de texte ?
Écran Affichage visuel ?
ALU Calculs arithmétiques ?
RAM Stockage temporaire ?
Disque dur Stockage permanent ?

Corrigé : Clavier → Entrée, Écran → Sortie, ALU → Traitement, RAM → Mémoire centrale, Disque dur → Mémoire de masse (stockage permanent).

Exercice 2 — Processus et threads (18 min)

Scénario enseignant : Vos étudiants confondent souvent processus et thread. Utilisez l'exemple concret du navigateur web pour ancrer la différence. Proposez des analogies (usine/ouvrier, cuisine/chef).

✓ Question de base (6 min)

Énoncé : Distinguer processus et thread. Donner un exemple concret avec un navigateur web.

Corrigé détaillé :

Caractéristique Processus Thread
Espace mémoire Indépendant (propre espace d'adressage) Partagé avec le processus parent
Communication Complexe (IPC : pipes, sockets, signaux) Directe (variables globales)
Création Lourde (copie du contexte) Légère (simple fil d'exécution)
Isolation Forte (un crash n'affecte pas les autres) Faible (un bug peut tout corrompre)
Commutation Coûteuse (changement de contexte) Rapide (même espace d'adressage)

Analogies pédagogiques :

  • Processus = usine (chaque usine a ses propres ressources, équipements, stocks)
  • Thread = ouvrier (les ouvriers d'une même usine partagent les mêmes outils et locaux)

Exemple navigateur web : - 1 processus pour l'ensemble du navigateur - Plusieurs threads : UI (interface), rendu (affichage des pages), réseau (téléchargement), extensions (plugins)

Exercice 3 — Algorithme maximum (18 min)

Scénario enseignant : L'algorithmique est le cœur de la pensée informatique. Cet exercice simple (recherche du maximum) permet de vérifier la maîtrise des boucles, conditions, indices de tableau, et de la notion de complexité.

✓ Question de base (6 min)

Énoncé : Écrire en pseudo-code l'algorithme qui trouve le maximum dans un tableau de n entiers. Quelle est sa complexité temporelle ?

Corrigé détaillé :

ALGORITHME Maximum(T[0..n-1])
  ENTRÉE : T, tableau d'entiers de taille n (n ≥ 1)
  SORTIE : la valeur maximale du tableau

  max ← T[0]             // Initialisation : on suppose que le premier est le max
  POUR i DE 1 À n-1 FAIRE   // On parcourt les éléments restants
    SI T[i] > max ALORS     // Si on trouve un élément plus grand
      max ← T[i]            // On met à jour max
    FIN SI
  FIN POUR

  RETOURNER max
FIN ALGORITHME

Complexité : O(n) — un seul parcours linéaire du tableau. C'est la complexité optimale car il faut examiner chaque élément au moins une fois.

Preuve de correction (élémentaire) : - Initialisation : max = T[0] est bien le maximum du sous-tableau T[0..0] - Conservation : à chaque itération i, max est le maximum de T[0..i] - Terminaison : quand i = n-1, max est le maximum de tout le tableau

★ Question intermédiaire (6 min)

Énoncé : Adapter l'algorithme pour retourner l'indice de la première occurrence du maximum (et non sa valeur).

Corrigé :

ALGORITHME IndiceMaximum(T[0..n-1])
  max ← T[0]
  indice ← 0
  POUR i DE 1 À n-1 FAIRE
    SI T[i] > max ALORS
      max ← T[i]
      indice ← i        // On mémorise l'indice
    FIN SI
  FIN POUR
  RETOURNER indice       // Indice de la première occurrence
FIN ALGORITHME

Variante : Pour obtenir l'indice de la dernière occurrence, remplacer > par >=.

★★ Question avancée (6 min)

Énoncé : Écrire un algorithme qui trouve les deux plus grandes valeurs d'un tableau en un seul parcours (complexité O(n)).
Indice : maintenez deux variables max1 et max2.

Corrigé :

ALGORITHME DeuxMax(T[0..n-1])
  max1 ← T[0]        // La plus grande
  max2 ← T[1]        // La deuxième plus grande

  SI max2 > max1 ALORS   // On s'assure que max1 ≥ max2
    ÉCHANGER max1 ET max2
  FIN SI

  POUR i DE 2 À n-1 FAIRE
    SI T[i] > max1 ALORS
      max2 ← max1
      max1 ← T[i]
    SINON SI T[i] > max2 ALORS
      max2 ← T[i]
    FIN SI
  FIN POUR

  RETOURNER (max1, max2)
FIN ALGORITHME

Complexité : toujours O(n), mais avec un peu plus d'opérations par itération.

Exercice 4 — Réseaux (18 min)

Scénario enseignant : Les notions de base du réseau (IP, masque, passerelle, DNS) sont essentielles pour comprendre comment les machines communiquent. Utilisez une analogie postale (adresse = IP, code postal = masque, bureau de poste = passerelle, annuaire = DNS).

✓ Question de base (6 min)

Énoncé : Différencier IP, masque de sous-réseau et passerelle par défaut. Expliquer le rôle du DNS.

Corrigé détaillé :

  • Adresse IP (Internet Protocol) : identifiant unique d'une machine sur le réseau (ex: 192.168.1.10). Comme une adresse postale.
  • Masque de sous-réseau : sépare la partie réseau de la partie hôte dans l'adresse IP (ex: 255.255.255.0 = /24). Comme le code postal.
  • Passerelle par défaut (default gateway) : adresse IP du routeur qui permet de sortir du réseau local pour accéder à Internet (ex: 192.168.1.1). Comme le bureau de poste central.
  • DNS (Domain Name System) : traduit un nom de domaine (google.com) en adresse IP (142.250.178.4). Comme l'annuaire téléphonique.

Exemple concret : Quand vous tapez www.ens.dz dans un navigateur : 1. Le navigateur demande au DNS : « quelle est l'IP de www.ens.dz ? » 2. Le DNS répond : 193.194.xxx.xxx 3. Le navigateur envoie une requête HTTP à cette IP via la passerelle 4. Le serveur web répond avec la page HTML

★ Question intermédiaire (6 min)

Énoncé : Une machine a l'IP 192.168.1.35 avec un masque 255.255.255.0.

  1. Quelle est l'adresse du réseau ?
  2. Combien de machines peuvent être connectées sur ce réseau ?
  3. La machine 192.168.1.200 est-elle sur le même réseau ?
  4. Et la machine 192.168.2.10 ?

Corrigé :

  1. Adresse réseau : 192.168.1.0 (partie réseau = 192.168.1, partie hôte = 0).
    Calcul : IP ∧ Masque = 192.168.1.35 ∧ 255.255.255.0 = 192.168.1.0
  2. Nombre de machines : 2⁸ - 2 = 254 machines (car 8 bits pour la partie hôte, on exclut l'adresse réseau .0 et le broadcast .255).
  3. Oui, 192.168.1.200 a la même partie réseau (192.168.1). Elle est sur le même réseau local.
  4. Non, 192.168.2.10 a une partie réseau différente (192.168.2). Elle nécessite un routage via la passerelle.

★★ Question avancée (6 min)

Énoncé : On considère le réseau 172.16.0.0/16. On veut créer 4 sous-réseaux de taille égale.

  1. Quel nouveau masque faut-il utiliser ?
  2. Quelles sont les adresses de chaque sous-réseau ?
  3. Combien de machines par sous-réseau ?

Corrigé :

  1. Masque /16 → /18 (on emprunte 2 bits pour le sous-réseage). Soit 255.255.192.0.
  2. Les 4 sous-réseaux :
  3. 172.16.0.0/18 (hôtes : 172.16.0.1 → 172.16.63.254)
  4. 172.16.64.0/18 (hôtes : 172.16.64.1 → 172.16.127.254)
  5. 172.16.128.0/18 (hôtes : 172.16.128.1 → 172.16.191.254)
  6. 172.16.192.0/18 (hôtes : 172.16.192.1 → 172.16.255.254)
  7. 2¹⁴ - 2 = 16 382 machines par sous-réseau.

Exercice 5 — Python et sécurité (16 min)

Scénario enseignant : Vos étudiants débutent en Python. Proposez un script simple (moyenne de notes) pour vérifier les bases. Ajoutez une dimension sécurité pour sensibiliser dès la 1ère séance.

✓ Question de base (6 min)

Énoncé : Écrire un script Python qui calcule la moyenne de 5 notes. Lister 3 bonnes pratiques en sécurité informatique.

Corrigé détaillé :

# Script : calcul_moyenne.py
# Auteur : Étudiant ENS
# Date : 2025

notes = [12, 14, 11, 15, 13]       # Liste des 5 notes
moyenne = sum(notes) / len(notes)   # Calcul de la moyenne
print(f"Moyenne : {moyenne:.2f}")  # Affichage formaté à 2 décimales

Explication pas à pas : 1. notes = [...] : création d'une liste Python (tableau dynamique) 2. sum(notes) : fonction intégrée qui additionne tous les éléments 3. len(notes) : retourne la taille de la liste (ici 5) 4. moyenne = ... : affectation du résultat 5. print(f"...") : f-string pour formater l'affichage

Bonnes pratiques de sécurité :

# Pratique Pourquoi ?
1 Authentification multifacteur (MFA) Ajoute une couche de sécurité au-delà du mot de passe
2 Mises à jour régulières Corrigent les vulnérabilités connues (zero-day, failles)
3 Sauvegardes automatiques Permettent de restaurer les données en cas d'attaque (ransomware)
4 Mots de passe uniques et complexes Empêchent le credential stuffing (réutilisation sur plusieurs sites)
5 Principe du moindre privilège Chaque utilisateur/programme n'a que les droits strictement nécessaires

★ Question intermédiaire (5 min)

Énoncé : Modifier le script Python pour qu'il : 1. Demande les notes à l'utilisateur via input() (5 notes) 2. Vérifie que chaque note est comprise entre 0 et 20 3. Affiche un message d'erreur si une note est invalide

Corrigé :

notes = []
for i in range(5):
    try:
        note = float(input(f"Entrez la note {i+1} (0-20) : "))
        if 0 <= note <= 20:
            notes.append(note)
        else:
            print("Erreur : la note doit être entre 0 et 20.")
            break
    except ValueError:
        print("Erreur : veuillez entrer un nombre valide.")
        break

if len(notes) == 5:
    moyenne = sum(notes) / len(notes)
    print(f"Moyenne : {moyenne:.2f}")
else:
    print("Calcul impossible : notes incomplètes.")

Concepts Python utilisés : - input() : saisie utilisateur (retourne une chaîne) - float() : conversion en nombre décimal - try/except : gestion d'exceptions (si l'utilisateur entre du texte) - break : sortie anticipée de la boucle

★★ Question avancée (5 min)

Énoncé : En une ligne de Python (compréhension de liste), calculer la moyenne d'un nombre variable de notes passées en argument via sys.argv.

Corrigé :

import sys
notes = [float(x) for x in sys.argv[1:]]
print(f"Moyenne : {sum(notes)/len(notes):.2f}" if notes else "Aucune note fournie.")

Exécution : python moyenne.py 12 14 11 15 13
Résultat : Moyenne : 13.00

Exercice 1 — Conversions binaires (15 min)

Scénario enseignant : Commencez par la méthode des divisions successives. Distribuez la table des puissances de 2 (ci-dessus). Pour chaque nombre, demandez aux étudiants de décomposer en sommes de puissances de 2, puis de passer à la méthode posée.

✓ Question de base (6 min)

Énoncé : Convertir les nombres suivants en binaire par la méthode des divisions successives par 2.

  1. 13 (décimal) → binaire
  2. 25 (décimal) → binaire
  3. 42 (décimal) → binaire
  4. 100 (décimal) → binaire

Corrigé détaillé :

1. 13₁₀ :

13 ÷ 2 = 6 reste 1  ↑  (poids faible)
 6 ÷ 2 = 3 reste 0  |
 3 ÷ 2 = 1 reste 1  |
 1 ÷ 2 = 0 reste 1  |  (poids fort)

Lecture des restes de bas en haut : 1101→
Vérification : 8 + 4 + 1 = 13 ✓

2. 25₁₀ :

25 ÷ 2 = 12 reste 1
12 ÷ 2 =  6 reste 0
 6 ÷ 2 =  3 reste 0
 3 ÷ 2 =  1 reste 1
 1 ÷ 2 =  0 reste 1

→ 11001₂ (16 + 8 + 1 = 25 ✓)

3. 42₁₀ :

42 ÷ 2 = 21 reste 0
21 ÷ 2 = 10 reste 1
10 ÷ 2 =  5 reste 0
 5 ÷ 2 =  2 reste 1
 2 ÷ 2 =  1 reste 0
 1 ÷ 2 =  0 reste 1

→ 101010₂ (32 + 8 + 2 = 42 ✓)

4. 100₁₀ :

100 ÷ 2 = 50 reste 0
 50 ÷ 2 = 25 reste 0
 25 ÷ 2 = 12 reste 1
 12 ÷ 2 =  6 reste 0
  6 ÷ 2 =  3 reste 0
  3 ÷ 2 =  1 reste 1
  1 ÷ 2 =  0 reste 1

→ 1100100₂ (64 + 32 + 4 = 100 ✓)

Exercice 2 — Conversions décimales (15 min)

Scénario enseignant : L'opération inverse (binaire → décimal) est plus intuitive : il suffit d'additionner les puissances de 2. Montrez la correspondance entre la position du bit et la puissance de 2.

✓ Question de base (6 min)

Énoncé : Convertir les nombres binaires suivants en décimal (additionner les puissances de 2).

  1. 1010→
  2. 1111→
  3. 100000→
  4. 110011→

Corrigé détaillé :

  1. 1010₂ = 1×8 + 0×4 + 1×2 + 0×1 = 8 + 2 = 10
  2. 1111₂ = 1×8 + 1×4 + 1×2 + 1×1 = 8 + 4 + 2 + 1 = 15
  3. 100000₂ = 1×32 + 0×16 + 0×8 + 0×4 + 0×2 + 0×1 = 32
  4. 110011₂ = 1×32 + 1×16 + 0×8 + 0×4 + 1×2 + 1×1 = 32 + 16 + 2 + 1 = 51

Méthode du doublement (alternative) :
Partir de 0, pour chaque bit de gauche à droite : doubler le résultat et ajouter le bit. - 1010₂ : 0 → 0×2+1=1 → 1×2+0=2 → 2×2+1=5 → 5×2+0=10 ✓

★ Question intermédiaire (5 min)

Énoncé : Quel est le plus grand nombre décimal qu'on peut coder avec :

  1. 4 bits ?
  2. 8 bits ?
  3. 16 bits ?

Corrigé : 1. 4 bits : 1111₂ = 2⁴ - 1 = 15 2. 8 bits : 1111 1111₂ = 2⁸ - 1 = 255 3. 16 bits : 2¹⁶ - 1 = 65535

Règle générale : Avec n bits, on peut coder les nombres de 0 à 2ⁿ - 1, soit 2ⁿ valeurs différentes.

Exercice 5 — Taille des fichiers (20 min)

Scénario enseignant : Exercice très concret : les étudiants pourront vérifier les résultats en ouvrant les propriétés de leurs propres fichiers. Expliquez la différence entre taille non compressée (calcul théorique) et taille réelle (après compression : JPEG, MP3, etc.).

✓ Question de base (8 min)

Énoncé : Calculer la taille estimée des fichiers suivants.

  1. Un texte de 5000 caractères ASCII (sans mise en forme).
  2. Une image 200×150 pixels en noir et blanc (1 bit/pixel).
  3. Une image 200×150 pixels en 24 bits (TrueColor).
  4. Une photo 4000×3000 pixels en 24 bits compressée JPEG (ratio 10:1).

Corrigé détaillé :

  1. Texte : 5000 × 1 octet = 5000 octets
    Soit 5000 ÷ 1024 ≈ 4,9 Ko

  2. Image NB 200×150 :

  3. Nombre de pixels = 200 × 150 = 30 000 pixels
  4. 1 bit/pixel → 30 000 bits = 30 000 ÷ 8 = 3750 octets

  5. Soit 3750 ÷ 1024 ≈ 3,7 Ko

  6. Image couleur 200×150 (24 bits) :

  7. 30 000 pixels × 24 bits = 720 000 bits
  8. 720 000 ÷ 8 = 90 000 octets

  9. Soit 90 000 ÷ 1024 ≈ 87,9 Ko
    Remarque : une icône typique (32×32) en 24 bits = 32×32×3 = 3072 octets ≈ 3 Ko.

  10. Photo 4000×3000 (24 bits) compressée JPEG :

  11. 4000 × 3000 = 12 000 000 pixels
  12. 12 000 000 × 3 = 36 000 000 octets ≈ 34,3 Mo
  13. Compression JPEG (10:1) → 36 000 000 ÷ 10 = 3 600 000 octets ≈ 3,4 Mo

Formules essentielles à retenir : - Taille (octets) = Largeur × Hauteur × (bits/pixel) ÷ 8 - Taille compressée = Taille non compressée ÷ ratio de compression

★ Question intermédiaire (6 min)

Énoncé : Une chanson au format CD audio (44,1 kHz, 16 bits, stéréo) dure 3 minutes. Calculer :

  1. Le débit audio en bits par seconde (bitrate).
  2. La taille totale du fichier non compressé.
  3. La taille compressée en MP3 (bitrate 128 kbps — kilo bits par seconde).

Corrigé :

  1. Débit audio :
  2. 44 100 échantillons/s × 16 bits/échantillon × 2 canaux = 1 411 200 bits/s

  3. Soit ≈ 1,41 Mbps (Mega bits par seconde)

  4. Taille non compressée :

  5. 1 411 200 bits/s × 180 s = 254 016 000 bits
  6. ÷ 8 = 31 752 000 octets

  7. ÷ 1024 ≈ 31 008 Ko ≈ 30,3 Mo

  8. Taille compressée MP3 (128 kbps) :

  9. 128 000 bits/s × 180 s = 23 040 000 bits
  10. ÷ 8 = 2 880 000 octets
  11. ÷ 1024 ≈ 2812 Ko ≈ 2,75 Mo

Ratio de compression : 30,3 / 2,75 ≈ 11:1 — impressionnant !

Scénario enseignant : Le cycle fetch-decode-execute-writeback est le battement de cœur du processeur. Faites-le mimer par les étudiants : un groupe mime le chargement, un autre le décodage, etc.

✓ Question de base (5 min)

Énoncé : Remettre dans l'ordre les étapes du cycle d'exécution d'une instruction.

  1. L'unité de contrôle décode l'instruction (operation + opérandes)
  2. L'ALU exécute l'opération
  3. Le résultat est écrit dans un registre ou en mémoire
  4. L'instruction est chargée depuis la RAM vers le registre instruction

Corrigé :

Étape Description Bus utilisé

Exercice 3 — Hiérarchie mémoire (20 min)

Scénario enseignant : La hiérarchie mémoire est un compromis vitesse/coût. Utilisez l'image d'une pyramide : plus on monte, plus c'est rapide et cher, mais plus la capacité est faible.

✓ Question de base (8 min)

Énoncé : Classer les types de mémoire suivants du plus rapide au plus lent et du plus petit au plus grand : SSD 1 To, RAM 16 Go, Cache L1 64 Ko, Registres 512 o, HDD 2 To, Cache L2 512 Ko.

Corrigé :

Niveau Type Taille Vitesse Ordre de grandeur
1 (rapide) Registres 512 o < 1 ns Comme une feuille de papier sur le bureau
2 Cache L1 64 Ko ~1 ns Comme un tiroir de bureau
3 Cache L2 512 Ko ~4 ns Comme une armoire dans la pièce
4 RAM 16 Go ~50 ns Comme une bibliothèque dans le bâtiment
5 SSD 1 To ~100 µs Comme un entrepôt en ville
6 (lent) HDD 2 To ~10 ms Comme un entrepôt dans une autre ville

Question : Pourquoi un ordinateur avec 8 Go de RAM peut-il être plus rapide qu'un autre avec 16 Go ? Réponse : La vitesse ne dépend pas que de la RAM. Un CPU plus rapide (fréquence + cache), un SSD au lieu d'un HDD, et un OS optimisé peuvent compenser une RAM moindre.

★ Question intermédiaire (6 min)

Énoncé : Principe de localité. On suppose qu'un programme accède 1000 fois consécutives à la même variable. Avec un cache L1 de 64 Ko et un temps d'accès de 1 ns (cache) vs 50 ns (RAM), calculer :

  1. Le temps total sans cache (accès RAM à chaque fois).
  2. Le temps total avec cache (1 accès RAM, 999 accès cache).
  3. Le facteur d'accélération.

Corrigé :

  1. Sans cache : 1000 × 50 ns = 50 000 ns = 50 µs
  2. Avec cache : 1 × 50 ns (premier accès, cache miss) + 999 × 1 ns (cache hit) = 50 + 999 = 1049 ns ≈ 1,05 µs
  3. Facteur d'accélération : 50 000 / 1049 ≈ 48× plus rapide !

Conclusion : Le cache exploite la localité temporelle (une variable accédée souvent reste dans le cache) et spatiale (les variables voisines sont chargées ensemble).

★★ Question avancée (6 min)

Énoncé : Une page web fait 4 Mo. Le cache L2 fait 512 Ko. Combien de « cache miss » (défauts de cache) y aura-t-il si la page est chargée intégralement via le cache ?
On suppose que le cache se remplit par blocs de 64 Ko (taille de ligne de cache).

Corrigé :

  1. Nombre total de blocs nécessaires : 4 Mo / 64 Ko = 4096 Ko / 64 Ko = 64 blocs
  2. Capacité du cache L2 : 512 Ko / 64 Ko = 8 lignes de cache
  3. Cache miss : le cache ne peut contenir que 8 blocs à la fois. Si la page est plus grande que le cache, chaque nouveau bloc provoque un miss. Avec un remplacement, il y aura au moins 64 - 8 = 56 cache misses (dans le pire cas, 64 misses si les blocs ne se chevauchent pas).
  4. Ratio de hits : (64 - 56) / 64 = 12,5 % de hits seulement dans ce cas — d'où l'importance d'avoir un cache suffisamment grand pour les données fréquemment utilisées.

Exercice 5 — Syscalls et permissions (15 min)

Scénario enseignant : La distinction mode utilisateur / mode noyau est fondamentale pour la sécurité et la stabilité du système. Un programme applicatif ne peut rien faire sans passer par l'OS.

✓ Question de base (5 min)

Énoncé : Vrai ou Faux ? Justifier.

  1. Un logiciel applicatif peut accéder directement au disque dur sans passer par l'OS.
  2. Le noyau Linux et le noyau Windows sont identiques.
  3. Un appel système (syscall) permet à une application de demander un service au noyau.
  4. La mémoire virtuelle permet à un processus d'utiliser plus de mémoire que la RAM disponible.
  5. Un processus bloqué consomme du temps CPU.

Corrigé :

  1. Faux — toute opération matérielle passe obligatoirement par l'OS (sécurité, abstraction, isolation). L'accès direct serait un trou de sécurité critique.
  2. Faux — architectures différentes (Linux : monolithique avec modules chargeables ; Windows : hybride avec micro-noyau + services). Les API (syscalls) sont également différentes.
  3. Vrai — c'est le mécanisme standard. L'application exécute une instruction spéciale (ex: int 0x80 ou syscall) qui passe en mode noyau.
  4. Vrai — via le swap (espace d'échange sur disque) et la pagination. Les pages rarement utilisées sont déplacées sur le disque pour libérer de la RAM.
  5. Faux — un processus bloqué est en attente d'une ressource (E/S, clavier, etc.). Il n'est pas dans la file des prêts et ne reçoit pas de temps CPU.

★ Question intermédiaire (5 min)

Énoncé : Tableau de permissions. Soit le fichier script.sh avec les permissions -rwxr-xr-- :

  1. Que peut faire le propriétaire ?
  2. Que peut faire un membre du groupe ?
  3. Que peut faire un autre utilisateur ?
  4. Quelle est la valeur numérique (en octal) de ces permissions ?

Corrigé :

- rwx r-x r--
  ↑  ↑   ↑   ↑
  |  |   |   └── Others (autres) : r-- = 4 (lecture seule)
  |  |   └────── Group (groupe) : r-x = 5 (lecture + exécution)
  |  └────────── User (propriétaire) : rwx = 7 (tous les droits)
  └───────────── Type : fichier normal (-), dossier (d)
  1. Propriétaire : peut lire, écrire et exécuter le script.
  2. Groupe : peut lire et exécuter (mais pas modifier).
  3. Autres : peut seulement lire (pas exécuter, pas modifier).
  4. Valeur octale : 754 (rwx=7, r-x=5, r--=4).

★★ Question avancée (5 min)

Énoncé : Scénario pratique. Un étudiant A crée un script evaluation.py dans son dossier personnel avec les permissions -rw-------. Un étudiant B veut l'exécuter.

  1. Pourquoi B ne peut-il pas exécuter le script ?
  2. Que doit faire A pour que B puisse l'exécuter (sans pouvoir le modifier) ?
  3. Et pour que tout le monde puisse le lire ET l'exécuter ?
  4. Quelle commande PowerShell (sous Windows) permet de gérer les permissions ? Quelle commande Linux fait la même chose ?

Corrigé :

  1. Permissions : -rw------- = 600. Le propriétaire (A) a lecture+écriture. Personne d'autre n'a aucun droit. B ne peut ni lire, ni exécuter.
  2. Donner l'exécution au groupe : chmod 710 evaluation.py (ou chmod g+rx evaluation.py). → -rwx--x--- (propriétaire : tout, groupe : exécution uniquement). B peut exécuter mais pas lire le code source.
  3. Lecture + exécution pour tous : chmod 755 evaluation.py → -rwxr-xr-x. Tout le monde peut lire et exécuter. La valeur 755 est le standard pour les scripts publics.
  4. Windows (PowerShell) : Get-Acl / Set-Acl pour lire/modifier les permissions (ACL).
    Linux : chmod, chown, chgrp pour gérer les permissions.

Énoncé : Créer un script recherche.py qui implémente deux algorithmes de recherche :

  1. recherche_sequentielle(liste, valeur) — parcourt la liste et retourne l'indice ou -1
  2. recherche_dichotomique(liste, valeur) — recherche dans une liste triée (diviser pour régner)

Corrigé :

def recherche_sequentielle(liste, valeur):
    """Recherche séquentielle. Retourne l'indice ou -1."""
    comparaisons = 0
    for i, v in enumerate(liste):
        comparaisons += 1
        if v == valeur:
            print(f"  Séquentielle : {comparaisons} comparaison(s)")
            return i
    print(f"  Séquentielle : {comparaisons} comparaison(s)")
    return -1

def recherche_dichotomique(liste, valeur):
    """Recherche dichotomique (liste triée). Retourne l'indice ou -1."""
    comparaisons = 0
    debut, fin = 0, len(liste) - 1
    while debut <= fin:
        comparaisons += 1
        milieu = (debut + fin) // 2
        if liste[milieu] == valeur:
            print(f"  Dichotomique : {comparaisons} comparaison(s)")
            return milieu
        elif liste[milieu] < valeur:
            debut = milieu + 1
        else:
            fin = milieu - 1
    print(f"  Dichotomique : {comparaisons} comparaison(s)")
    return -1

class Pile:
    """Implémentation d'une pile LIFO."""
    def __init__(self):
        self._elements = []

    def empiler(self, element):
        self._elements.append(element)

    def depiler(self):
        if not self.est_vide():
            return self._elements.pop()
        return None

    def sommet(self):
        if not self.est_vide():
            return self._elements[-1]
        return None

    def est_vide(self):
        return len(self._elements) == 0

    def taille(self):
        return len(self._elements)

def valider_parentheses(expression):
    """Valide le parenthésage et retourne (valide, erreur_position, message)."""
    correspondance = {")": "(", "]": "[", "}": "{"}
    ouvrantes = "([{"
    fermantes = ")]}"
    pile = Pile()

    for i, char in enumerate(expression):
        if char in ouvrantes:
            pile.empiler(char)
        elif char in fermantes:
            if pile.est_vide():
                return False, i, f"Parenthèse fermante '{char}' sans ouvrante à la position {i}"
            sommet = pile.depiler()
            if sommet != correspondance[char]:
                return False, i, f"Non concordance : '{sommet}' ouvert mais '{char}' fermé à la position {i}"

    if not pile.est_vide():
        return False, len(expression) - 1, f"Il manque {pile.taille()} parenthèse(s) fermante(s)"

    return True, -1, "Expression correcte"

Corrigé :

import random

def tri_fusion(liste):
    """Tri fusion récursif."""
    if len(liste) <= 1:
        return liste

    milieu = len(liste) // 2
    gauche = tri_fusion(liste[:milieu])
    droite = tri_fusion(liste[milieu:])

    return fusionner(gauche, droite)

def fusionner(gauche, droite):
    """Fusionne deux listes triées."""
    resultat = []
    i = j = 0
    while i < len(gauche) and j < len(droite):
        if gauche[i] <= droite[j]:
            resultat.append(gauche[i])
            i += 1
        else:
            resultat.append(droite[j])
            j += 1
    resultat.extend(gauche[i:])
    resultat.extend(droite[j:])
    return resultat

Exercice 2 — Évaluation d'expression postfixée (RPN) (20 min)

Énoncé : Créer un script rpn.py qui évalue une expression en notation polonaise inversée (NPI/RPN) en utilisant une pile.

Principe : L'opérateur suit ses opérandes. Exemple : 3 4 + = 3 + 4 = 7

Exemples : - 3 4 + → 7 - 5 3 8 + - → 5 - (3 + 8) = -6 - 10 4 2 + * → 10 × (4 + 2) = 60

def evaluer_rpn(expression):
    """Évalue une expression en notation polonaise inversée."""
    pile = []
    operateurs = {
        "+": lambda a, b: a + b,
        "-": lambda a, b: a - b,
        "*": lambda a, b: a * b,
        "/": lambda a, b: a / b if b != 0 else None
    }

    elements = expression.split()
    for elem in elements:
        if elem in operateurs:
            if len(pile) < 2:
                return "Erreur : pas assez d'opérandes"
            b = pile.pop()
            a = pile.pop()
            resultat = operateurs[elem](a, b)
            if resultat is None:
                return "Erreur : division par zéro"
            pile.append(resultat)
        else:
            try:
                pile.append(float(elem))
            except ValueError:
                return f"Erreur : élément invalide '{elem}'"

    if len(pile) != 1:
        return f"Erreur : {len(pile)} résultats au lieu de 1"
    return pile[0]

L'exercice 5 (RLE) est ludique : demander aux étudiants de trouver des exemples de répétitions dans leur propre nom ou dans des phrases.
