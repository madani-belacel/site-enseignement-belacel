Objectifs pédagogiques

À l'issue de cette séance de TD, l'étudiant est capable de : - Identifier et décrire les 5 unités du modèle de von Neumann - Ordonner les étapes du cycle d'exécution d'une instruction (fetch-decode-execute-writeback) - Classer les différents types de mémoire par vitesse et taille - Exécuter des commandes de base en ligne de commande (PowerShell) - Expliquer le rôle de chaque composant dans le fonctionnement global d'un ordinateur

Vous êtes enseignant et devez expliquer comment fonctionne un ordinateur de l'intérieur. Ce TD détaille l'architecture de von Neumann, le cycle d'exécution, la hiérarchie mémoire et les commandes de base en ligne de commande. Utilisez des analogies concrètes (recette de cuisine, bureau de travail) et privilégiez la manipulation (ligne de commande en direct si possible sur machine virtuelle).

Exercice 1 — Modèle de von Neumann (15 min)

Scénario enseignant : Le modèle de von Neumann est la base de l'architecture des ordinateurs modernes. Commencez par une analogie simple (recette de cuisine) puis faites remplir le tableau d'association.

Analogie : L'ordinateur est comme une cuisine : - ALU = les ustensiles de cuisine (couteau, fouet, cuillère — les outils qui transforment les ingrédients) - UC = le chef cuisinier qui lit la recette et dit quoi faire dans quel ordre - RAM = le plan de travail où sont posés les ingrédients en cours d'utilisation - Disque dur = le garde-manger/réfrigérateur (stockage permanent) - Bus = les mains et les déplacements du chef entre les postes de travail

★★ Question avancée (4 min)

Énoncé : Le modèle de von Neumann a un goulot d'étranglement célèbre : le goulot de von Neumann (von Neumann bottleneck). Expliquer de quoi il s'agit et proposer une solution architecturale pour l'atténuer.

Corrigé : - Problème : Le bus unique entre le CPU et la mémoire limite le débit (les instructions et les données empruntent le même chemin). Le CPU peut être plus rapide que le temps de transfert mémoire → il reste inactif en attendant les données. - Solutions : - Architecture Harvard (bus séparés instructions/données) - Hiérarchie de caches (L1, L2, L3) - Mémoires plus rapides (DDR5, HBM) - Prédiction de branchement et exécution spéculative

Exercice 2 — Cycle d'exécution (15 min)

Scénario enseignant : Le cycle fetch-decode-execute-writeback est le battement de cœur du processeur. Faites-le mimer par les étudiants : un groupe mime le chargement, un autre le décodage, etc.

✓ Question de base (5 min)

Énoncé : Remettre dans l'ordre les étapes du cycle d'exécution d'une instruction.

  1. L'unité de contrôle décode l'instruction (operation + opérandes)
  2. L'ALU exécute l'opération
  3. Le résultat est écrit dans un registre ou en mémoire
  4. L'instruction est chargée depuis la RAM vers le registre instruction

Ordre correct : 4 → 1 → 2 → 3 (Fetch → Decode → Execute → Write-back)

Application : Décrire ce qui se passe quand on tape A au clavier (depuis la pression de la touche jusqu'à l'affichage à l'écran).

Réponse : Clavier → interruption matérielle → UC → OS (lecture du scan code) → conversion en caractère → écriture en RAM → affichage à l'écran via le contrôleur graphique.

★ Question intermédiaire (5 min)

Énoncé : Trace d'exécution. On suppose l'instruction ADD R1, R2, R3 (addition : R1 ← R2 + R3). Décrire chaque étape du cycle en détaillant les bus utilisés.

Corrigé :

Étape Description Bus utilisé
Fetch L'UC envoie l'adresse de la prochaine instruction (PC) sur le bus d'adresses → la RAM renvoie l'instruction sur le bus de données → l'instruction est stockée dans le Registre Instruction (IR) Bus d'adresses, Bus de données
Decode L'UC décode le code opération (ADD) et identifie les opérandes (R2, R3 comme sources, R1 comme destination) Interne au CPU
Execute L'ALU lit la valeur de R2 et R3 depuis les registres, effectue l'addition, stocke le résultat dans un registre temporaire Interne au CPU
Write-back Le résultat est écrit dans le registre R1. Le PC est incrémenté pour pointer vers l'instruction suivante Bus de données (interne)

★★ Question avancée (5 min)

Énoncé : Soit le programme machine suivant (langage d'assemblage simplifié) :

LOAD R1, #5        ; R1 ← 5 (chargement immédiat)
LOAD R2, #3        ; R2 ← 3
ADD  R3, R1, R2    ; R3 ← R1 + R2
STORE R3, [100]    ; Écrire R3 à l'adresse mémoire 100
HALT               ; Arrêt

Exécuter le cycle complet pour chaque instruction et donner l'état final des registres (R1, R2, R3) et de la mémoire à l'adresse 100.

Corrigé :

Instruction Fetch Decode Execute Write-back État PC
1: LOAD R1,#5 Charger instr. 1 LOAD immédiat R1 ← 5 R1 = 5 PC = 2
2: LOAD R2,#3 Charger instr. 2 LOAD immédiat R2 ← 3 R2 = 3 PC = 3
3: ADD R3,R1,R2 Charger instr. 3 ADD R3 ← 5+3=8 R3 = 8 PC = 4
4: STORE R3,[100] Charger instr. 4 STORE Écrire R3 en mémoire MEM[100] = 8 PC = 5
5: HALT Charger instr. 5 HALT Arrêt - PC = 5

État final : R1 = 5, R2 = 3, R3 = 8, MEM[100] = 8.

Exercice 3 — Hiérarchie mémoire (20 min)

Scénario enseignant : La hiérarchie mémoire est un compromis vitesse/coût. Utilisez l'image d'une pyramide : plus on monte, plus c'est rapide et cher, mais plus la capacité est faible.

✓ Question de base (8 min)

Énoncé : Classer les types de mémoire suivants du plus rapide au plus lent et du plus petit au plus grand : SSD 1 To, RAM 16 Go, Cache L1 64 Ko, Registres 512 o, HDD 2 To, Cache L2 512 Ko.

Corrigé :

Niveau Type Taille Vitesse Ordre de grandeur
1 (rapide) Registres 512 o < 1 ns Comme une feuille de papier sur le bureau
2 Cache L1 64 Ko ~1 ns Comme un tiroir de bureau
3 Cache L2 512 Ko ~4 ns Comme une armoire dans la pièce
4 RAM 16 Go ~50 ns Comme une bibliothèque dans le bâtiment
5 SSD 1 To ~100 µs Comme un entrepôt en ville
6 (lent) HDD 2 To ~10 ms Comme un entrepôt dans une autre ville

Question : Pourquoi un ordinateur avec 8 Go de RAM peut-il être plus rapide qu'un autre avec 16 Go ? Réponse : La vitesse ne dépend pas que de la RAM. Un CPU plus rapide (fréquence + cache), un SSD au lieu d'un HDD, et un OS optimisé peuvent compenser une RAM moindre.

★ Question intermédiaire (6 min)

Énoncé : Principe de localité. On suppose qu'un programme accède 1000 fois consécutives à la même variable. Avec un cache L1 de 64 Ko et un temps d'accès de 1 ns (cache) vs 50 ns (RAM), calculer :

  1. Le temps total sans cache (accès RAM à chaque fois).
  2. Le temps total avec cache (1 accès RAM, 999 accès cache).
  3. Le facteur d'accélération.

Corrigé :

  1. Sans cache : 1000 × 50 ns = 50 000 ns = 50 µs
  2. Avec cache : 1 × 50 ns (premier accès, cache miss) + 999 × 1 ns (cache hit) = 50 + 999 = 1049 ns ≈ 1,05 µs
  3. Facteur d'accélération : 50 000 / 1049 ≈ 48× plus rapide !

Conclusion : Le cache exploite la localité temporelle (une variable accédée souvent reste dans le cache) et spatiale (les variables voisines sont chargées ensemble).

★★ Question avancée (6 min)

Énoncé : Une page web fait 4 Mo. Le cache L2 fait 512 Ko. Combien de « cache miss » (défauts de cache) y aura-t-il si la page est chargée intégralement via le cache ?
On suppose que le cache se remplit par blocs de 64 Ko (taille de ligne de cache).

Corrigé :

  1. Nombre total de blocs nécessaires : 4 Mo / 64 Ko = 4096 Ko / 64 Ko = 64 blocs
  2. Capacité du cache L2 : 512 Ko / 64 Ko = 8 lignes de cache
  3. Cache miss : le cache ne peut contenir que 8 blocs à la fois. Si la page est plus grande que le cache, chaque nouveau bloc provoque un miss. Avec un remplacement, il y aura au moins 64 - 8 = 56 cache misses (dans le pire cas, 64 misses si les blocs ne se chevauchent pas).
  4. Ratio de hits : (64 - 56) / 64 = 12,5 % de hits seulement dans ce cas — d'où l'importance d'avoir un cache suffisamment grand pour les données fréquemment utilisées.

★★ Question avancée (5 min)

Énoncé : En une seule ligne PowerShell, trouver tous les fichiers .txt dans C:\Users et ses sous-dossiers, afficher leur nom, taille et date de modification, triés par taille décroissante.

Corrigé :

Get-ChildItem -Path "C:\Users" -Filter "*.txt" -Recurse | 
    Select-Object Name, Length, LastWriteTime | 
    Sort-Object -Property Length -Descending

Explication : - Get-ChildItem -Recurse : parcourt récursivement - -Filter "*.txt" : filtre les fichiers texte - Select-Object : ne garde que les colonnes utiles - Sort-Object -Descending : trie par taille décroissante

Variante plus concise : gci -r "C:\Users" -fi "*.txt" | sort len -desc | select name,len,last*

Note pédagogique ENS

Transposition didactique

Le modèle de von Neumann peut être introduit en collège/lycée avec une analogie simple : le cerveau (CPU) qui lit une recette de cuisine (programme en mémoire), exécute les instructions (ALU), et utilise le plan de travail (RAM) pour stocker les ingrédients temporaires. Chaque élève peut mimer le rôle d'un composant (mémoire, ALU, contrôleur) dans une activité théâtrale.

Conseil pour l'enseignant formateur

L'exercice 2 (cycle d'exécution) est fondamental : s'assurer que chaque étudiant sait réciter les 4 étapes dans l'ordre. Utiliser un jeu de cartes ou de flashcards pour mémoriser le cycle. Pour la hiérarchie mémoire, insister sur les ordres de grandeur (ns vs µs vs ms) qui sont abstraits pour les débutants. L'exercice de trace d'exécution (★★) est très formateur mais peut être réservé aux étudiants les plus avancés.

Prolongement

Proposer aux étudiants de démonter (virtuellement via des schémas ou réellement avec un vieil ordinateur) les composants d'un PC et de les identifier. Réaliser une affiche de classe représentant le modèle de von Neumann avec les composants réels d'un ordinateur du laboratoire.

Pour aller plus loin

  • Cycle d'exécution : Simuler le cycle avec un jeu de cartes où chaque carte représente une instruction machine.
  • Hiérarchie mémoire : Demander aux étudiants de chronométrer différents accès (lecture d'un fichier sur HDD vs SSD vs RAM disk).
  • Ligne de commande : Organiser un défi « course aux commandes » : l'enseignant donne une tâche, le premier étudiant qui écrit la commande correcte gagne un point.
  • QCM : Les étudiants créent eux-mêmes 3 questions d'architecture pour leurs camarades (format pair-à-pair).
