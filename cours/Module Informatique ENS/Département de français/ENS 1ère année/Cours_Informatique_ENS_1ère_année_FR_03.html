Le modèle de von Neumann (proposé par John von Neumann en 1945) est l'architecture fondamentale de presque tous les ordinateurs modernes. Ses 5 unités sont :

1.1 Unité de Contrôle (Control Unit)

  • Dirige et coordonne toutes les actions de l'ordinateur
  • Lit les instructions en mémoire et les interprète
  • Génère les signaux de contrôle pour les autres unités
  • Contient le compteur ordinal (PC — Program Counter) qui pointe vers la prochaine instruction
  • Contient le registre d'instruction (IR — Instruction Register) qui stocke l'instruction en cours

1.2 Unité Arithmétique et Logique (UAL / ALU)

  • Effectue les opérations arithmétiques : addition, soustraction, multiplication, division
  • Effectue les opérations logiques : ET, OU, NON, XOR
  • Effectue les comparaisons : égalité, supérieur, inférieur
  • Utilise des registres (accumulateurs) pour stocker les opérandes et les résultats

1.3 Mémoire (unité de stockage)

  • Stocke à la fois les données et les programmes (= principe de von Neumann)
  • Organisée en cellules adressables, chaque cellule contenant un mot mémoire (8, 16, 32 ou 64 bits)
  • Deux opérations : lecture (read) et écriture (write)

1.4 Entrées / Sorties (I/O)

  • Entrées : clavier, souris, microphone, appareil photo, scanner, réseau
  • Sorties : écran, haut-parleurs, imprimante, réseau
  • Communication via les bus (données, adresses, contrôle)

1.5 Les bus

  • Bus de données : transporte les données entre les unités (bidirectionnel)
  • Bus d'adresses : transporte l'adresse mémoire à lire/écrire (unidirectionnel CPU → mémoire)
  • Bus de contrôle : transporte les signaux de synchronisation (lecture/écriture, horloge)

Largeur des bus : Un bus d'adresses de 32 bits peut adresser 2³² = 4 Go de mémoire. Un bus de 64 bits peut adresser 2⁶⁴ = 16 Eo (exaoctets).

2. Le cycle fetch-decode-execute

sequenceDiagram

    participant MEM as Mémoire (RAM)
    participant IR as Registre<br/>Instruction
    participant UC as Unité de<br/>Contrôle
    participant UAL as UAL (ALU)

    Note over PC,UAL: Cycle d'exécution d'une instruction

    UC->>MEM: 1. FETCH : Envoyer (PC) sur bus d'adresses
    MEM-->>UC: Lire instruction à l'adresse PC
    UC->>IR: Stocker instruction dans IR
    UC->>PC: PC ← PC + 1 (incrémentation)

    UC->>IR: 2. DECODE : Analyser l'opcode (ex: ADD)
    UC->>UC: Identifier les opérandes nécessaires

    UC->>MEM: 3. FETCH Operandes : Lire opérandes
    MEM-->>UAL: Transmettre opérandes à l'UAL

    UAL->>UAL: 4. EXECUTE : Effectuer l'opération
    UAL-->>MEM: 5. STORE : Écrire le résultat en mémoire

Détail des étapes

Étape 1 — Fetch (recherche) : - L'unité de contrôle place le contenu du PC (compteur ordinal) sur le bus d'adresses - La mémoire renvoie l'instruction située à cette adresse - L'instruction est chargée dans le IR (registre d'instruction) - Le PC est incrémenté pour pointer vers l'instruction suivante

Étape 2 — Decode (décodage) : - L'unité de contrôle décode l'opcode (code opératoire) pour déterminer l'opération à effectuer - Elle identifie les opérandes (registres ou adresses mémoire concernés) - Elle active les circuits appropriés dans l'UAL

Étape 3 — Execute (exécution) : - L'UAL effectue l'opération (addition, soustraction, comparaison, etc.) - Le résultat est temporairement stocké dans un registre accumulateur

Étape 4 — Store (rangement) : - Le résultat est écrit dans un registre ou en mémoire (RAM) - Le cycle recommence avec l'instruction suivante (pointée par PC)

Fréquence d'horloge : Chaque cycle est cadencé par l'horloge du processeur. Un CPU à 3 GHz effectue 3 × 10⁹ cycles par seconde. Une instruction simple (ADD) peut prendre 1 cycle, une instruction complexe (DIV) peut en prendre plusieurs.

Les différentes mémoires

1. Registres : - Intégrés dans le processeur - Capacité : quelques dizaines à quelques centaines d'octets - Temps d'accès : ~ 0,3 ns (1 cycle d'horloge) - Utilisation : stockage des opérandes et résultats immédiats de l'UAL

2. Mémoire cache (L1, L2, L3) : - Mémoire rapide et coûteuse, proche du CPU - Stocke les données et instructions fréquemment utilisées (principe de localité spatiale et temporelle) - L1 : la plus rapide, dédiée par cœur - L2 : partagée ou par cœur, moins rapide - L3 : partagée entre tous les cœurs

3. RAM (Random Access Memory) : - Mémoire volatile (perdue à l'extinction) - Capacité : 8 à 64 Go (selon la configuration) - Temps d'accès : ~ 50 ns (DDR4) - Organisation : barrettes DIMM/SO-DIMM

4. SSD (Solid State Drive) : - Mémoire non volatile (Flash NAND) - Capacité : 256 Go à 2 To - Temps d'accès : ~ 10 000 ns (10 µs) - Avantages : rapide, silencieux, résistant aux chocs - Inconvénient : cycles d'écriture limités

5. HDD (Hard Disk Drive) : - Mémoire magnétique non volatile - Capacité : 500 Go à 10+ To - Temps d'accès : ~ 10 000 000 ns (10 ms) - Avantage : coût par Go très faible - Inconvénient : lent, mécanique, bruyant

Principe de localité

  • Localité temporelle : une donnée accédée récemment sera probablement réutilisée bientôt (boucles)
  • Localité spatiale : une donnée proche d'une donnée accédée sera probablement accédée bientôt (tableaux)

Ces principes expliquent l'efficacité du cache : le CPU copie automatiquement en cache les données fréquemment utilisées, ce qui accélère considérablement l'exécution.

Calcul de temps d'accès moyen

Exemple : taux de hit cache = 95 %, temps cache = 1 ns, temps RAM = 50 ns.

Temps moyen = 0,95 × 1 ns + 0,05 × 50 ns = 0,95 + 2,5 = 3,45 ns

Sans cache, le temps d'accès serait de 50 ns. Avec un cache à 95 % de hits, on gagne un facteur 14.

Conclusion

L'architecture de von Neumann est le modèle universel de tous les ordinateurs modernes. Les 5 unités (contrôle, UAL, mémoire, entrées, sorties) fonctionnent en synergie via le cycle fetch-decode-execute. La hiérarchie mémoire (registres → cache → RAM → SSD → HDD) est conçue pour concilier vitesse et capacité : plus on s'éloigne du CPU, plus la mémoire est lente et volumineuse. Ces notions sont fondamentales pour comprendre les performances d'un système informatique.

Note pédagogique ENS

Transposition didactique : Pour enseigner l'architecture en SNT Seconde (thème « Architecture machine ») : - Activité débranchée simuler le cycle fetch-decode-execute avec des élèves jouant les rôles (unité de contrôle, mémoire, UAL) - Construire une pyramide physique de la mémoire avec des gobelets ou des boîtes pour visualiser la hiérarchie - Comparer les temps d'accès avec des analogies : registre = votre cerveau (1 sec), cache = bureau (3 sec), RAM = bibliothèque (5 min), SSD = ville voisine (2h), HDD = pays lointain (semaines)

Lien avec les langues : Faire le parallèle entre la mémoire cache (stockage temporaire des données fréquentes) et le vocabulaire actif/passif dans l'apprentissage des langues.

Conseil pour l'enseignant formateur : Veiller à ne pas noyer les étudiants dans les détails techniques de l'architecture. L'objectif est qu'ils comprennent le cheminement d'une instruction (du clic à l'affichage) et non les spécificités des microprocesseurs. Utiliser des vidéos animées du cycle d'exécution (ex: « How a CPU works » de la chaîne YouTube CrashCourse) pour renforcer la compréhension visuelle. Prolongement : Les étudiants peuvent explorer l'assembleur MIPS ou RISC-V via le simulateur en ligne « MARS » pour visualiser l'exécution instruction par instruction. Proposer une activité complémentaire : comparer les architectures CISC (Intel) et RISC (ARM) et leurs implications dans les appareils mobiles utilisés en contexte scolaire (tablettes, smartphones).
