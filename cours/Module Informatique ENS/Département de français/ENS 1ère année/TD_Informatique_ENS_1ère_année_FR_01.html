Exercice 1 — Architecture et codage (15 min)

Scénario enseignant : Vous devez vérifier que vos étudiants comprennent le rôle des composants élémentaires d'un ordinateur. Cet exercice permet de sonder leurs connaissances sur l'architecture von Neumann.

✓ Question de base (5 min)

Énoncé : Expliquer le rôle de l'ALU, de l'unité de contrôle et de la mémoire centrale. Convertir 13 en binaire.

Corrigé détaillé :

  • ALU (Arithmetic Logic Unit) : effectue les opérations arithmétiques (addition, soustraction) et logiques (ET, OU, NON).
  • UC (Unité de Contrôle) : orchestre le cycle fetch-decode-execute, séquence le déroulement des instructions.
  • Mémoire centrale (RAM) : stocke temporairement les instructions et les données en cours d'utilisation. Volatile.
  • 13₁₀ = 1101₂ — méthode : divisions successives par 2 :
13 ÷ 2 = 6 reste 1  ↑
 6 ÷ 2 = 3 reste 0  |
 3 ÷ 2 = 1 reste 1  |
 1 ÷ 2 = 0 reste 1  |
 Lecture des restes de bas en haut → 1101

★ Question intermédiaire (5 min)

Énoncé : Associer chaque composant à sa catégorie (entrée, sortie, traitement, contrôle, mémoire) :

Composant Rôle Catégorie
Clavier Saisie de texte ?
Écran Affichage visuel ?
ALU Calculs arithmétiques ?
RAM Stockage temporaire ?
Disque dur Stockage permanent ?

Corrigé : Clavier → Entrée, Écran → Sortie, ALU → Traitement, RAM → Mémoire centrale, Disque dur → Mémoire de masse (stockage permanent).

Exercice 2 — Processus et threads (18 min)

Scénario enseignant : Vos étudiants confondent souvent processus et thread. Utilisez l'exemple concret du navigateur web pour ancrer la différence. Proposez des analogies (usine/ouvrier, cuisine/chef).

✓ Question de base (6 min)

Énoncé : Distinguer processus et thread. Donner un exemple concret avec un navigateur web.

Corrigé détaillé :

Caractéristique Processus Thread
Espace mémoire Indépendant (propre espace d'adressage) Partagé avec le processus parent
Communication Complexe (IPC : pipes, sockets, signaux) Directe (variables globales)
Création Lourde (copie du contexte) Légère (simple fil d'exécution)
Isolation Forte (un crash n'affecte pas les autres) Faible (un bug peut tout corrompre)
Commutation Coûteuse (changement de contexte) Rapide (même espace d'adressage)

Analogies pédagogiques :

  • Processus = usine (chaque usine a ses propres ressources, équipements, stocks)
  • Thread = ouvrier (les ouvriers d'une même usine partagent les mêmes outils et locaux)

Exemple navigateur web : - 1 processus pour l'ensemble du navigateur - Plusieurs threads : UI (interface), rendu (affichage des pages), réseau (téléchargement), extensions (plugins)

★ Question intermédiaire (6 min)

Énoncé : Cochez la bonne colonne pour chaque situation.

Situation Processus Thread
Deux onglets Chrome isolés (site A et site B) ? ?
Vérification orthographique dans un traitement de texte ? ?
Un serveur web qui traite 100 requêtes simultanées ? ?
Un programme malveillant qui fait planter tout le système ? ?

Corrigé :

Situation Processus Thread
Deux onglets Chrome isolés ✓ (isolation de sécurité)
Vérification orthographique ✓ (léger, partage le document)
Serveur web 100 requêtes ✓ (pool de threads pour performance)
Programme malveillant plante tout ✓ (si un processus accède au noyau)

Exercice 3 — Algorithme maximum (18 min)

Scénario enseignant : L'algorithmique est le cœur de la pensée informatique. Cet exercice simple (recherche du maximum) permet de vérifier la maîtrise des boucles, conditions, indices de tableau, et de la notion de complexité.

✓ Question de base (6 min)

Énoncé : Écrire en pseudo-code l'algorithme qui trouve le maximum dans un tableau de n entiers. Quelle est sa complexité temporelle ?

Corrigé détaillé :

ALGORITHME Maximum(T[0..n-1])
  ENTRÉE : T, tableau d'entiers de taille n (n ≥ 1)
  SORTIE : la valeur maximale du tableau

  max ← T[0]             // Initialisation : on suppose que le premier est le max
  POUR i DE 1 À n-1 FAIRE   // On parcourt les éléments restants
    SI T[i] > max ALORS     // Si on trouve un élément plus grand
      max ← T[i]            // On met à jour max
    FIN SI
  FIN POUR

  RETOURNER max
FIN ALGORITHME

Complexité : O(n) — un seul parcours linéaire du tableau. C'est la complexité optimale car il faut examiner chaque élément au moins une fois.

Preuve de correction (élémentaire) : - Initialisation : max = T[0] est bien le maximum du sous-tableau T[0..0] - Conservation : à chaque itération i, max est le maximum de T[0..i] - Terminaison : quand i = n-1, max est le maximum de tout le tableau

★ Question intermédiaire (6 min)

Énoncé : Adapter l'algorithme pour retourner l'indice de la première occurrence du maximum (et non sa valeur).

Corrigé :

ALGORITHME IndiceMaximum(T[0..n-1])
  max ← T[0]
  indice ← 0
  POUR i DE 1 À n-1 FAIRE
    SI T[i] > max ALORS
      max ← T[i]
      indice ← i        // On mémorise l'indice
    FIN SI
  FIN POUR
  RETOURNER indice       // Indice de la première occurrence
FIN ALGORITHME

Variante : Pour obtenir l'indice de la dernière occurrence, remplacer > par >=.

★★ Question avancée (6 min)

Énoncé : Écrire un algorithme qui trouve les deux plus grandes valeurs d'un tableau en un seul parcours (complexité O(n)).
Indice : maintenez deux variables max1 et max2.

Corrigé :

ALGORITHME DeuxMax(T[0..n-1])
  max1 ← T[0]        // La plus grande
  max2 ← T[1]        // La deuxième plus grande

  SI max2 > max1 ALORS   // On s'assure que max1 ≥ max2
    ÉCHANGER max1 ET max2
  FIN SI

  POUR i DE 2 À n-1 FAIRE
    SI T[i] > max1 ALORS
      max2 ← max1
      max1 ← T[i]
    SINON SI T[i] > max2 ALORS
      max2 ← T[i]
    FIN SI
  FIN POUR

  RETOURNER (max1, max2)
FIN ALGORITHME

Complexité : toujours O(n), mais avec un peu plus d'opérations par itération.

Exercice 4 — Réseaux (18 min)

Scénario enseignant : Les notions de base du réseau (IP, masque, passerelle, DNS) sont essentielles pour comprendre comment les machines communiquent. Utilisez une analogie postale (adresse = IP, code postal = masque, bureau de poste = passerelle, annuaire = DNS).

✓ Question de base (6 min)

Énoncé : Différencier IP, masque de sous-réseau et passerelle par défaut. Expliquer le rôle du DNS.

Corrigé détaillé :

  • Adresse IP (Internet Protocol) : identifiant unique d'une machine sur le réseau (ex: 192.168.1.10). Comme une adresse postale.
  • Masque de sous-réseau : sépare la partie réseau de la partie hôte dans l'adresse IP (ex: 255.255.255.0 = /24). Comme le code postal.
  • Passerelle par défaut (default gateway) : adresse IP du routeur qui permet de sortir du réseau local pour accéder à Internet (ex: 192.168.1.1). Comme le bureau de poste central.
  • DNS (Domain Name System) : traduit un nom de domaine (google.com) en adresse IP (142.250.178.4). Comme l'annuaire téléphonique.

Exemple concret : Quand vous tapez www.ens.dz dans un navigateur : 1. Le navigateur demande au DNS : « quelle est l'IP de www.ens.dz ? » 2. Le DNS répond : 193.194.xxx.xxx 3. Le navigateur envoie une requête HTTP à cette IP via la passerelle 4. Le serveur web répond avec la page HTML

★ Question intermédiaire (6 min)

Énoncé : Une machine a l'IP 192.168.1.35 avec un masque 255.255.255.0.

  1. Quelle est l'adresse du réseau ?
  2. Combien de machines peuvent être connectées sur ce réseau ?
  3. La machine 192.168.1.200 est-elle sur le même réseau ?
  4. Et la machine 192.168.2.10 ?

Corrigé :

  1. Adresse réseau : 192.168.1.0 (partie réseau = 192.168.1, partie hôte = 0).
    Calcul : IP ∧ Masque = 192.168.1.35 ∧ 255.255.255.0 = 192.168.1.0
  2. Nombre de machines : 2⁸ - 2 = 254 machines (car 8 bits pour la partie hôte, on exclut l'adresse réseau .0 et le broadcast .255).
  3. Oui, 192.168.1.200 a la même partie réseau (192.168.1). Elle est sur le même réseau local.
  4. Non, 192.168.2.10 a une partie réseau différente (192.168.2). Elle nécessite un routage via la passerelle.

★★ Question avancée (6 min)

Énoncé : On considère le réseau 172.16.0.0/16. On veut créer 4 sous-réseaux de taille égale.

  1. Quel nouveau masque faut-il utiliser ?
  2. Quelles sont les adresses de chaque sous-réseau ?
  3. Combien de machines par sous-réseau ?

Corrigé :

  1. Masque /16 → /18 (on emprunte 2 bits pour le sous-réseage). Soit 255.255.192.0.
  2. Les 4 sous-réseaux :
  3. 172.16.0.0/18 (hôtes : 172.16.0.1 → 172.16.63.254)
  4. 172.16.64.0/18 (hôtes : 172.16.64.1 → 172.16.127.254)
  5. 172.16.128.0/18 (hôtes : 172.16.128.1 → 172.16.191.254)
  6. 172.16.192.0/18 (hôtes : 172.16.192.1 → 172.16.255.254)
  7. 2¹⁴ - 2 = 16 382 machines par sous-réseau.

Exercice 5 — Python et sécurité (16 min)

Scénario enseignant : Vos étudiants débutent en Python. Proposez un script simple (moyenne de notes) pour vérifier les bases. Ajoutez une dimension sécurité pour sensibiliser dès la 1ère séance.

✓ Question de base (6 min)

Énoncé : Écrire un script Python qui calcule la moyenne de 5 notes. Lister 3 bonnes pratiques en sécurité informatique.

Corrigé détaillé :

# Script : calcul_moyenne.py
# Auteur : Étudiant ENS
# Date : 2025

notes = [12, 14, 11, 15, 13]       # Liste des 5 notes
moyenne = sum(notes) / len(notes)   # Calcul de la moyenne
print(f"Moyenne : {moyenne:.2f}")  # Affichage formaté à 2 décimales

Explication pas à pas : 1. notes = [...] : création d'une liste Python (tableau dynamique) 2. sum(notes) : fonction intégrée qui additionne tous les éléments 3. len(notes) : retourne la taille de la liste (ici 5) 4. moyenne = ... : affectation du résultat 5. print(f"...") : f-string pour formater l'affichage

Bonnes pratiques de sécurité :

# Pratique Pourquoi ?
1 Authentification multifacteur (MFA) Ajoute une couche de sécurité au-delà du mot de passe
2 Mises à jour régulières Corrigent les vulnérabilités connues (zero-day, failles)
3 Sauvegardes automatiques Permettent de restaurer les données en cas d'attaque (ransomware)
4 Mots de passe uniques et complexes Empêchent le credential stuffing (réutilisation sur plusieurs sites)
5 Principe du moindre privilège Chaque utilisateur/programme n'a que les droits strictement nécessaires

★ Question intermédiaire (5 min)

Énoncé : Modifier le script Python pour qu'il : 1. Demande les notes à l'utilisateur via input() (5 notes) 2. Vérifie que chaque note est comprise entre 0 et 20 3. Affiche un message d'erreur si une note est invalide

Corrigé :

notes = []
for i in range(5):
    try:
        note = float(input(f"Entrez la note {i+1} (0-20) : "))
        if 0 <= note <= 20:
            notes.append(note)
        else:
            print("Erreur : la note doit être entre 0 et 20.")
            break
    except ValueError:
        print("Erreur : veuillez entrer un nombre valide.")
        break

if len(notes) == 5:
    moyenne = sum(notes) / len(notes)
    print(f"Moyenne : {moyenne:.2f}")
else:
    print("Calcul impossible : notes incomplètes.")

Concepts Python utilisés : - input() : saisie utilisateur (retourne une chaîne) - float() : conversion en nombre décimal - try/except : gestion d'exceptions (si l'utilisateur entre du texte) - break : sortie anticipée de la boucle

★★ Question avancée (5 min)

Énoncé : En une ligne de Python (compréhension de liste), calculer la moyenne d'un nombre variable de notes passées en argument via sys.argv.

Corrigé :

import sys
notes = [float(x) for x in sys.argv[1:]]
print(f"Moyenne : {sum(notes)/len(notes):.2f}" if notes else "Aucune note fournie.")

Exécution : python moyenne.py 12 14 11 15 13
Résultat : Moyenne : 13.00

Note pédagogique ENS

Transposition didactique

Ce TD de synthèse montre l'interconnexion des thèmes du module. En classe de Seconde (SNT), on peut proposer un TD similaire mais avec des exercices simplifiés : conversion binaire sur de petits nombres, reconnaissance des périphériques, utilisation d'un navigateur pour illustrer le client-serveur. L'objectif est de donner une vision d'ensemble sans entrer dans les détails techniques.

Conseil pour l'enseignant formateur

Utiliser ce TD comme évaluation diagnostique en début de module. Demander aux étudiants de répondre sans préparation, puis corriger collectivement pour mesurer le niveau initial. Les résultats permettront d'adapter la progression des séances suivantes. Les pictogrammes ✓/★/★★ permettent une différenciation pédagogique : les étudiants rapides peuvent avancer sur les ★★★ pendant que les autres terminent les ✓.

Prolongement

Réaliser une carte mentale collective (sur papier ou avec un outil comme XMind) qui relie tous les thèmes abordés. Chaque étudiant ajoute une notion ou un exemple vu dans le TD. Cette carte servira de fil conducteur tout au long du module.

Pour aller plus loin

  • Architecture : Simuler le cycle d'exécution avec un jeu de rôle (un étudiant = chaque composant)
  • Processus : Utiliser le Gestionnaire de tâches Windows (Ctrl+Maj+Échap) pour observer les processus en direct
  • Algorithme : Implémenter le maximum en Python et tester sur des tableaux aléatoires de taille croissante (mesurer le temps d'exécution avec time)
  • Réseaux : Utiliser ping, tracert, nslookup en ligne de commande pour observer le DNS et le routage
  • Python : Proposer un mini-projet « calculatrice de moyenne avec notes pondérées » qui réinvestit les listes, boucles et conditions
