Exercice 1 — Récursivité : factorielle (15 min)

Mise en situation : La factorielle (n! = 1×2×...×n) apparaît en combinatoire. Sa définition récursive (n! = n×(n-1)!) est l'exemple canonique pour introduire la récursivité.

Objectif spécifique : Comprendre le mécanisme d'appel récursif — cas de base et appel récursif — et savoir tracer la pile d'exécution.

Énoncé : Écrire une fonction récursive factorielle(n) et tracer son exécution pour n=4.

Corrigé :

def factorielle(n):
    if n <= 1:          # Cas de base
        return 1
    return n * factorielle(n - 1)  # Appel récursif

Tracé pour n = 4 :

factorielle(4)
  → 4 * factorielle(3)
    → 4 * (3 * factorielle(2))
      → 4 * (3 * (2 * factorielle(1)))
        → 4 * (3 * (2 * 1)) → 4 * (3 * 2) → 4 * 6 → 24

Table de traçage (pile d'appels) :

Niveau Appel n Retour Action
0 factorielle(4) 4 ? Lancement
1 factorielle(3) 3 ? Appel (n-1)
2 factorielle(2) 2 ? Appel (n-1)
3 factorielle(1) 1 1 Cas de base
2 factorielle(2) 2 2×1=2 Retour
1 factorielle(3) 3 3×2=6 Retour
0 factorielle(4) 4 4×6=24 Résultat

Sous-questions : 1. Tracer pour n=5 ? 2. factorielle(-1) — protection ? 3. Version itérative ? 4. Complexité temporelle/spatiale ? 5. Arbre d'appels pour n=4 ?

Variantes : ★☆☆ somme_recursive(n) — ★★☆ lru_cache — ★★★ Sans multiplication explicite.

Différenciation : N1 : squelette fourni. N2 : tracer puis implémenter. N3 : sys.setrecursionlimit et stack overflow.

Complexité : Temps O(n), Espace O(n). Version itérative : O(n) temps, O(1) espace.

Exercice 2 — Récursivité : Fibonacci (20 min)

Mise en situation : La suite de Fibonacci illustre le danger de la récursivité naïve : le double appel récursif cause une explosion exponentielle.

Objectif spécifique : Analyser la complexité exponentielle et découvrir les optimisations (itératif, mémoïsation).

Énoncé : Écrire une fonction récursive fibonacci(n) (F₀=0, F₁=1, Fₙ=Fₙ₋₁+Fₙ₋₂). Calculer fibonacci(7) à la main.

Corrigé :

def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

Valeurs :

fib(0)=0  fib(1)=1  fib(2)=1  fib(3)=2  fib(4)=3  fib(5)=5  fib(6)=8  fib(7)=13

Arbre d'appels pour fibonacci(5) — 15 appels :

                  fib(5)
                 /       \
            fib(4)       fib(3)
           /      \      /    \
        fib(3)  fib(2) fib(2) fib(1)
        /   \    /  \
     fib(2) fib(1) ... (15 appels)

Soit 15 appels pour fib(5), 41 pour fib(7), 331M pour fib(40) !

Comparaison : Naïve O(2ⁿ), Itérative O(n), Mémoïsée O(n). Pour n=30 : 2,6M vs 29 vs 30 opérations.

Sous-questions : 1. Nombre d'appels pour fib(10) ? 2. Version itérative ? 3. Version avec dictionnaire memo. 4. Pour n=100, version naïve impossible ? 5. @lru_cache.

Variantes : ★☆☆ Itératif simple — ★★☆ @functools.lru_cache — ★★★ Exponentiation de matrice O(log n).

Différenciation : N1 : tracer pour n=4. N2 : analyser complexité et comparer. N3 : chronométrer les 3 versions.

Exercice 3 — Recherche dichotomique (20 min)

Mise en situation : Avec des données triées, on peut éliminer la moitié des données à chaque étape : complexité O(log n).

Objectif spécifique : Implémenter la recherche dichotomique et analyser sa complexité logarithmique.

Énoncé : Fonction dichotomie(tableau, cible). Appliquer à notes = [5, 8, 10, 12, 15, 18, 20] pour trouver 15.

Corrigé :

def dichotomie(tableau, cible):
    debut, fin = 0, len(tableau) - 1
    while debut <= fin:
        milieu = (debut + fin) // 2
        if tableau[milieu] == cible:
            return milieu
        elif tableau[milieu] < cible:
            debut = milieu + 1
        else:
            fin = milieu - 1
    return -1

notes = [5, 8, 10, 12, 15, 18, 20]
print(dichotomie(notes, 15))  # 4

Table de traçage — cible = 15 (trouvé) :

Itér. debut fin milieu tab[milieu] Comparaison Action
1 0 6 3 12 12 < 15 debut = 4
2 4 6 5 18 18 > 15 fin = 4
3 4 4 4 15 15 == 15 Trouvé !

Table — cible = 7 (non trouvé) :

Itér. debut fin milieu tab[milieu] Comparaison Action
1 0 6 3 12 12 > 7 fin = 2
2 0 2 1 8 8 > 7 fin = 0
3 0 0 0 5 5 < 7 debut = 1
4 1 0 — — debut > fin Retour -1

Sous-questions : 1. Tracer pour 18. Combien d'itérations ? 2. Que se passe-t-il en cas de doublons ? 3. Version récursive ? 4. Pour n=1024, nombre max d'itérations ? 5. Version générique (str, float...).

Variantes : ★☆☆ Retourner indice d'insertion — ★★☆ Recherche par interpolation — ★★★ Recherche avec fonction key.

Différenciation : N1 : pseudo-code uniquement. N2 : implémentation Python complète. N3 : comparer expérimentalement avec la recherche linéaire.

Gabarit à compléter :

Exercice 4 — Tri bulle (20 min)

Mise en situation : Le tri bulle compare les éléments adjacents et les échange si nécessaire. Les plus grands « remontent » vers la fin comme des bulles.

Objectif spécifique : Comprendre le tri par échanges successifs et analyser sa complexité O(n²).

Énoncé : Fonction tri_bulle(tableau). Tracer sur [15, 8, 12, 20, 5].

Corrigé :

def tri_bulle(tableau):
    n = len(tableau)
    for i in range(n):
        trie = True
        for j in range(n - i - 1):
            if tableau[j] > tableau[j + 1]:
                tableau[j], tableau[j + 1] = tableau[j + 1], tableau[j]
                trie = False
        if trie:
            break
    return tableau

Tracé :

Départ : [15, 8, 12, 20, 5]
Pass 1 : [8, 12, 15, 5, 20]   Pass 2 : [8, 12, 5, 15, 20]
Pass 3 : [8, 5, 12, 15, 20]   Pass 4 : [5, 8, 12, 15, 20]

Table de traçage :

Pass Comparaisons Échanges Tableau
1 15>8, 15>12, 15>20?, 20>5 3 [8, 12, 15, 5, 20]
2 8>12?, 12>15?, 15>5 1 [8, 12, 5, 15, 20]
3 8>12?, 12>5 1 [8, 5, 12, 15, 20]
4 8>5 1 [5, 8, 12, 15, 20]
5 trie=True → break 0 Trié

Sous-questions : 1. Combien de comparaisons dans le pire cas ? 2. Rôle du drapeau trie ? 3. Tracer sur [1,2,3,4,5] (déjà trié). 4. Adapter en ordre décroissant. 5. Version sans trie — différence ?

Variantes : ★☆☆ Sans optimisation — ★★☆ Tri cocktail — ★★★ Sur liste chaînée.

Différenciation : N1 : code fourni, tracer manuellement. N2 : implémenter avec optimisation. N3 : compter les comparaisons expérimentalement.

Exercice 5 — Tri fusion (15 min)

Mise en situation : Le tri fusion illustre « diviser pour régner » : découper récursivement en deux, puis fusionner les paires triées. Complexité O(n log n).

Objectif spécifique : Maîtriser la conception d'un algorithme récursif et analyser sa complexité.

Énoncé : Écrire tri_fusion(tableau) et fusionner(gauche, droite). Trier [15, 8, 12, 20, 5, 10, 18].

Corrigé :

def tri_fusion(tableau):
    if len(tableau) <= 1:
        return tableau
    milieu = len(tableau) // 2
    gauche = tri_fusion(tableau[:milieu])
    droite = tri_fusion(tableau[milieu:])
    return fusionner(gauche, droite)

def fusionner(gauche, droite):
    resultat = []
    i = j = 0
    while i < len(gauche) and j < len(droite):
        if gauche[i] <= droite[j]:
            resultat.append(gauche[i]); i += 1
        else:
            resultat.append(droite[j]); j += 1
    resultat.extend(gauche[i:]); resultat.extend(droite[j:])
    return resultat

notes = [15, 8, 12, 20, 5, 10, 18]
print(tri_fusion(notes))

Tracé du découpage :

[15, 8, 12, 20, 5, 10, 18]
  ├── [15, 8, 12, 20]
  │   ├── [15, 8] → [15]─[8] → [8, 15]
  │   └── [12, 20] → [12]─[20] → [12, 20]
  │   → [8, 12, 15, 20]
  └── [5, 10, 18]
      ├── [5]
      └── [10, 18] → [10]─[18] → [10, 18]
      → [5, 10, 18]
  → [5, 8, 10, 12, 15, 18, 20]

Table des fusions :

Étape Gauche Droite Résultat
1 [15] [8] [8, 15]
2 [12] [20] [12, 20]
3 [8, 15] [12, 20] [8, 12, 15, 20]
4 [5] [10] [5, 10]
5 [5, 10] [18] [5, 10, 18]
6 [8, 12, 15, 20] [5, 10, 18] [5, 8, 10, 12, 15, 18, 20]

Sous-questions : 1. Nombre de niveaux de récursion pour n ? 2. Pourquoi le tri fusion est-il stable ? 3. Modifier pour ordre décroissant. 4. Comparer comparaisons tri fusion vs tri bulle pour n=10, 100, 1000. 5. Mémoire utilisée par le tri fusion ?

Variantes : ★☆☆ Tracer sur 4 éléments — ★★☆ Sur liste chaînée — ★★★ Version itérative bottom-up.

Note pédagogique ENS

Transposition didactique : La récursivité peut être introduite au collège par les poupées russes ou les fractales. Les algorithmes de tri peuvent être simulés avec des cartes numérotées déplacées sur la table (approche kinesthésique).

Conseil pour l'enseignant formateur : Après chaque algorithme, demandez aux étudiants de l'exécuter à la main sur un petit jeu de données avant de le coder. Insistez sur la comparaison des complexités.

Activités débranchées (CS Unplugged) : - Factorielle : combien de façons de ranger 4 élèves dans une file ? - Dichotomie : jeu « Devine le nombre » entre 1 et 100 - Tri bulle : élèves avec des pancartes numérotées se déplacent - Tri fusion : diviser la classe en deux groupes, chaque groupe trie ses cartes

Prolongement : Défi d'optimisation — implémenter Fibonacci itératif (programmation dynamique) et comparer les temps avec la version récursive naïve pour n=30, 35, 40.
