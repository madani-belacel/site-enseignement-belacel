TD Informatique — ENS 2ème année — Séance 07 (FR)

Enseignant : BELACEL Madani
Module : Informatique
Niveau : ENS — 2ème année — Département de français
Durée : 1h30
Année universitaire : 2025-2026

Exercice 1 — Initialisation et premier commit (15 min)

Énoncé : Simuler les commandes Git pour : 1. Initialiser un dépôt Git 2. Créer un fichier README.md 3. Ajouter le fichier à l'index (staging) 4. Faire un commit avec le message "Initial commit"

Corrigé :

# 1. Initialiser le dépôt
git init

# 2. Créer le fichier
echo "# Projet ENS2" > README.md
echo "TD Git - Cycle Pédagogique" >> README.md

# 3. Ajouter à l'index
git add README.md

# 4. Premier commit
git commit -m "Initial commit"

# Vérifier
git log --oneline

Arbre après Exercice 1 :

* (HEAD -> master) Initial commit

Exercice 2 — Travail avec les branches (20 min)

Énoncé : Simuler le workflow suivant :

  1. Créer une branche developpement
  2. Basculer sur cette branche
  3. Créer TP1.md et TP2.md (chacun avec une ligne de contenu)
  4. Ajouter et commiter les deux fichiers (message : "Ajout TP1 et TP2")
  5. Rebasculer sur master — constater que les fichiers n'y sont pas

Corrigé :

# 1-2. Créer et basculer
git checkout -b developpement

# 3. Créer les fichiers
echo "# TP1 - POO" > TP1.md
echo "# TP2 - BD" > TP2.md

# 4. Commit
git add TP1.md TP2.md
git commit -m "Ajout TP1 et TP2"

# 5. Retour sur master
git checkout master

# Vérifier
ls             # TP1.md et TP2.md ne sont PAS visibles
git log --oneline --all   # Montre les deux commits

Arbre après Exercice 2 :

* (developpement) Ajout TP1 et TP2
* (HEAD -> master) Initial commit

Exercice 3 — Fusion (merge) et conflit (20 min)

Énoncé : Simuler un conflit de fusion :

  1. Sur master, modifier README.md : ajouter la ligne "## Description"
  2. Commiter : git add . && git commit -m "Modif README sur master"
  3. Sur developpement, modifier README.md : ajouter la ligne "## Auteur: Sara"
  4. Commiter : git add . && git commit -m "Modif README sur dev"
  5. Fusionner developpement dans master → CONFLIT
  6. Résoudre le conflit manuellement

Corrigé :

# Sur master
echo -e "# Projet ENS2\n## Description" > README.md
git add README.md && git commit -m "Modif README sur master"

# Sur developpement
git checkout developpement
echo -e "# Projet ENS2\n## Auteur: Sara" > README.md
git add README.md && git commit -m "Modif README sur dev"

# Fusion
git checkout master
git merge developpement
# CONFLIT dans README.md

# Résoudre : éditer README.md pour combiner les deux
# Contenu final :
: # Projet ENS2
: ## Description
: ## Auteur: Sara

git add README.md
git commit -m "Résolution conflit README"

Arbre après Exercice 3 :

*   (HEAD -> master) Résolution conflit README
|\
| * Modif README sur dev
* | Modif README sur master
|/
* (developpement) Ajout TP1 et TP2
* Initial commit

Exercice 4 — Git flow : rebase et reset (20 min)

Énoncé : Simuler un git-flow simplifié :

  1. Créer une branche feature/calcul-moyenne depuis developpement
  2. Ajouter moyenne.py (fonction simple), commiter
  3. Avant de fusionner, master a avancé (simuler un commit)
  4. Rebaser feature/calcul-moyenne sur master

Corrigé :

# 1. Créer la branche feature
git checkout developpement
git checkout -b feature/calcul-moyenne

# 2. Créer et commiter la fonction
echo "def moyenne(notes): return sum(notes)/len(notes)" > moyenne.py
git add moyenne.py && git commit -m "Ajout fonction moyenne"

# 3. Simuler un commit sur master
git checkout master
echo "Fichier supplémentaire" > note.txt
git add note.txt && git commit -m "Ajout note.txt"

# 4. Rebase
git checkout feature/calcul-moyenne
git rebase master
# Les commits feature sont rejoués par-dessus master

# Alternative : git merge master (fusion classique)

Arbre avant rebase :

* (master) Ajout note.txt
| * (HEAD -> feature/calcul-moyenne) Ajout fonction moyenne
|/
* (developpement) Ajout TP1 et TP2
| ...

Arbre après rebase :

* (HEAD -> feature/calcul-moyenne) Ajout fonction moyenne
* (master) Ajout note.txt
| ...

Exercice 5 — Workflow collaboratif complet (15 min)

Énoncé : Écrire la séquence complète de commandes pour le scénario suivant :

Deux développeurs (Ali et Sara) travaillent sur le même dépôt GitHub ens-project.

  1. Ali crée le dépôt, ajoute un README, commit, push sur main
  2. Sara clone le dépôt
  3. Ali crée une branche feature/auth et y travaille
  4. Sara crée une branche feature/ui et y travaille
  5. Ali finit le premier, merge dans main via Pull Request
  6. Sara rebase sa branche sur main, puis Pull Request

Corrigé :

# 1. Ali : dépôt distant
# (Créé sur github.com/ali/ens-project)
git init
echo "# Projet ENS" > README.md
git add README.md && git commit -m "Initial"
git remote add origin https://github.com/ali/ens-project.git
git push -u origin main

# 2. Sara : clone
git clone https://github.com/ali/ens-project.git

# 3. Ali : feature/auth
git checkout -b feature/auth
echo "def login(): pass" > auth.py
git add auth.py && git commit -m "Ajout auth"
git push -u origin feature/auth
# → Pull Request sur GitHub

# 4. Sara : feature/ui
git checkout -b feature/ui
echo "<h1>Bienvenue</h1>" > index.html
git add index.html && git commit -m "Page accueil"
git push -u origin feature/ui

# 5. Ali : Pull Request mergée sur main
git checkout main
git merge feature/auth
git push origin main

# 6. Sara : rebase sur main
git checkout main
git pull origin main
git checkout feature/ui
git rebase main
# Résoudre conflits éventuels
git push -f origin feature/ui
# → Pull Request

Note pédagogique ENS

Transposition didactique : Les concepts de versionnement peuvent être introduits au collège via des exercices de suivi de modifications de texte (ex. rédaction collaborative). En lycée, on peut simuler Git avec des scénarios concrets de travail en équipe avant d'utiliser le terminal.

Conseil pour l'enseignant formateur : Utiliser des analogies (ex. "Git est comme un lecteur de sauvegarde de jeu vidéo") et privilégier la pratique sur des dépôts locaux avant d'introduire le distant. Le conflit de fusion est l'étape la plus délicate ; la préparer avec un exercice papier.

Prolongement : Proposer un projet collectif où chaque étudiant contribue sur une branche différente, avec revue de code via Pull Request sur GitHub.
