TD Informatique — ENS 2ème année (FR)

Enseignant : BELACEL Madani
Niveau : ENS — 2ème année
Durée : 1h30 (90 min) Public cible : Futurs enseignants de collège/lycée — Département de français
Prérequis : Notions de base en Python, algorithmique, SQL et HTML/CSS
Modalité : TD en binômes — alternance théorie et pratique sur machine

Objectif du TD

Pratiquer POO, algorithmes, SQL, Web, Git et conception d'une séance pédagogique.

Objectifs opérationnels : À l'issue de ce TD, l'étudiant sera capable de : 1. Modéliser un système de notes avec les classes Python (instanciation, méthodes, attributs) 2. Implémenter l'algorithme de recherche dichotomique et justifier sa complexité en O(log n) 3. Écrire une requête SQL correcte avec jointure et agrégation (SELECT, JOIN, GROUP BY, AVG) 4. Produire une page Web intégrant un formulaire, une mise en page CSS et une interaction JavaScript 5. Appliquer un workflow Git de base (branche, commit, merge) et concevoir une séance pédagogique

Niveau taxonomique de Bloom : Application (3) → Analyse (4) → Création (6)

Exercice 1 — POO Python (18 min)

Mise en situation :
Dans la vie d'un enseignant, le calcul des moyennes est une tâche récurrente et fastidieuse. Un outil automatisé permet non seulement de gagner du temps, mais aussi d'éviter les erreurs de calcul. La programmation orientée objet (POO) est particulièrement adaptée pour modéliser ce problème : une Note est un objet possédant des propriétés (matière, valeur, coefficient) et un Bulletin regroupe un ensemble de notes et sait en calculer la moyenne pondérée.

Objectif spécifique : Comprendre et appliquer les concepts de classe, d'attribut, de méthode et de constructeur en Python.

Énoncé : Créer une classe Note (matière, valeur, coefficient) et une classe Bulletin calculant la moyenne pondérée.

Corrigé détaillé :

class Note:
    def __init__(self, matiere, valeur, coef=1):
        self.matiere = matiere
        self.valeur = valeur
        self.coef = coef

class Bulletin:
    def __init__(self, notes):
        self.notes = notes
    def moyenne(self):
        s = sum(n.valeur * n.coef for n in self.notes)
        c = sum(n.coef for n in self.notes)
        return s / c

Sous-questions :

  1. Que se passe-t-il si la liste notes est vide dans moyenne() ? Proposer une gestion d'erreur.
  2. Ajouter une méthode afficher_bulletin() qui imprime chaque note avec sa matière, sa valeur et son coefficient.
  3. Comment garantir qu'une note est toujours comprise entre 0 et 20 ? Où placer cette validation ?
  4. Implémenter une méthode maximum() qui retourne la note la plus élevée du bulletin.
  5. Quelle est la différence entre un attribut d'instance et un attribut de classe ? Donner un exemple.

Variantes : - ★☆☆ Ajouter un attribut appreciation (chaîne) à Note et l'afficher dans le bulletin. - ★★☆ Ajouter une classe Eleve qui possède un nom, un prénom et un bulletin. La moyenne s'obtient par eleve.moyenne(). - ★★★ Remplacer la liste de notes par un dictionnaire {matiere: Note} et gérer les matières obligatoires/optionnelles.

Différenciation pédagogique : - Niveau 1 (soutien) : fournir un squelette avec les signatures des méthodes déjà écrites ; l'étudiant remplit le corps. - Niveau 2 (autonomie) : laisser l'étudiant concevoir librement les classes à partir de l'énoncé seul. - Niveau 3 (approfondissement) : demander d'ajouter une méthode statique Note.from_input() qui construit une note à partir d'une saisie clavier.

Commentaires pas à pas du corrigé :

  • coef=1 rend le coefficient optionnel — valeur par défaut 1 si non fourni.
  • Le constructeur de Bulletin reçoit une liste d'objets Note : relation de composition.
  • moyenne() parcourt la liste avec une compréhension de générateur. sum(...) calcule la somme des produits valeur × coef (numérateur) et la somme des coefficients (dénominateur).
  • Piège : oublier de gérer le cas c == 0 (liste vide) → proposer return 0.0 ou raise ValueError("Aucune note").

Exercice 2 — Recherche dichotomique (18 min)

Mise en situation :
Imaginez que vous cherchez le mot « maison » dans un dictionnaire papier de 1000 pages : vous ouvrez au milieu, comparez, et décidez de chercher à gauche ou à droite. C'est le principe de la recherche dichotomique. Transposé en informatique, cet algorithme trouve un élément dans un tableau trié en temps logarithmique, ce qui le rend extrêmement efficace pour de grands volumes de données.

Objectif spécifique : Maîtriser la stratégie « diviser pour régner » et analyser la complexité algorithmique.

Énoncé : Pseudo-code recherche dichotomique. Précondition ? Complexité ?

Corrigé détaillé :

  • Tableau trié obligatoire (précondition essentielle).
  • Diviser pour régner : comparer l'élément recherché avec la valeur au milieu du tableau, réduire l'intervalle de recherche à la moitié gauche ou droite.
  • Complexité : O(log₂ n) dans le pire des cas — chaque étape divise la taille du problème par 2.

Sous-questions :

  1. Tracer manuellement la recherche de 12 dans [3, 7, 12, 18, 25, 30, 42]. Combien d'étapes nécessaires ?
  2. Que se passe-t-il si le tableau n'est pas trié ? Donner un contre-exemple.
  3. Écrire l'algorithme en Python (version itérative et version récursive).
  4. Comparer le nombre d'opérations pour n = 100, 10 000 et 1 000 000 entre recherche linéaire et dichotomique.
  5. Proposer une version qui retourne l'indice de la première occurrence en cas de doublons.

Variantes : - ★☆☆ Implémenter la version récursive de la recherche dichotomique. - ★★☆ Adapter l'algorithme pour chercher dans un tableau d'objets (par exemple, chercher un élève par son nom dans une liste triée alphabétiquement). - ★★★ Implémenter la recherche par interpolation qui utilise la valeur plutôt que le milieu fixe pour deviner la position.

Différenciation pédagogique : - Niveau 1 : fournir le pseudo-code avec des trous à compléter. - Niveau 2 : demander l'implémentation complète en Python avec gestion des cas limites. - Niveau 3 : ajouter une analyse comparative expérimentale (chronométrer les deux versions sur un grand tableau).

Commentaires pas à pas du corrigé :

  • Étape 1 : vérifier que le tableau est trié (précondition).
  • Étape 2 : debut = 0, fin = len(tableau) - 1.
  • Étape 3 : tant que debut <= fin, calculer milieu = (debut + fin) // 2.
  • Étape 4 : si tableau[milieu] == cible → retourner milieu.
  • Étape 5 : si tableau[milieu] < cible → chercher à droite (debut = milieu + 1) ; sinon à gauche (fin = milieu - 1).
  • Étape 6 : si la boucle se termine sans trouver → retourner -1 ou None.

Exercice 3 — SQL (18 min)

Mise en situation :
Dans un établissement scolaire, les notes des élèves sont stockées dans une base de données relationnelle. Un enseignant peut avoir besoin d'extraire la moyenne de chaque élève pour remplir un bulletin. La requête SQL appropriée combine les tables eleve et note via une jointure, puis agrège les résultats par élève. Cet exercice simule une situation réelle d'interrogation de base de données.

Objectif spécifique : Maîtriser la syntaxe SQL des jointures et des fonctions d'agrégation avec GROUP BY.

Énoncé : Tables eleve(id, nom) et note(id_eleve, matiere, valeur). Requête : moyenne par élève.

Corrigé détaillé :

SELECT e.nom, AVG(n.valeur) AS moyenne
FROM eleve e
JOIN note n ON e.id = n.id_eleve
GROUP BY e.id, e.nom;

Sous-questions :

  1. Que renvoie la requête si un élève n'a aucune note ? Comment modifier avec LEFT JOIN pour qu'il apparaisse avec une moyenne NULL ?
  2. Ajouter une condition pour n'afficher que les élèves ayant une moyenne supérieure à 10 (utiliser HAVING).
  3. Trier le résultat par moyenne décroissante avec ORDER BY.
  4. Écrire une requête qui donne la moyenne par matière pour toute la classe.
  5. Proposer une sous-requête pour trouver l'élève ayant la meilleure moyenne.

Variantes : - ★☆☆ Ajouter une colonne prenom à eleve et adapter la requête. - ★★☆ Créer une table matiere(id, nom, coefficient) et pondérer les notes par matière. - ★★★ Écrire une requête qui calcule la moyenne générale, minimale et maximale sur toute la classe en une seule requête.

Différenciation pédagogique : - Niveau 1 : fournir le schéma de la base et un jeu de données d'exemple ; écrire la requête étape par étape. - Niveau 2 : faire varier les conditions (WHERE, HAVING, ORDER BY) et observer les changements. - Niveau 3 : optimiser la requête avec des index et analyser le plan d'exécution (EXPLAIN).

Commentaires pas à pas du corrigé :

  • SELECT e.nom, AVG(n.valeur) AS moyenne — alias AS moyenne pour la lisibilité.
  • FROM eleve e — alias e pour simplifier l'écriture.
  • JOIN note n ON e.id = n.id_eleve — jointure sur la clé étrangère.
  • GROUP BY e.id, e.nom — toutes les colonnes non agrégées du SELECT doivent figurer dans le GROUP BY.
  • Piège : oublier e.id dans le GROUP BY peut causer une erreur si deux élèves ont le même nom.
  • Alternative : LEFT JOIN pour inclure les élèves sans note.

Exercice 4 — Page Web (18 min)

Mise en situation :
La création de formulaires Web est une compétence de base pour tout enseignant de technologie au collège. Un formulaire permet de collecter des données utilisateur (inscription, questionnaire, sondage). L'intégration harmonieuse du HTML (structure), du CSS (présentation) et du JavaScript (interactivité) constitue le socle du développement front-end.

Objectif spécifique : Créer une page Web interactive en intégrant les trois langages du Web front-end.

Énoncé : Page HTML formulaire (nom, email) + CSS centré + JS alerte à la soumission.

Corrigé détaillé :

  • <form> avec input type="text" et email.
  • CSS margin: auto; max-width: 400px.
  • onsubmit → preventDefault() + alert('Merci').

Sous-questions :

  1. Ajouter une validation JavaScript qui vérifie que le champ nom n'est pas vide avant soumission.
  2. Ajouter un champ message (textarea) et un compteur de caractères en temps réel.
  3. Rendre le formulaire responsive (adapté aux mobiles) avec une media query CSS.
  4. Modifier l'alerte pour afficher le nom saisi : « Merci [nom] ! ».
  5. Utiliser localStorage pour sauvegarder les données du formulaire et les réafficher après rechargement.

Variantes : - ★☆☆ Ajouter un champ âge de type number avec validation (entre 6 et 99). - ★★☆ Utiliser Bootstrap ou Tailwind CSS pour la mise en page au lieu du CSS pur. - ★★★ Envoyer les données du formulaire vers une API factice avec fetch() et afficher la réponse.

Différenciation pédagogique : - Niveau 1 : fournir le squelette HTML complet ; l'étudiant ajoute uniquement le JavaScript. - Niveau 2 : l'étudiant écrit le HTML, le CSS et le JS à partir d'une maquette (image). - Niveau 3 : ajouter une validation asynchrone (vérifier si un nom d'utilisateur existe déjà).

Commentaires pas à pas du corrigé :

  • HTML : <form onsubmit="return handleSubmit(event)"> ou écouteur d'événement en JS.
  • CSS : display: flex; flex-direction: column; align-items: center; avec max-width: 400px; margin: auto;.
  • JavaScript : event.preventDefault() empêche le rechargement ; alert('Merci') affiche une boîte de dialogue.
  • Structure recommandée : séparer les fichiers (index.html, style.css, script.js) pour une meilleure organisation.

Exercice 5 — Git et séance pédagogique (13 min)

Mise en situation :
Dans le cadre d'un projet de développement en binôme (création d'un exerciseur pour une classe de 3e), il est indispensable de collaborer sans risquer de perdre son travail ou d'écraser celui du coéquipier. Git est l'outil standard de gestion de versions. Parallèlement, un enseignant doit savoir concevoir une séance pédagogique structurée et cohérente avec les programmes officiels.

Objectif spécifique : Utiliser Git pour le travail collaboratif et appliquer une méthodologie de conception de séance.

Énoncé : Décrire workflow Git pour projet binôme. Esquisser séance 45 min « Boucles en Python » pour 3e.

Corrigé détaillé :

  • Branches main + feature ; commits atomiques ; merge request.
  • Séance : rappel 10 min, exercices guidés 25 min, défi 10 min ; critères : code fonctionnel, lisible.

Sous-questions :

  1. Quelle est la différence entre git merge et git rebase ? Quand utiliser l'un ou l'autre ?
  2. Que faire en cas de conflit lors d'un merge ? Décrire la procédure de résolution.
  3. Proposer un fichier .gitignore adapté à un projet Python (__pycache__, .env, etc.).
  4. Détailler le contenu des 3 phases de la séance « Boucles en Python » (rappel, guidé, défi).
  5. Proposer une grille d'auto-évaluation pour les élèves de 3e sur cette séance.

Variantes : - ★☆☆ Simuler un workflow Git à deux sur un même fichier avec des modifications distinctes. - ★★☆ Utiliser GitHub Classroom pour distribuer et collecter les travaux. - ★★★ Mettre en place une intégration continue (GitHub Actions) qui exécute les tests automatiquement.

Différenciation pédagogique : - Niveau 1 : décrire le workflow avec un schéma plutôt qu'avec des commandes. - Niveau 2 : exécuter les commandes Git dans un terminal et observer l'effet de chacune. - Niveau 3 : rédiger une fiche pédagogique complète pour la séance « Boucles » avec objectifs, déroulé, évaluation et différenciation.

Commentaires pas à pas du corrigé :

  • Workflow : git init → git checkout -b feature/ma-fonction → modifications → git add . → git commit -m "message" → git push origin feature/ma-fonction → Pull Request → git merge après validation.
  • Séance : phase 1 (rappel) — réactiver les itérations avec des exemples concrets (compter de 1 à 10) ; phase 2 (guidé) — exercices pas à pas (somme, affichage) ; phase 3 (défi) — jeu de devinette avec boucle while.
  • Critères d'évaluation : code fonctionnel (s'exécute sans erreur), code lisible (noms des variables, indentation).

Note pédagogique ENS

Transposition didactique : Ce TD couvre cinq piliers fondamentaux de l'informatique (POO, algorithmique, SQL, Web, Git) qu'un futur enseignant de collège-lycée doit maîtriser pour transposer ces concepts dans ses cours de technologie. La diversité des exercices permet de montrer aux élèves comment les mêmes principes (abstraction, structuration, automatisation) s'appliquent à différents domaines.

Conseil pour l'enseignant formateur : Encouragez les étudiants à expliciter le lien entre chaque exercice et les programmes du secondaire. Par exemple, la recherche dichotomique peut être reformulée comme un jeu de "devine le nombre" au collège. Demandez-leur de produire une trace écrite réflexive après chaque exercice.

Liens avec les programmes du secondaire : - 3e : algorithmes et programmation (Scratch → Python) - 2nde : algorithmique, tableurs, HTML/CSS - 1re Spé NSI : POO, SQL, récursivité

Prolongement : Proposer une séance interdisciplinaire où les élèves de 3e créent un mini-projet mêlant formulaire Web, base de données et visualisation des notes avec un graphique.
