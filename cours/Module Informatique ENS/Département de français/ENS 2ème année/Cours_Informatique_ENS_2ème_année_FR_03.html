1. Héritage (15 min)

Principe : une classe peut hériter des attributs et méthodes d'une autre classe.

Vocabulaire : - Classe parente (super-classe) : classe de base - Classe fille (sous-classe) : hérite et peut ajouter/modifier

class Personne:
    def __init__(self, nom, prenom):
        self.nom = nom
        self.prenom = prenom

    def se_presenter(self):
        return f"{self.prenom} {self.nom}"

class Eleve(Personne):   # Eleve hérite de Personne
    def __init__(self, nom, prenom, groupe):
        super().__init__(nom, prenom)  # Appel du constructeur parent
        self.groupe = groupe

e = Eleve("Benali", "Sara", "ENS2-A")
print(e.se_presenter())  # Hérité ! → "Sara Benali"
print(e.groupe)          # Propre à Eleve → "ENS2-A"

2. Surcharge (override) (10 min)

Une classe fille peut redéfinir une méthode de la classe parente.

class Personne:
    def description(self):
        return "Une personne"

class Enseignant(Personne):
    def __init__(self, nom, matiere):
        self.nom = nom
        self.matiere = matiere

    def description(self):  # Surcharge
        return f"Enseignant de {self.matiere}"

p = Personne()
e = Enseignant("M. Belacel", "Informatique")
print(p.description())  # "Une personne"
print(e.description())  # "Enseignant de Informatique"

3. La fonction super() (10 min)

super() permet d'appeler une méthode de la classe parente.

class Enseignant(Personne):
    def __init__(self, nom, prenom, matiere):
        super().__init__(nom, prenom)  # Appelle Personne.__init__
        self.matiere = matiere

    def se_presenter(self):
        # Étend la méthode parente
        base = super().se_presenter()
        return f"{base} — Enseignant de {self.matiere}"

4. Héritage multiple (10 min)

Python permet d'hériter de plusieurs classes (attention aux conflits).

class Sportif:
    def discipline(self):
        return "Sport"

class Musicien:
    def instrument(self):
        return "Piano"

class EleveSportifMusicien(Personne, Sportif, Musicien):
    pass

e = EleveSportifMusicien("Ali", "Ben")
print(e.se_presenter())   # De Personne
print(e.discipline())     # De Sportif
print(e.instrument())     # De Musicien

5. Encapsulation (15 min)

Encapsulation : protéger l'accès aux attributs pour garantir l'intégrité.

class CompteBancaire:
    def __init__(self, titulaire, solde=0):
        self.titulaire = titulaire
        self._solde = 0     # Protégé (convention : _)
        if solde >= 0:
            self._solde = solde

    def deposer(self, montant):
        if montant > 0:
            self._solde += montant

    def retirer(self, montant):
        if 0 < montant <= self._solde:
            self._solde -= montant
            return montant
        return 0

    @property           # Getter
    def solde(self):
        return self._solde

    @solde.setter       # Setter
    def solde(self, valeur):
        if valeur >= 0:
            self._solde = valeur

# Utilisation
cb = CompteBancaire("Ali", 1000)
cb.deposer(500)
print(cb.solde)        # 1500 (via le getter)
# cb._solde = 999999    # Techniquement possible mais déconseillé

Convention Python : _attribut = protégé, __attribut = privé (name mangling).

6. Polymorphisme (10 min)

Polymorphisme : la même interface peut avoir des comportements différents selon le type d'objet.

def faire_cours(intervenant):
    """Fonction polymorphe"""
    print(intervenant.se_presenter())
    print(" va faire cours.")

class Enseignant(Personne):
    def se_presenter(self):
        return f"{self.prenom} {self.nom} (enseignant)"

class IntervenantExterne(Personne):
    def se_presenter(self):
        return f"{self.prenom} {self.nom} (intervenant externe)"

# Même fonction, comportements différents
faire_cours(Enseignant("Belacel", "Madani"))
faire_cours(IntervenantExterne("Dupont", "Jean"))

7. Exemple complet : système scolaire (15 min)

class Personne:
    def __init__(self, nom, prenom, email):
        self.nom = nom
        self.prenom = prenom
        self.email = email

    def __str__(self):
        return f"{self.prenom} {self.nom}"

class Eleve(Personne):
    def __init__(self, nom, prenom, email, groupe):
        super().__init__(nom, prenom, email)
        self.groupe = groupe
        self.notes = []

    def ajouter_note(self, note, matiere):
        self.notes.append({"matiere": matiere, "note": note})

    def moyenne_generale(self):
        if not self.notes:
            return 0.0
        return sum(n["note"] for n in self.notes) / len(self.notes)

class Enseignant(Personne):
    def __init__(self, nom, prenom, email, matiere):
        super().__init__(nom, prenom, email)
        self.matiere = matiere

    def __str__(self):
        return f"{self.prenom} {self.nom} — {self.matiere}"

# Test
eleve = Eleve("Benali", "Sara", "s.benali@etu.ens.dz", "ENS2-A")
eleve.ajouter_note(15, "Info")
eleve.ajouter_note(12, "Français")
prof = Enseignant("Belacel", "Madani", "m.belacel@ens.dz", "Informatique")
print(eleve)                 # "Sara Benali"
print(prof)                  # "Madani Belacel — Informatique"
print(f"Moyenne : {eleve.moyenne_generale():.2f}")

Conclusion

Héritage, encapsulation et polymorphisme sont les trois piliers de la POO. Ils permettent d'écrire du code structuré, réutilisable et extensible.

Note pédagogique ENS

Transposition didactique : L'héritage peut être expliqué au collège avec un exemple simple : "Un carré est un rectangle particulier" — le carré hérite des propriétés du rectangle (4 côtés, angles droits) mais ajoute la contrainte d'égalité des côtés. En NSI Terminale, la hiérarchie Personne → Eleve/Enseignant illustre parfaitement le concept. L'encapsulation se traduit pédagogiquement par la métaphore de la boîte noire : on utilise un objet sans connaître son fonctionnement interne.

Conseil pour l'enseignant formateur : L'héritage multiple est souvent source de confusion. Insistez d'abord sur l'héritage simple avec des exemples concrets du monde scolaire. Pour l'encapsulation, l'exemple du CompteBancaire est efficace car les étudiants comprennent intuitivement qu'on ne doit pas pouvoir modifier un solde directement. Proposez un mini-TP où les étudiants doivent ajouter une classe ProfesseurPrincipal(Enseignant) qui hérite d'Enseignant et ajoute un attribut classe.

Prolongement : Les étudiants peuvent modéliser un système complet de gestion d'établissement scolaire avec une hiérarchie de classes : Personne → Eleve, Enseignant, PersonnelAdministratif. Chaque sous-classe ajoute des attributs et méthodes spécifiques. Ce modèle POO sera réutilisé dans le projet ENS2 et la base de données SQL.
