TD Informatique — ENS 2ème année — Séance 10 (FR)

Enseignant : BELACEL Madani
Module : Informatique
Niveau : ENS — 2ème année — Département de français
Durée : 1h30
Année universitaire : 2025-2026

Objectif de la séance

Finaliser le projet de gestion des notes entamé à la séance précédente : - Présentation par chaque groupe (5 min) - Démonstration fonctionnelle (3 min) - Questions et évaluation par les pairs (2 min) - Remise du code source et documentation

Exercice 1 — Finalisation du code (20 min)

Chaque binôme dispose de 20 minutes pour finaliser son application avant la présentation.

Checklist de Finalisation :

Tâche Fait
CRUD étudiants fonctionnel (créer, lire) ☐
Saisie de notes avec coefficients ☐
Calcul de moyenne (simple + pondérée) ☐
Au moins 3 étudiants + 2 matières en base ☐
Interface responsive (CSS) ☐
Gestion des erreurs (note > 20, champs vides) ☐

Questions d'auto-évaluation : - Mon application gère-t-elle les cas limites (note négative, étudiant sans notes) ? - Les données persistent-elles entre les sessions ? - L'interface est-elle utilisable sur mobile ?

Structure de la présentation (5 min)

1. Présentation du projet (30 sec)
   - "Notre application permet de..."

2. Architecture et choix techniques (1 min)
   - Langage, framework, base de données
   - "Nous avons choisi Django car..."

3. Démonstration (2 min)
   - Ajouter un étudiant
   - Saisir des notes
   - Afficher la moyenne

4. Difficultés rencontrées (1 min)
   - "Le plus difficile a été..."
   - "Nous avons résolu en..."

5. Conclusion et perspectives (30 sec)
   - "Si nous avions plus de temps, nous ajouterions..."

Exercice 4 — Rétrospective de projet (15 min)

Énoncé : En binôme, rédiger une rétrospective (format "Keep, Problem, Try") de 10 lignes maximum.

Keep — Ce qui a bien fonctionné : - _____ - _____ - ________

Problem — Les difficultés rencontrées : - _____ - _____ - ________

Try — Ce que vous feriez différemment : - _____ - _____ - ________

Exemple de rétrospective :

KEEP :
- Le travail en binôme a permis de diviser le travail (front-end / back-end)
- Django facilite le CRUD avec les modèles

PROBLEM :
- La gestion des notes avec coefficients était complexe (calcul des moyennes)
- Nous avons sous-estimé le temps pour le déploiement

TRY :
- Faire un diagramme de classes avant de coder
- Prévoir plus de temps pour les tests utilisateurs

Exercice 5 — Remise et documentation (15 min)

Énoncé : Créer un fichier README.md pour le projet. Il doit contenir :

  1. Titre du projet
  2. Description (2-3 lignes)
  3. Prérequis (Python, dépendances)
  4. Installation et exécution (3-4 commandes)
  5. Structure du projet (arbre des fichiers)
  6. Auteurs

## Grille d'évaluation

| Critère | Poids | Non acquis (0) | Partiel (0.5) | Acquis (1) |
|---------|-------|----------------|----------------|------------|
| Finalisation du code (CRUD, notes, moyennes) | 20 % | Application non fonctionnelle | Fonctionnalités partielles | CRUD, saisie, moyenne opérationnels |
| Présentation orale et démonstration | 20 % | Présentation absente ou incohérente | Présentation partielle | Structure claire, démo fonctionnelle |
| Évaluation par les pairs | 20 % | Aucune évaluation rendue | Évaluations incomplètes | Grilles remplies et arguments pertinents |
| Rétrospective de projet (KPT) | 20 % | Absente ou superficielle | Partiellement rédigée | Analyse pertinente avec pistes d'amélioration |
| Documentation et README | 20 % | Absent ou incomplet | README partiel | README complet avec installation et structure |

## Note pédagogique ENS

**Transposition didactique :** La soutenance de projet est transposable au lycée sous forme d'exposé oral où les élèves présentent leur site web ou leur jeu Scratch. Cela développe des compétences transversales (communication, esprit critique, auto-évaluation).

**Conseil pour l'enseignant formateur :** Structurer les présentations avec un temps limité pour habituer les étudiants aux contraintes professionnelles. La grille d'évaluation par les pairs responsabilise et développe le regard critique.

**Prolongement :** Organiser un "mini-concours" où un jury extérieur (autres enseignants, professionnels) évalue les projets et remet des prix.
