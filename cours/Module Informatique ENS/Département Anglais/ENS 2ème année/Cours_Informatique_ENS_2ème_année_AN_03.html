1. Inheritance (15 min)

Principle : a class can inherit attributes and methods from another class.

Vocabulary : - Parent class (super-class) : base class - Child class (sub-class) : inherits and can add/modify

class Personne:
    def __init__(self, nom, prenom):
        self.nom = nom
        self.prenom = prenom

    def se_presenter(self):
        return f"{self.prenom} {self.nom}"

class Eleve(Personne):   # Eleve inherits from Personne
    def __init__(self, nom, prenom, groupe):
        super().__init__(nom, prenom)  # Call parent constructor
        self.groupe = groupe

e = Eleve("Benali", "Sara", "ENS2-A")
print(e.se_presenter())  # Inherited ! → "Sara Benali"
print(e.groupe)          # Specific to Eleve → "ENS2-A"

2. Override (10 min)

A child class can redefine a method from the parent class.

class Personne:
    def description(self):
        return "A person"

class Enseignant(Personne):
    def __init__(self, nom, matiere):
        self.nom = nom
        self.matiere = matiere

    def description(self):  # Override
        return f"Teacher of {self.matiere}"

p = Personne()
e = Enseignant("Mr. Belacel", "Computer Science")
print(p.description())  # "A person"
print(e.description())  # "Teacher of Computer Science"

3. The super() function (10 min)

super() allows calling a method from the parent class.

class Enseignant(Personne):
    def __init__(self, nom, prenom, matiere):
        super().__init__(nom, prenom)  # Calls Personne.__init__
        self.matiere = matiere

    def se_presenter(self):
        # Extends the parent method
        base = super().se_presenter()
        return f"{base} — Teacher of {self.matiere}"

4. Multiple inheritance (10 min)

Python allows inheriting from multiple classes (beware of conflicts).

class Sportif:
    def discipline(self):
        return "Sport"

class Musicien:
    def instrument(self):
        return "Piano"

class EleveSportifMusicien(Personne, Sportif, Musicien):
    pass

e = EleveSportifMusicien("Ali", "Ben")
print(e.se_presenter())   # From Personne
print(e.discipline())     # From Sportif
print(e.instrument())     # From Musicien

5. Encapsulation (15 min)

Encapsulation : protecting access to attributes to guarantee integrity.

class CompteBancaire:
    def __init__(self, titulaire, solde=0):
        self.titulaire = titulaire
        self._solde = 0     # Protected (convention : _)
        if solde >= 0:
            self._solde = solde

    def deposer(self, montant):
        if montant > 0:
            self._solde += montant

    def retirer(self, montant):
        if 0 < montant <= self._solde:
            self._solde -= montant
            return montant
        return 0

    @property           # Getter
    def solde(self):
        return self._solde

    @solde.setter       # Setter
    def solde(self, valeur):
        if valeur >= 0:
            self._solde = valeur

# Usage
cb = CompteBancaire("Ali", 1000)
cb.deposer(500)
print(cb.solde)        # 1500 (via getter)
# cb._solde = 999999    # Technically possible but discouraged

Python convention : _attribut = protected, __attribut = private (name mangling).

6. Polymorphism (10 min)

Polymorphism : the same interface can have different behaviours depending on the object type.

def faire_cours(intervenant):
    """Polymorphic function"""
    print(intervenant.se_presenter())
    print(" will teach.")

class Enseignant(Personne):
    def se_presenter(self):
        return f"{self.prenom} {self.nom} (teacher)"

class IntervenantExterne(Personne):
    def se_presenter(self):
        return f"{self.prenom} {self.nom} (external speaker)"

# Same function, different behaviours
faire_cours(Enseignant("Belacel", "Madani"))
faire_cours(IntervenantExterne("Dupont", "Jean"))

7. Complete example : school system (15 min)

class Personne:
    def __init__(self, nom, prenom, email):
        self.nom = nom
        self.prenom = prenom
        self.email = email

    def __str__(self):
        return f"{self.prenom} {self.nom}"

class Eleve(Personne):
    def __init__(self, nom, prenom, email, groupe):
        super().__init__(nom, prenom, email)
        self.groupe = groupe
        self.notes = []

    def ajouter_note(self, note, matiere):
        self.notes.append({"matiere": matiere, "note": note})

    def moyenne_generale(self):
        if not self.notes:
            return 0.0
        return sum(n["note"] for n in self.notes) / len(self.notes)

class Enseignant(Personne):
    def __init__(self, nom, prenom, email, matiere):
        super().__init__(nom, prenom, email)
        self.matiere = matiere

    def __str__(self):
        return f"{self.prenom} {self.nom} — {self.matiere}"

# Test
eleve = Eleve("Benali", "Sara", "s.benali@etu.ens.dz", "ENS2-A")
eleve.ajouter_note(15, "CS")
eleve.ajouter_note(12, "French")
prof = Enseignant("Belacel", "Madani", "m.belacel@ens.dz", "Computer Science")
print(eleve)                 # "Sara Benali"
print(prof)                  # "Madani Belacel — Computer Science"
print(f"Average : {eleve.moyenne_generale():.2f}")

Pedagogical Note ENS

Teaching transposition : Inheritance can be explained in middle school with a simple example : "A square is a special rectangle" — the square inherits the properties of the rectangle (4 sides, right angles) but adds the constraint of equal sides. In 12th grade NSI, the Personne → Eleve/Enseignant hierarchy perfectly illustrates the concept. Encapsulation is pedagogically translated by the black box metaphor : we use an object without knowing its internal workings.

Trainer advice : Multiple inheritance is often a source of confusion. First focus on simple inheritance with concrete examples from the school world. For encapsulation, the CompteBancaire example is effective because students intuitively understand that one should not be able to modify a balance directly. Propose a mini-practical where students must add a ProfesseurPrincipal(Enseignant) class that inherits from Enseignant and adds a classe attribute.

Extension : Students can model a complete school management system with a class hierarchy : Personne → Eleve, Enseignant, PersonnelAdministratif. Each subclass adds specific attributes and methods. This OOP model will be reused in the ENS2 project and the SQL database.
