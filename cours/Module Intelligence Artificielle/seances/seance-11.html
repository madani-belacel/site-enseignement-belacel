🤖 Séance 11 — OpenCode + DeepSeek : piloter un agent IA

Module Intelligence Artificielle — 2ème année PEP · ENS Université de Mostaganem

💡 Astuce IA — Toujours le mode Plan avant (touche Tab)
Demande d'abord le PLAN, lis-le, puis passe en Build avec la touche Tab. Un agent qui exécute sans plan agrège ses erreurs ; un agent qui planifie les isole — une par validation. Et si ça part en vrille : /undo annule la dernière action, tes originaux n'ayant jamais été touchés.

🎯 En une phrase

À la fin de cette séance, tu sauras installer OpenCode, le connecter à DeepSeek, et lui confier une vraie tâche sur tes fichiers — en restant maître de chaque étape grâce au mode Plan, à @fichier et à /undo.

💡 Pourquoi c'est utile pour toi

Jusqu'ici, l'IA te répondait. Ici, elle agit : elle lit tes fichiers, écrit du code, l'exécute et te montre ce qu'elle a changé. Pour un étudiant, cela veut dire : 50 vidéos compressées, un devoir formaté, un rapport en PDF, une tâche répétitive de 2 heures faite en 5 minutes — sans quitter ton terminal. C'est le même principe que les assistants intégrés aux éditeurs (séances 9 et 10), mais en plus puissant : l'agent travaille sur tout ton dossier.

🔑 Les 3 idées essentielles

  • Un agent = un assistant qui exécute : il ne se contente pas de répondre, il modifie des fichiers et lance des commandes. D'où l'obligation de le superviser.
  • Plan d'abord, Build ensuite : tu passes par la touche Tab. Dans le Plan, rien ne s'exécute — l'agent expose ce qu'il compte faire et tu valides.
  • Le contexte se choisit : avec @fichier, tu dis à l'agent quoi lire. Ce qu'il ne lit pas, il ne le devine pas — et ne le casse pas.

🧠 L'astuce clé de la séance

Astuce 37 — La boucle en 3 temps : générer, vérifier, corriger
C'est la méthode qui fait gagner le plus de temps avec un agent. Générer une première version rapide. Vérifier en lançant le programme. Corriger en donnant le résultat du test — pas ton avis. « Le test échoue avec cette erreur : [coller le message]. Corrige uniquement la cause, ne touche à rien d'autre. »
Et l'astuce 42 : formulaire pour chat → DeepSeek ou Grok. Pour modifier un projet entier → OpenCode. Pour une simple question → ChatGPT. Ne prends jamais l'outil par habitude.

🔧 IA au quotidien — Utiliser OpenCode pour compresser 50 vidéos
Tu as 50 vidéos de cours à envoyer par e-mail, trop lourdes. Tu ouvres OpenCode dans le dossier : « Comprime toutes les vidéos en MP4 720p avec ffmpeg, garde la piste audio, et donne-moi le gain d'espace. » L'agent écrit le script, tu valides, il s'exécute. Tes 5 Go deviennent 500 Mo — et tu as appris un geste réutilisable.

📋 Comment faire — pas à pas

Étape 1 — Installer OpenCode (4 min)

📍 opencode.ai → terminal ⏱️ 4 min

Ce que tu vas faire : installer l'outil depuis le site officiel, puis vérifier le résultat dans le terminal. Une seule commande, et tu contrôles ce qu'elle fait avant de l'appuyer.

Ce que tu tapes :

curl -fsSL https://opencode.ai/install | bash

Voici ce que le terminal va répondre :

🤖 Réponse typique du terminal

$ curl -fsSL https://opencode.ai/install | bash
Downloading opencode ...
Installing to ~/.opencode/bin/opencode
opencode installed ✓

$ opencode --version
1.2.3

→ Si Node.js est déjà installé sur ta machine, l'équivalent est npm install -g opencode-ai. Le numéro de version affiché dépend de ta version.

→ Si le terminal répond « command not found », redémarre-le : l'installateur ajoute le chemin dans ton profil.

Lis toujours une commande curl | bash avant de l'exécuter : elle télécharge et lance un programme. Ici l'adresse commence par opencode.ai, le site officiel — c'est le seul critère qui compte.
⚠️ Piège à éviter : ne copie jamais une « commande miracle » d'un forum : vérifie le domaine du site officiel, puis installe uniquement depuis lui.

Étape 2 — Connecter DeepSeek (5 min)

📍 OpenCode → /connect ⏱️ 5 min

Ce que tu vas faire : dire à OpenCode quel modèle il doit utiliser et lui donner ta clé API DeepSeek — le « mot de passe » qui autorise OpenCode à appeler le modèle à ta place.

Ce que tu tapes (dans OpenCode) :

/connect

Voici ce que l'interface va probablement te répondre :

🤖 Réponse typique d'OpenCode

Une fenêtre s'ouvre avec la liste des fournisseurs :

Select a provider
  › opencode
    deepseek          ← on choisit celui-ci
    openai
    anthropic
    google
    ...

Puis, après avoir choisi deepseek :

DeepSeek API key
  ••••••••••••••••

Ta clé se récupère sur platform.deepseek.com (rubrique « API keys » → « Create key »). Elle est enregistrée dans la configuration locale d'OpenCode, jamais dans tes fichiers de projet.

Message de confirmation : ✓ Connected to deepseek (deepseek-chat)

Garde ta clé dans le gestionnaire de mots de passe (Bitwarden, KeePass) en plus : si tu réinstalles la machine, tu la retrouves sans la régénérer.
⚠️ Piège à éviter : ne place JAMAIS une clé API dans un fichier que tu pourrais pousser sur GitHub : les dépôts publics sont scannés en continu et ta clé sera consommée par quelqu'un d'autre en quelques heures.

Étape 3 — Ouvrir ton dossier et initialiser le projet (5 min)

📍 Terminal → opencode → /init ⏱️ 5 min

Ce que tu vas faire : lancer OpenCode dans ton dossier de travail, puis demander /init : l'agent analyse le projet et écrit un fichier AGENTS.md qui lui servira de mémoire à chaque ouverture.

Ce que tu tapes :

cd projet-ia opencode /init

Voici ce que l'IA va probablement te répondre :

🤖 Réponse typique d'OpenCode

« J'ai analysé le projet : 14 fichiers (Python, Markdown). Je crée un fichier AGENTS.md à la racine avec la structure du projet, les commandes utiles et les conventions que j'ai détectées. »

# AGENTS.md — projet-ia

## Structure
- scripts/   fichiers Python utilitaires
- notes/     relevés et sorties CSV

## Commandes
- python script.py      lancer un script
- pip install -r req.txt  dépendances

## Conventions
- commentaires en français
- noms de fichiers sans accents ni espaces

→ Ce fichier est ta mémoire commune : relis-le, corrige-le, complète-le. À la prochaine ouverture, l'agent repart de tes règles, pas des siennes.

Ajoute-y toi-même une ligne de règle, par exemple « réponds toujours en français » ou « ne modifie jamais les fichiers de notes » : elle s'appliquera à toutes tes sessions, sans jamais la redemander.
⚠️ Piège à éviter : ne lance /init que dans un dossier de travail propre — s'il contient des fichiers sensibles, l'agent les décrit dans AGENTS.md, et ce fichier est fait pour être partagé.

Étape 4 — Poser une question sur tes fichiers avec @ (5 min)

📍 OpenCode → message @fichier ⏱️ 5 min

Ce que tu vas faire : attacher un fichier précis à ta question avec @. L'agent ne devine plus : il lit ce que tu lui donnes et répond en citant l'endroit exact.

Ce que tu tapes :

Explique-moi ce que fait @scripts/meteo.py ligne par ligne, comme à un étudiant qui verra Python pour la première fois. Puis donne-moi 3 questions pour vérifier que j'ai compris.

Voici ce que l'IA va probablement te répondre :

🤖 Réponse typique d'OpenCode

scripts/meteo.py fait trois choses :

  1. Ligne 5 : il construit l'adresse du service météo avec les coordonnées de Paris — c'est la « question » préparée pour le serveur.
  2. Ligne 12 : requests.get(...) envoie réellement la requête à Internet et ramène la réponse en JSON.
  3. Lignes 18-20 : il ouvre la réponse comme un tiroir (data["current"]["temperature_2m"]) et affiche la température.

→ Si le script plantait, l'agent ajouterait la ligne exacte et le chemin du fichier, par exemple scripts/meteo.py:12.

3 questions : 1) Que renvoie la ligne 12 ? 2) Que se passe-t-il si le serveur est hors ligne ? 3) Quelle ligne affiche la température ?

Attache uniquement les fichiers utiles avec @ : chaque fichier ajouté augmente le coût et dilue l'attention de l'agent. Deux fichiers ciblés valent mieux que tout le dossier.
⚠️ Piège à éviter : ne joins jamais à une question un fichier contenant des clés, des mots de passe ou des données d'élèves : tout fichier attaché part chez le fournisseur du modèle.

Étape 5 — Plan, Build, et annuler avec /undo (6 min)

📍 OpenCode → touche Tab → /undo ⏱️ 6 min

Ce que tu vas faire : confier une vraie tâche (compresser tes vidéos) en passant d'abord par le mode Plan, puis apprendre à revenir en arrière. C'est le cœur du pilotage d'agent.

Ce que tu tapes :

Comprime toutes les vidéos du dossier videos/ en MP4 720p, en gardant la piste audio, avec ffmpeg. Écris d'abord le PLAN, je validerai avant toute exécution.

Voici ce que l'IA va probablement te répondre :

🤖 Réponse typique d'OpenCode (mode Plan)

« Voici le plan — aucune action pour l'instant :

  1. Vérifier que ffmpeg est installé (ffmpeg -version).
  2. Lister les vidéos de videos/ et noter la taille totale.
  3. Créer videos_compressees/ pour ne pas écraser l'original.
  4. Convertir chaque vidéo : -vf scale=-2:720 -c:a copy (piste audio conservée telle quelle).
  5. Comparer l'avant/après et afficher l'espace gagné.

Tape la touche Tab pour passer en mode Build et lancer l'exécution. »

En mode Build, l'agent exécute, affiche la progression, puis :

✓ 50/50 vidéos converties
Espace avant : 5.2 Go → après : 610 Mo  (gain : 4.6 Go)

Pour tout remettre comme avant :

/undo → « Dernière action annulée : dossier videos_compressees/ retiré. Les fichiers d'origine n'ont jamais été modifiés. »

Exige toujours une sortie dans un nouveau dossier (videos_compressees/) : tes originaux restent intacts, et /undo redevient un simple « supprimer le dossier créé ».
⚠️ Piège à éviter : ne passe en mode Build qu'après avoir lu le plan : un agent qui exécute avant que tu aies lu agrège ses erreurs au lieu de les isoler.

🎨 Bonus — Demander un schéma en ASCII à l'IA

Un schéma en ASCII est un dessin fait uniquement avec des caractères du clavier (tirets, barres, flèches, plus). Ça marche partout, sans image. Très utile pour comprendre une idée visuellement en un coup d'œil.

Comment demander un schéma à l'IA ? Ajoute simplement « avec un schéma en ASCII » à la fin de ton prompt.

🧪 Exemples réels

Exemple 1 — Le script ffmpeg exact qu'écrit l'agent (département Anglais)

Situation : tu dois envoyer 50 enregistrements d'oral à ton formateur, mais la limite d'envoi est de 25 Mo par message.

Ce que tu tapes :

Écris compress.sh : pour chaque .mp4 du dossier videos/, crée une version 720p dans videos_compressees/, conserve l'audio, affiche la taille avant/après de chaque fichier, puis le total. Commente chaque ligne en français.

Voici ce que l'IA va probablement te répondre :

🤖 Réponse typique d'OpenCode

#!/bin/bash
# compress.sh — réduit toutes les vidéos en 720p, audio conservé
mkdir -p videos_compressees                 # dossier de sortie (créé si absent)

for f in videos/*.mp4; do                   # on parcourt chaque vidéo
  nom=$(basename "$f")                      # nom du fichier sans le chemin
  avant=$(du -h "$f" | cut -f1)             # taille d'origine
  ffmpeg -y -i "$f" -vf scale=-2:720 -c:a copy          "videos_compressees/$nom"          # conversion + copie de l'audio
  apres=$(du -h "videos_compressees/$nom" | cut -f1)
  echo "$nom : $avant -> $apres"            # suivi à l'écran
done

echo "Avant : $(du -sh videos | cut -f1)"
echo "Après : $(du -sh videos_compressees | cut -f1)"

Sortie :

cours_01.mp4 : 180M -> 42M
cours_02.mp4 : 210M -> 51M
...
Avant : 5.2G
Après : 610M
Ajoute « affiche aussi le pourcentage gagné par fichier » : tu repères d'un coup d'œil les vidéos anormalement lourdes — souvent celles mal encodées à la source.

Exemple 2 — Refactorer un vieux script de notes (département Français)

Situation : tu as retrouvé un script écrit l'an dernier, avec la logique mélangée à l'affichage, et tu n'oses pas y toucher.

Ce que tu tapes (mode Plan d'abord) :

@scripts/notes.py — Écris d'abord le plan pour séparer ce script en 3 fonctions (lire, calculer, afficher), ajouter la gestion d'erreur si le fichier manque, et garder EXACTEMENT le même résultat à l'écran. N'exécute rien avant ma validation.

Voici ce que l'IA va probablement te répondre :

🤖 Réponse typique d'OpenCode (mode Plan)

Plan :

  1. Créer lire_notes(chemin) : lit le fichier, convertit en flottants, lève FileNotFoundError si absent.
  2. Créer calculer_stats(notes) : moyenne, max, min — sans aucun print.
  3. Créer afficher(stats) : uniquement le formatage.
  4. Dans le main, appeler les trois, avec un try/except qui affiche « fichier introuvable : vérifie le chemin ».
  5. Comparaison : lancer l'ancienne et la nouvelle version sur le même fichier et diffuser les deux sorties.

Risque : aucun fichier n'est modifié tant que le plan n'est pas validé ; le fichier d'origine est conservé comme notes_v1.py.

→ Tab pour Build, puis : ✓ 2 fichiers modifiés, sortie identique à l'ancienne version.

L'étape 5 (comparer les deux sorties) est la vraie garantie : tant que les deux versions affichent la même chose, le refactoring n'a rien cassé.

Exemple 3 — Rédiger le README de ton projet (département Espagnol)

Situation : tu rends un projet mini-lexique et le formateur exige un fichier README.md décrivant l'usage — que tu as toujours reporté.

Ce que tu tapes :

Analyse le contenu du dossier et rédige un README.md en français : titre du projet, à quoi il sert, comment l'installer, comment l'utiliser avec un exemple de session, et une section « Limites connues ». Ton didactique, 40 lignes maximum.

Voici ce que l'IA va probablement te répondre :

🤖 Réponse typique d'OpenCode

# Mini-lexique espagnol — quiz.py

## À quoi ça sert
Fait réciter un lexique espagnol/français à partir de `vocabulario.txt`
et note les réponses pour concentrer les révisions sur les mots ratés.

## Installation
Aucune dépendance : Python 3 suffit.

## Utilisation
    python quiz.py
Exemple de session :
    el apodo = ? apelido
      ✓ bien
    Score : 9/10
    Encore ? (o/n)

## Limites connues
- gère mal les accents si le fichier n'est pas en UTF-8
- 10 mots tirés au sort par session (modifiable en changeant `min(10, ...)`)
- aucune sauvegarde de progression entre deux sessions

→ L'agent a listé les fichiers, compris le rôle de chacun, puis écrit la documentation — tu n'as plus qu'à relire et corriger le ton.

La section « Limites connues » est celle que personne n'écrit et que tout jury attend : elle prouve que tu connais les faiblesses de ton propre outil.

🎓 Les astuces que personne ne dit

  • Plan avant Build, toujours. La touche Tab te fait gagner les seules erreurs qui coûtent cher : celles qui écrasent.
  • AGENTS.md est ta mémoire. Ajoute-y « réponds en français » et tes règles : elles s'appliquent à chaque session.
  • @fichier ciblé. Deux fichiers précis valent mieux que tout le dossier : réponse plus juste, coût moindre.
  • Sortie vers un nouveau dossier. Les originaux intacts rendent /undo instantané et sans risque.
  • Une tâche à la fois. Comme dans les séances 7 à 10 : une modification par prompt, sinon tu ne sais plus qui a fait quoi.
  • Ta clé API reste locale. Gestionnaire de mots de passe, jamais un fichier de projet, jamais un dépôt public.
  • /undo avant de paniquer. Presque tout se défaite ; le pire réflexe est de tout fermer sans rien tenter.

⚠️ Erreurs à éviter

  • ❌ Passer en Build sans lire le plan → les erreurs s'accumulent au lieu d'être isolées. ✅ Lis l'étape 1 à 5, puis Tab.
  • ❌ Déposer une clé API dans un fichier du projet → elle sera volée en quelques heures. ✅ Clé dans le gestionnaire, jamais dans le code.
  • ❌ Laisser l'agent écrire par-dessus tes originaux → pas de retour possible. ✅ Toujours un dossier de sortie séparé.

🧠 À retenir

  • Un agent exécute : il lit, écrit, lance — d'où la supervision obligatoire.
  • Tab = Plan ↔ Build ; @fichier = contexte choisi ; /init = mémoire AGENTS.md.
  • /undo annule la dernière action : c'est ton filet de sécurité.
  • Clé API locale et secrète — jamais dans un fichier versionné.
  • Sortie dans un nouveau dossier : l'annulation devient un jeu d'enfant.

❓ Questions que tout le monde se pose sur l'IA

1. Où l'IA trouve-t-elle ses exemples ?

L'IA apprend dans des data centers (immenses salles de serveurs) appartenant à des sociétés : OpenAI pour ChatGPT, Google pour Gemini, DeepSeek pour DeepSeek.

Elle apprend à partir de milliards de pages web publiques : Wikipedia, forums, livres numérisés, articles. Ce ne sont PAS les ordinateurs des utilisateurs connectés à Internet.

⚠️ Ton PC, ton téléphone, le PC de ton voisin : rien de tout ça n'est utilisé pour entraîner ChatGPT. Seul un data center de la société est utilisé.

2. Peut-on créer une IA simple avec 1000 photos de chats ?

Oui, c'est possible en 30 minutes avec Google Colab (gratuit). Voici les étapes :

  1. Collecte : 500 photos de chats + 500 photos d'autres choses, dans deux dossiers.
  2. Entraînement : un petit réseau de neurones apprend la différence (code fourni ci-dessous).
  3. Test : tu lui montres une nouvelle photo, il dit « Chat » ou « Pas chat ».

🤖 Code Python minimal (Google Colab)

import tensorflow as tf

train = tf.keras.utils.image_dataset_from_directory(
    "dataset/", image_size=(128,128), batch_size=32)

model = tf.keras.Sequential([
    tf.keras.layers.Rescaling(1./255),
    tf.keras.layers.Conv2D(32, 3, activation='relu'),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Conv2D(64, 3, activation='relu'),
    tf.keras.layers.MaxPooling2D(),
    tf.keras.layers.Flatten(),
    tf.keras.layers.Dense(64, activation='relu'),
    tf.keras.layers.Dense(2, activation='softmax')
])

model.compile(optimizer='adam',
    loss='sparse_categorical_crossentropy',
    metrics=['accuracy'])
model.fit(train, epochs=10)
⚠️ Important : ce programme calcule, il ne « comprend » pas. Il a juste appris quelles formes ressemblent à un chat.

3. IA et robots : quelle différence ?

Un robot = un corps mécanique. L'IA = un cerveau logiciel. On peut les combiner :

Exemple L'IA fait Le robot fait
Aspirateur RoombaDécide où allerSe déplace, aspire
Voiture TeslaReconnaît les piétonsFreine, tourne
Robot médical Da VinciAnalyse les mouvementsCoupe précisément

Mais la majorité des IA n'ont pas de robot. ChatGPT, Perplexity, Gemini : aucun corps, juste du texte.

4. Peut-on faire confiance à l'IA pour les mots de passe ?

NON, jamais. Voici pourquoi :

Information Peut-on la donner ? Pourquoi ?
Mot de passe❌ JAMAISEnvoyé sur un serveur, journalisé
Carte bancaire❌ JAMAISFraude possible
Carte d'identité❌ JAMAISUsurpation d'identité
Adresse personnelle⚠️ ÉviterPas nécessaire
Question d'étude✅ OKAucun risque
Règle d'or : ne mets JAMAIS dans un chat IA ce que tu ne mettrais pas dans un e-mail à un inconnu. Ton message part sur Internet, est stocké sur un serveur de la société, et peut être lu par des employés ou piraté.
Solution privée : utilise une IA locale (Ollama) sur ton propre ordinateur. Aucune donnée ne sort. C'est la seule solution totalement privée. Pour les mots de passe, utilise Bitwarden ou KeePass (gratuits et chiffrés).

5. Chaque pays utilise l'IA différemment

L'IA n'est ni bonne ni mauvaise. Tout dépend de qui l'utilise et pourquoi. Exemples :

  • Médecine — détecter un cancer sur une radio
  • Agriculture — prévoir les récoltes, détecter les maladies des plantes
  • Transport — GPS, voitures autonomes, gestion du trafic
  • Finance — détecter la fraude bancaire
  • Surveillance — reconnaissance faciale dans les lieux publics (usage controversé)
  • Militaire — drones autonomes (usage controversé)
  • Éducation — corriger les copies, adapter les exercices

🔒 Vos données sont-elles en sécurité ?

1. Où sont stockés vos e-mails Gmail ?

Gmail est hébergé dans les data centers de Google, répartis dans le monde entier. Google possède 21 data centers, dont 5 en Europe (Irlande, Pays-Bas, Danemark, Finlande, Belgique).

⚠️ Aucun data center Google dans la plupart des pays du Sud. Vos e-mails, vos documents, et le travail de thèse partagé avec votre encadrant sont stockés à l'étranger — probablement aux États-Unis ou en Europe.

2. Un employé Google peut-il lire vos e-mails ?

Techniquement oui, mais sous contrôle. Google a trois niveaux d'accès :

  1. Vous : accès direct, chiffré.
  2. Employés Google autorisés : accès possible avec une justification professionnelle.
  3. Services Google : accès automatique pour le fonctionnement.

Ce qui protège : vérification des antécédents, accords de confidentialité, journal Access Transparency (chaque accès est enregistré).

Ce qui ne protège PAS : si la justice américaine ordonne l'accès, Google doit obéir — même pour des données stockées en Europe. Le U.S. CLOUD Act étend la juridiction des tribunaux américains à toutes les données contrôlées par des sociétés américaines.

Conclusion : Gmail est déjà un risque pour la souveraineté numérique. L'IA en est un autre, souvent plus grave car vos données peuvent servir à améliorer le modèle de la société.

4. « Ça laisse les pays du tiers-monde en retard » — VRAI

Votre intuition est confirmée par la Banque Mondiale :

« L'infrastructure et les systèmes qui sous-tendent l'économie numérique des pays à revenu faible et intermédiaire sont souvent construits, détenus ou exploités par des acteurs qu'ils ne contrôlent ni ne régulent pleinement. »
  • Dépendance technologique : les pays du Sud n'ont pas d'infrastructure IA locale.
  • Fuite de données : les données partent à l'étranger pour être traitées.
  • Biais culturels : les modèles sont entraînés sur des données du Nord, imposant leurs visions du monde.

🧠 Quiz — vérifie ta compréhension

  1. Que fait-on avant d'exécuter une tâche dans OpenCode ?
    (Réponse : on lit le plan en mode Plan, on valide, puis on passe en Build avec Tab.)
  2. À quoi sert AGENTS.md ?
    (Réponse : à stocker la structure et tes règles, que l'agent relit à chaque ouverture.)
  3. Que fait la touche @ ?
    (Réponse : joindre un fichier précis au contexte de la question.)
  4. Où faut-il garder ta clé API ?
    (Réponse : dans un gestionnaire de mots de passe, jamais dans un fichier du projet ni un dépôt public.)
  5. Que commande annule la dernière action ?
    (Réponse : /undo.)

📖 Glossaire

  • Agent IA — Assistant qui agit (lit, écrit, exécute) au lieu de se limiter à répondre.
  • Mode Plan — Phase où l'agent expose son intention sans rien exécuter (Tab pour basculer).
  • AGENTS.md — Fichier de règles et de structure du projet, lu par l'agent à chaque session.
  • Fournisseur (provider) — Société qui fournit le modèle (DeepSeek, OpenAI…).
  • Clé API — Secret qui autorise OpenCode à appeler le modèle à ta place.
  • /undo — Commande qui annule la dernière modification ou action de l'agent.
