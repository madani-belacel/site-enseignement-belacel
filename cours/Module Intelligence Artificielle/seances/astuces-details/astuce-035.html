1. Le texte source

Je veux un script Python qui : 1) lit un fichier CSV 2) calcule la moyenne de la colonne « note » 3) affiche les 5 meilleures lignes Écris le code complet, commenté en français, prêt à coller.

35 Cursor pour coder avec l'IA intégrée

Pourquoi ça marche

Cursor intègre l'IA directement au cœur de l'éditeur de code, ce qui permet de modifier plusieurs fichiers en même temps et de comprendre le contexte global du projet.

Étapes

  1. Ouvre ton projet dans l'éditeur Cursor.
  2. Utilise le raccourci de chat contextuel (Ctrl + L ou Cmd + L) pour cibler des portions de code.
  3. Applique les modifications suggérées via le diff intégré, en relisant chaque ligne.

Prompt à copier

@codebase Refactorise cette fonction pour optimiser la gestion des erreurs et ajoute les types manquants. Explique chaque modification avant de l'appliquer.

Exemple réel

Mettre à jour l'ensemble des routes d'une application en modifiant le fichier de configuration et les contrôleurs associés en une seule fois.

Erreur fréquente

Accepter toutes les modifications d'un coup sans examiner le diff ligne par ligne.

Vérification

  • ☐ Le contexte global du projet a été pris en compte.
  • ☐ Les modifications ont été relues dans le panneau de diff.
  • ☐ Le code compile et fonctionne après application.

Variante (Anglais / Français)

Anglais : Use Cursor for AI-integrated coding with codebase awareness. Français : Utilise Cursor pour coder avec une IA intégrée consciente de la base de code.

2. Explication phrase par phrase

« Je veux un script qui… » → Tu décris par le résultat, pas par la technique. Pas « utilise pandas et groupby », mais « calcule la moyenne ». C'est la description qui compte.

« 1) lit un fichier CSV, 2) calcule, 3) affiche » → Tu découpes en 3 étapes numérotées. L'IA les traite dans l'ordre et produit un code qui fait exactement ces 3 choses. Sans étapes, l'IA devine — et peut se tromper de 50 %.

« Écris le code complet, commenté en français, prêt à coller » → Tu bornes les limites. Sans « complet », l'IA tronque. Sans « commenté », tu ne comprends pas ce que tu exécutes. Sans « prêt à coller », tu dois recoller des morceaux.

3. Une analogie pour comprendre

Imagine que tu commandes un repas dans un restaurant.

Cas 1 : tu dis « faites-moi un truc avec des tomates, une poêle, du feu moyen pendant 8 minutes ». Le cuisinier te regarde bizarrement — il connaît son métier, il n'a pas besoin qu'on lui dicte la recette. Tu risques juste d'avoir un plat qui ne te plaît pas.

Cas 2 : tu dis « je veux un plat chaud, avec des tomates, pas trop épicé, servi avec du riz ». Le cuisinier sait quoi faire, et tu es sûr du résultat.

Décrire une tâche à une IA de code, c'est pareil. Décris le résultat final, pas la recette interne. L'IA connaît la recette mieux que toi.

5. Application pratique — renommer 200 photos

Prompt jargon (mauvais) :

Écris un script qui utilise os.listdir, fait un for avec os.rename, utilise datetime pour extraire la date EXIF, et gère les collisions avec un compteur.

Résultat : l'IA produit un code correct, mais tu ne sais pas s'il fait ce que tu veux, et si un détail cloche (ordre alphabétique, format de date), tu ne peux pas le corriger.

Prompt résultat (bon) :

Je veux un script Python qui : 1) parcourt les fichiers .jpg du dossier « photos/ » 2) lit la date de chaque photo 3) renomme chaque fichier en « photo_AAAAMMJJ_001.jpg », les 3 derniers chiffres comptant de 1 à N 4) affiche à l'écran chaque renommage Écris le code complet, commenté en français, prêt à coller.

Résultat : tu obtiens un script qui fait exactement ce que tu voulais. Et si un détail ne te plaît pas, tu peux le demander en français : « mets les 3 chiffres avant la date », et c'est corrigé.

6. Le réflexe à retenir

Décris toujours le résultat, jamais la recette.

Une règle : imagine que tu expliques à un ami non-informaticien ce que tu veux obtenir. Si tu utilises des mots comme « listdir », « for », « regex », c'est que tu décris la recette. Si tu utilises « parcourir », « renommer », « afficher », tu décris le résultat. C'est ce dernier qui marche.

7. Erreurs fréquentes à éviter

  1. Dicter la technique d'entrée. « Utilise pandas, puis numpy, puis matplotlib » — tu perds du temps et tu obtiens parfois un code bizarre. Laisse l'IA choisir.
  2. Ne pas découper en étapes. Une phrase fourre-tout donne un code qui mélange les responsabilités. Numérote toujours.
  3. Oublier « code complet ». L'IA tronque les réponses longues. Tu dois recoller des morceaux.
  4. Laisser les commentaires en anglais. Par défaut, l'IA commente en anglais. Exige « commentaires en français ».
  5. Ne pas relire avant d'exécuter. Le jargon peut cacher un bug. Lis chaque ligne, tu comprendras mieux le code.

9. Ce que tu dois retenir

  • Décris le résultat, pas la recette. Tu gagnes du temps et tu obtiens un code plus juste.
  • Numérote les étapes. 3 à 5 étapes, jamais une phrase fourre-tout.
  • Exige : code complet, commentaires en français, prêt à coller.
  • Relis chaque ligne. Un code que tu comprends est un code que tu peux corriger.
